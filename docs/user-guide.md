## SSH 연결

1. 사이드바 **연결** 구역의 ⋯(또는 우클릭) → **새 연결**이나 `Ctrl+Shift+N`에서 이름, 호스트, 포트, 사용자, 인증 방식을 입력한다. 개인키는 로컬 파일 경로를 입력한다.
2. 비밀번호와 Passphrase는 이번 연결에만 쓰거나 저장할 수 있다. 저장소를 쓸 수 없으면 '저장하지 않음'을 선택한다. 평문 파일로 대체 저장하지 않는다.
3. 처음 접속하는 서버는 서버 관리자가 제공한 SHA-256 지문과 대조한 뒤 신뢰한다. 변경되거나 폐기된 키는 연결을 차단하며, 앱에 우회 버튼이 없다.
4. 저장된 세션을 더블클릭하거나 Enter를 누른다. 수정, 즐겨찾기, 복제, 삭제는 세션을 우클릭한다. 그룹 폴더를 우클릭하면 그 그룹에 새 연결이나 하위 그룹을 만들고 그룹을 수정한다. 세션 이름 옆에 `SSH`, `FTP`, `FTPS`가 표시된다. 탭마다 독립된 연결을 쓴다.

연결 종료는 탭을 우클릭해 고른다. 종료된 탭의 안내 카드나 탭 메뉴의 **재접속**은 새 셸을 열며 이전 명령을 다시 실행하지 않는다. tmux 세션을 지정한 연결은 같은 tmux 세션에 다시 붙는다([tmux 세션](#tmux-세션)).

### 인증 방식

- **지원 방식**: 비밀번호, 개인키(Ed25519, ECDSA, RSA), 암호화 개인키의 Passphrase, OS SSH agent, keyboard-interactive. 개인키·agent 인증 뒤 서버가 요구하는 OTP·MFA 질문도 표시한다. 응답은 저장하지 않으며 질문당 120초를 제공한다.
- **SSH agent**: Windows는 OpenSSH `ssh-agent` 서비스와 `ssh-add`로 등록한 키를 쓴다. macOS와 Unix는 `SSH_AUTH_SOCK`을 쓴다. 연결당 시도는 최대 5회이므로 agent에 키가 많으면 사용할 키를 정리한다.
- **RSA**: OpenSSH 일반·암호화, PEM PKCS#1, PKCS#8 일반·암호화 키를 읽는다. 2048~8192비트, SHA-256/512만 허용하고 SHA-1 `ssh-rsa` 서명은 허용하지 않는다. 오래된 PEM 암호화 형식은 OpenSSH나 PKCS#8로 변환해야 한다.
- **SSH 키 전달(agent forwarding)**: 서버에서 이 PC의 키로 `git push` 등을 할 때 쓴다. 서명할 때마다 승인을 받는다. [SSH 키 전달](#ssh-키-전달)을 본다.
- **미지원**: Pageant, FIDO2 키 직접 접근, GSSAPI/Kerberos, 호스트 CA 인증서.

### 점프 호스트

세션 폼 **고급 옵션**의 **점프 호스트**에서 경유할 SSH 프로필을 순서대로 추가한다. 경유 프로필 자체의 경로까지 포함해 최종 서버 외 최대 4홉이다. 홉마다 인증과 호스트키 신뢰를 따로 확인하고, 변경은 새 연결부터 적용된다.

### SSH 키 전달

서버에서 이 PC의 SSH 키로 `git push`, `git pull`, 다른 서버 접속을 할 수 있게 한다. 앱에 들어 있는 agent가 이 PC에서 서명하므로 개인키는 서버로 가지 않고, 서버가 서명을 요청할 때마다 이 PC에서 승인한다.

- **켜기**: 세션 편집의 **고급 옵션 → SSH 키 전달**. 기본은 꺼짐이고 세션마다 켠다. 세션 파일로 내보내거나 가져오지 않으므로 가져온 세션은 다시 켜야 한다. 변경은 새 연결부터 적용된다.
- **전달할 키**: 키 전달을 켜면 바로 아래에 나온다. 서버에는 이 목록의 공개키만 보인다.
  - **로그인 키**: 개인키 파일로 로그인하는 세션이면 그 키를 함께 제공한다. 기본은 켜짐이다.
  - **추가할 키 파일 경로**: Git 호스팅에 등록한 키처럼 로그인 키와 다른 키를 최대 8개까지 더한다. 경로만 저장한다. 암호화된 키의 Passphrase는 처음 서명을 허용할 때 카드에서 묻고, **이 PC에 저장**을 고르면 OS 인증정보 저장소(마스터 패스워드를 켰으면 금고)에 두어 다음부터 묻지 않는다.
  - **이 PC의 SSH agent 키도 사용**: 이 PC의 agent에 등록된 키도 함께 제공한다. 기본은 켜짐이고, agent가 없거나 꺼져 있으면 조용히 건너뛴다.
  - 키는 서명하는 동안만 메모리에 두고(로그인 키는 그 연결 동안), RSA 키는 SHA-2 서명만 한다.
- **이 PC의 agent(선택)**: 위 목록의 키 파일만 쓰면 준비할 것이 없다. 이 PC의 agent에 넣어 둔 키를 함께 쓰려는 경우에만 agent를 켠다. Windows는 OpenSSH `ssh-agent` 서비스이고, 꺼져 있으면 관리자 PowerShell에서 한 번 켠다.

  ```powershell
  Get-Service ssh-agent | Set-Service -StartupType Automatic
  Start-Service ssh-agent
  ssh-add $env:USERPROFILE\.ssh\id_ed25519
  ```

  macOS는 로그인할 때 시스템이 정하는 `SSH_AUTH_SOCK`의 agent를 쓰고, 키는 `ssh-add`로 등록한다.

- **서명 승인**: 서버가 서명을 요청하면 그 터미널 위에 카드가 뜬다. 카드에는 세션 이름, 용도(다른 SSH 서버 로그인과 사용자 이름, 또는 데이터 서명의 용도), 로그인할 서버의 호스트키, 키 이름, 키 출처(앱의 키 파일 또는 이 PC의 agent)와 SHA-256 지문이 나온다. **거부**, **이번만 허용**, **이 연결에서 10분 허용** 중에서 고르고, 60초 안에 답하지 않으면 거부한다. 카드는 키보드 포커스를 가져가지 않으므로 터미널에 치던 키가 답이 되지 않는다. 기다리는 동안 탭은 `입력 대기`로 표시되고, 다른 창을 보고 있으면 OS 알림이 온다. 승인은 끌 수 없다.
- **서버가 할 수 없는 것**: 서버는 키 목록 조회와 승인된 서명만 할 수 있다. 서버에서 키를 추가·삭제하거나 agent를 잠글 수 없다. 제공하지 않은 키로 서명을 요청하면 묻지 않고 거부한다. 점프 호스트에는 전달하지 않는다. 서버가 전달을 거부하면(`AllowAgentForwarding no`) 연결당 한 번 안내한다.

**위험**: 서버의 관리자, 같은 계정으로 로그인한 사람, 서버에서 도는 프로그램(CLI 에이전트 포함)도 전달된 agent에 서명을 요청할 수 있다. 키를 빼 갈 수는 없지만, 허용한 서명은 그 키로 할 수 있는 모든 일(그 키가 등록된 모든 저장소와 서버 접속)에 쓰일 수 있다. 믿는 서버에서만 켜고, 직접 실행한 명령이 보낸 요청인지 확인한 뒤 허용한다. **이 연결에서 10분 허용**은 그 10분 동안 서버의 다른 프로그램이 보낸 요청도 묻지 않고 허용한다. 서버용으로 권한을 줄인 키를 따로 만들어 agent에 넣는 것이 안전하다.

**무인 push는 서버 전용 배포 키로 한다**: 승인 카드는 사람이 화면 앞에 있어야 답할 수 있다. CLI 에이전트를 tmux에 두고 자리를 비운 동안 push까지 하게 하려면 키 전달 대신 그 서버에만 있는 키를 만들고, Git 호스팅 서비스에서 그 저장소 하나에만 쓰기 권한이 있는 배포 키(deploy key)로 등록한다.

```sh
ssh-keygen -t ed25519 -N "" -f ~/.ssh/deploy_myrepo -C "myserver deploy"
cat ~/.ssh/deploy_myrepo.pub   # 이 공개키를 저장소의 배포 키로 등록하고 쓰기 권한을 준다
```

서버의 `~/.ssh/config`에 그 저장소 전용 이름을 두고, 원격 주소를 그 이름으로 바꾼다. `IdentityAgent none`이 있으면 키 전달을 켠 연결에서도 이 저장소에는 전달된 agent를 쓰지 않아 승인 카드가 뜨지 않는다.

```text
Host git-myrepo
  HostName git.example.com
  User git
  IdentityFile ~/.ssh/deploy_myrepo
  IdentitiesOnly yes
  IdentityAgent none
```

```sh
git remote set-url origin git-myrepo:owner/myrepo.git
```

암호 없는 배포 키는 서버에 접근할 수 있는 사람이면 누구나 쓸 수 있다. 권한을 그 저장소 하나로 두고, 서버를 더 쓰지 않거나 노출이 의심되면 Git 호스팅에서 바로 삭제한다.

**tmux 재접속 뒤의 `SSH_AUTH_SOCK`**: 전달된 agent의 소켓은 연결마다 새로 만들어지고 연결이 끝나면 사라진다. [tmux 세션](#tmux-세션)에 다시 붙으면 tmux 세션 환경은 새 소켓으로 바뀌지만, 이미 떠 있던 패널의 셸은 끊긴 연결의 소켓을 그대로 가리켜 `ssh-add -l`과 `git push`가 agent에 연결하지 못한다. 그 패널에서 다음을 실행하면 새 소켓을 쓴다.

```sh
eval "$(tmux show-environment -s SSH_AUTH_SOCK)"
```

이미 실행 중인 프로그램(CLI 에이전트 등)은 시작할 때의 값을 계속 쓰므로, 재접속 뒤 그 프로그램이 push하게 하려면 위 명령을 실행한 셸에서 프로그램을 다시 시작한다. 무인 push는 위의 배포 키를 쓰면 이 문제가 없다.

로컬·WSL 탭에서 같은 키를 쓰는 방법은 [로컬·WSL 탭의 키와 자격 증명](#로컬wsl-탭의-키와-자격-증명)에 있다.

### HTTPS 자격 증명 전달

서버의 git이 `https://` 저장소의 사용자 이름과 토큰(또는 암호)을 물을 때 이 PC에서 답한다. SSH 포트가 막혀 HTTPS만 쓰는 저장소에서 쓴다. 서버에는 아무것도 설치하지 않고 파일도 쓰지 않는다. 서버의 git에 원래 들어 있는 `credential-cache` 클라이언트가 이 연결이 연 소켓으로 요청을 보낸다.

- **켜기**: 세션 편집의 **고급 옵션 → HTTPS Git 자격 증명 전달**. 기본은 꺼짐이고 SSH 키 전달과 따로 세션마다 켠다. 세션 파일로 켜지지 않고 점프 호스트에는 적용하지 않는다. 변경은 새 연결부터 적용된다. 서버가 소켓 전달을 막아 두었으면(`AllowStreamLocalForwarding no`) 연결당 한 번 안내하고, 셸은 그대로 쓸 수 있다.
- **셸에 넣는 것**: Bash·Zsh에는 연결할 때 `GIT_CONFIG_PARAMETERS`에 helper 하나를 덧붙인다. 서버 사용자의 git 설정은 바꾸지 않는다. 그래서 사용자가 서버에 설정한 helper가 먼저 불리고, 그 helper가 값을 주면 카드가 뜨지 않는다. [tmux 세션](#tmux-세션)에는 새 창과 새 패널부터 적용된다. fish·csh에는 자동으로 넣지 않는다.
- **승인 카드**: 서명 카드와 같은 자리에 뜬다. 세션 이름, 저장소 서버, 사용자 이름(git이 보낸 경우), 저장소 경로(서버의 git이 `credential.useHttpPath`를 켠 경우)를 보여준다. **거부**, **이번만 허용**, **이 연결에서 10분 허용**, **직접 입력** 중에서 고르고, 60초 안에 답하지 않으면 거부한다. 거부하면 git은 원래대로 터미널에서 묻는다. **이번만 허용**은 같은 push가 이어서 묻는 요청(대용량 파일 저장소는 push 한 번에 여러 번 묻는다)에 30초 동안 같은 값을 쓴다.
- **값을 찾는 순서**: 허용한 뒤에야 찾는다. 앱에 저장한 토큰, 이 PC의 git이 쓰는 자격 증명 저장소(Git 자격 증명 관리자, macOS 키체인 등. 이 단계에서 그 프로그램의 로그인 창이 열릴 수 있다), 둘 다 없으면 카드의 입력 칸 순서다. 입력 칸에서 **이 PC에 저장**을 고르면 OS 인증정보 저장소나 금고에 두고, **설정 › Git › 저장한 Git 자격 증명**에서 지울 수 있다. 서버가 보낸 값은 저장하지 않는다.
- **거부하는 요청**: `http://` 저장소(토큰이 평문으로 나간다), 같은 저장소 서버의 요청이 10초에 10번을 넘는 경우(1분 동안), git의 `store`·`erase` 요청.

**위험**: 서명과 달리 **값 자체가 서버로 간다.** 서버의 관리자는 그 순간 토큰을 볼 수 있다. 서버 사용자가 git에 `store`나 `cache` helper를 설정해 두었으면 git이 push에 성공한 뒤 그 helper에도 값을 넘겨 서버에 남을 수 있고, 카드가 이를 알린다. 믿는 서버에서만 켜고, 무인 push에는 그 저장소에만 권한이 있는 서버 전용 토큰을 쓴다.

### 저장 위치

세션과 그룹은 앱 데이터 폴더의 `sessions.sqlite3`, 신뢰한 호스트키는 같은 폴더의 `known_hosts`에 저장한다. 사용자의 `~/.ssh/known_hosts`도 읽지만 수정하지 않는다.

## 인증정보 보관

세션의 사용자 이름과 접속 설정은 SQLite에, 비밀번호와 개인키 Passphrase는 OS 보안 저장소에 저장한다. SQLite에는 저장소 참조 ID만 남는다. 세션 폼의 **인증정보 보관 → 입력한 값을 암호화 보관**을 선택한다.

- 첫 접속 인증창에서 암호 저장을 선택하면 로그인 성공 후 보관하고 다음 접속에 사용한다. OTP는 저장하지 않는다.
- 세션을 복제해도 비밀정보는 복제되지 않는다. 세션을 삭제하면 해당 OS 항목도 삭제된다.
- 접속 대상을 바꾸면 기존 인증정보를 명시적으로 삭제하거나 교체해야 한다.
- 비밀번호는 세션 JSON 내보내기에 포함되지 않는다.

### 마스터 패스워드

**설정 → 암호 보관함**에서 12자 이상의 암호를 설정한다. 기존 저장 인증정보도 새 암호화 형식으로 이행한다. Argon2id(32MiB, 3회, 1 lane)로 유도한 키가 임의의 데이터 키를 감싸고, 각 인증정보는 AES-256-GCM과 독립 난수 nonce, 참조 ID 인증 데이터로 보호한다. OS 저장소에도 이 암호문만 기록하며 마스터 패스워드 자체는 저장하지 않는다.

- 앱을 시작하면 잠겨 있다. 해제 후 5분이 지나면 자동으로 잠기고, 즉시 수동으로 잠글 수도 있다. 이미 연결된 SSH·FTP 작업은 유지된다.
- 세션 수정 **고급 옵션**의 **저장된 암호 보기**는 매번 마스터 패스워드를 다시 확인한다. 30초 경과, 창 포커스 이탈, 닫기에 숨기며 클립보드에 자동 복사하지 않는다.
- 마스터 패스워드를 바꾸면 데이터 키와 저장 암호문을 모두 교체한다. 실패하면 기존 참조를 보존한다.
- **마스터 패스워드를 잊으면 복구할 수 없다.** 다른 기기로 옮길 수 있는 암호 백업·동기화는 제공하지 않는다.
- 마스터 패스워드를 설정하지 않아도 OS 보안 저장소의 암호화는 적용된다.

## 터미널

- **탭 메뉴**: 탭을 우클릭하거나 탭 표시줄의 ⋯를 누르면 터미널 검색, 세션 기록, 조작표, 오른쪽·아래로 분할(같은 대상에 새 연결, 오른쪽은 Ctrl+Shift+\\), 이 창 확대, 새 창으로 분리, 연결 종료·재접속, 탭 닫기가 나온다. 터미널 안의 우클릭은 메뉴 없이 바로 붙여넣는다.
- **상태바**: 아래 한 줄에 포커스된 칸의 대상, 상태, 인코딩, [Git 브랜치와 변경 수](#git-상태), 기록 중 표시(`REC`), SSH 서버의 CPU·RAM을 보여 준다. 전체화면과 독립 창에서도 표시된다.
- **검색**: Ctrl+Shift+F나 탭 메뉴로 터미널 위에 검색창을 연다. Enter와 Shift+Enter로 다음·이전 결과로 이동하고, Esc로 표시를 지우고 입력으로 돌아간다.
- **복사와 붙여넣기**: 드래그 선택 자동 복사와 우클릭 붙여넣기가 기본으로 켜져 있고 **터미널 설정**에서 끌 수 있다. 끈 경우 Ctrl+Shift+C/V와 Shift+Insert를 쓴다. 여러 줄이나 제어 문자가 포함된 붙여넣기는 실행 전에 확인한다.
- **마우스를 쓰는 TUI**: vim, tmux 등에서는 Shift+드래그와 우클릭으로 터미널 선택·붙여넣기를 쓴다.
- **터미널 설정**: **설정 → 터미널**에서 모든 터미널에 공통인 값을 정한다. **표시**(글꼴 크기, 스크롤 기록), **마우스·키보드**(선택 복사, 우클릭 붙여넣기, Backspace 전송 방식, macOS의 Option 키를 Meta로 사용), **프로그램 연동**(조작표 자동 표시, 새 파일 패널의 경로 따라가기, 프로그램 상태 표시, 클립보드 복사 허용), **알림**(OS 알림, 터미널 벨, 긴 명령 완료 알림)으로 나뉜다. 연결마다 다른 인코딩, tmux, 인증은 연결 편집에서, 세션 기록과 조작표 고정은 탭 메뉴에서 정한다.
- **키 입력**: SSH는 `TERM=xterm-256color`, `VERASE=DEL`, `IUTF8`을 요청한다. 서버가 이 설정을 덮어쓰면 **Backspace 전송 → Ctrl+H**를 선택한다. 잘못된 서버 terminfo, 로케일, 셸 설정까지 자동으로 고치지는 않는다.
- **독립 창**: 터미널을 새 창으로 분리해도 연결을 다시 만들지 않는다. 입력, 크기 변경은 한 창만 소유한다. 독립 창을 닫으면 해당 SSH 연결과 종속 작업이 종료된다. 검색, 세션 기록, 스니펫, 터미널 설정, 원격 파일은 독립 창 위쪽 **메뉴**에 있다.

### 명령 경계

[경로 따라가기](#터미널-경로-따라가기)가 Bash·Zsh에 넣는 세션 함수는 프롬프트마다 직전 명령의 종료 코드와 새 프롬프트 위치도 알린다. 명령 내용은 보내지 않는다.

- **프롬프트 이동**: 터미널에서 Ctrl+Shift+↑/↓(macOS는 Command)로 이전·다음 프롬프트로 스크롤한다. 알림이 없는 셸에서는 키가 셸로 그대로 간다.
- **실패한 명령**: 종료 코드가 0이 아닌 명령 줄의 왼쪽에 빨간 막대가 표시되고, 마우스를 올리면 종료 코드가 보인다. 빈 줄에서 Enter만 누른 것은 표시하지 않는다.
- **긴 명령 완료 알림**: SSH 탭에서 정해 둔 시간(기본 30초) 이상 걸린 명령이 끝나면, 그 터미널을 보고 있지 않을 때만 OS 알림을 띄운다. **설정 → 터미널 → 알림 → 긴 명령 완료 알림**에서 시간을 바꾸거나 끈다.
- 명령 시작은 Zsh와 Bash 4.4 이상이 직접 알린다. macOS 기본 Bash 3.2는 프롬프트에서 누른 Enter 시각을 시작으로 쓴다. 세션 설정 파일은 바꾸지 않는다.
- 창을 분리할 때 다시 보여 주는 지난 출력에서는 표시만 복원하고 알림은 보내지 않는다.

### Git 상태

터미널 탭(SSH, 로컬 셸, WSL)의 셸이 Git 저장소 안에 있으면 상태바에 브랜치와 변경 수(`main ●3`)가 보인다. SSH 탭은 서버의 git, 로컬 탭은 이 PC의 git, WSL 탭은 그 배포판 안의 git으로 조회한다. 따로 켤 것은 없고, 저장소 폴더로 `cd`하면 나타나고 저장소 밖으로 나가면 사라진다. 업스트림 대비 앞섬·뒤처짐과 변경 종류는 마우스를 올리면 보이고, 누르면 사이드바 **Git** 보기가 열리며 다시 조회한다(독립 창에는 Git 보기가 없어 다시 조회만 한다). 탭 이름에 마우스를 올려도 같은 내용이 보인다. 사이드바 **파일** 트리에는 변경된 파일 오른쪽에 `M`(수정), `A`(추가), `D`(삭제), `?`(추적 안 함), `U`(충돌)가, 변경을 담은 폴더에는 `•`가 표시된다.

- **조회 시점**: 폴더를 옮기거나 파일 트리를 새로 고칠 때, 명령이 끝나 프롬프트가 돌아올 때(5초에 한 번까지), 탭을 다시 열 때(30초가 지났으면), CLI 에이전트가 완료·입력 대기를 알릴 때 조회한다. 일정한 간격으로 반복 조회하지 않는다.
- **저장소가 아니거나 서버에 Git이 없으면** 아무것도 표시하지 않는다.
- **실행하는 명령**: 셸의 폴더에서 서버의 `sh`로 다음을 실행한다. 폴더 이름만 인용해 넣고 나머지는 고정이다. stage, commit, push 같은 쓰기 동작은 하지 않는다.

  ```sh
  cd -- '<폴더>' &&
    LC_ALL=C GIT_OPTIONAL_LOCKS=0 git -c core.fsmonitor=false rev-parse --show-toplevel &&
    LC_ALL=C GIT_OPTIONAL_LOCKS=0 git -c core.fsmonitor=false status --porcelain=v2 --branch -z
  ```

  `GIT_OPTIONAL_LOCKS=0`은 사용자의 Git 작업과 잠금이 겹치지 않게 하고, `core.fsmonitor=false`는 저장소 설정만으로 프로그램이 실행되는 경로를 끈다. 서버의 `safe.directory` 설정은 그대로 따르며 앱이 예외를 추가하지 않는다.

- **저장소의 필터**: `.gitattributes`의 `filter=<이름>`과 Git 설정의 `filter.<이름>.clean`이 있으면 `git status`가 그 프로그램을 실행할 수 있다. 이 PC와 WSL 탭의 자동 조회는 저장소 자체 설정에 든 필터를 끄고 읽는다. 사용자 전역 설정의 필터(예: Git LFS)는 그대로 쓴다. 끌 수 없는 이름의 필터가 있으면 조회하지 않고 알린다. 필터를 끄면 내용이 같은 파일이 변경으로 보일 수 있다. **SSH 탭은 서버의 설정을 그대로 따르므로**, 믿을 수 없는 서버의 폴더에서는 **설정 → Git → 표시 방식 → Git 상태 자동 조회**를 끈다. 끄면 상태바의 **Git** 버튼을 누를 때만 조회한다. [변경 검토](#변경-검토)와 스테이지·커밋은 직접 시작하는 작업이라 필터를 그대로 실행한다.
- **상한**: 5초, 출력 1MiB, 항목 5,000개다. 항목이 더 많으면 `●5000+`로 표시한다. 시간이나 출력 상한을 넘으면 그 저장소의 자동 조회를 멈추고 상태바에 **Git 조회 멈춤**을 보여 주며, 누르면 다시 조회한다.
- FTP와 파드 터미널 탭에는 표시하지 않는다.

### 변경 검토

서버에서 고친 코드를 앱 안에서 보고, 줄마다 남긴 의견을 터미널 프롬프트에 넣는다. 연결된 SSH 탭을 우클릭해 **변경 검토**를 고르거나 `Ctrl+Shift+G`를 누르면, 그 탭의 셸이 있는 저장소를 보여 주는 **변경 검토 · 세션 이름** 탭이 원래 터미널 오른쪽에 열린다. 다른 탭처럼 끌어서 옮기고, 나누고, 확대할 수 있다. 독립 창으로는 분리하지 않는다.

- **기준**: 처음에는 HEAD와 비교해 커밋하지 않은 변경을 보여 준다. 위쪽 **기준**에서 브랜치를 고르면 그 브랜치에서 갈라진 지점과 비교한다. worktree가 여럿이면 **작업 폴더**에서 고른다. 목록과 diff는 탭을 열 때, 기준·폴더·파일을 바꿀 때, 새로 고침을 누를 때만 조회한다.
- **표시**: 수정·추가·삭제·이름 변경·추적 안 함 파일을 `M`, `A`, `D`, `R`, `?`로 보여 준다. 넓은 칸에서는 이전과 새 줄을 좌우로, 좁은 칸에서는 위아래로 보여 준다. 한 줄은 4,000자에서 자른다. 바이너리 파일, 2 MB를 넘는 파일, 10초 안에 오지 않은 diff는 내용을 보여 주지 않고 터미널에서 볼 명령을 복사할 수 있게 한다. 이름을 UTF-8로 읽을 수 없는 파일은 목록에만 나온다.
- **의견**: 줄 번호를 누르고 Shift를 누른 채 다른 줄 번호를 누르면 범위가 선택된다. 의견을 적고 Enter를 누르면 아래 **검토 목록**에 쌓인다. 목록은 탭을 닫으면 사라지며 어디에도 저장하지 않는다.
- **프롬프트로 보내기**: 검토 탭을 연 터미널의 입력 줄에 `src/foo.ts:42-47 의견` 형식으로 넣는다. **Enter는 보내지 않으므로** 내용을 확인한 뒤 직접 보낸다. 그 터미널이 닫혔거나, 끊겼거나, 다시 연결되었거나, 동시 입력 중이면 넣지 않고 안내만 하며 **복사**로 옮긴다. 붙여넣기 모드가 꺼진 셸에서는 줄바꿈이 명령 실행이 되므로 의견을 한 줄로 이어 넣는다.
- **실행하는 명령**: `git for-each-ref`, `git worktree list`, `git diff`(`--name-status`, `--numstat`, 파일 하나), `git ls-files --others`를 읽기 전용으로 실행한다. 모두 Git 상태와 같은 접두사(`LC_ALL=C GIT_OPTIONAL_LOCKS=0 git -c core.fsmonitor=false`)를 쓰고, diff에는 `--no-ext-diff --no-textconv --no-color`를 붙여 저장소 설정이 지정한 외부 diff·textconv 프로그램이 실행되지 않게 한다. 경로는 `GIT_LITERAL_PATHSPECS=1`로 글자 그대로 쓴다. 브랜치는 서버가 준 목록에 있는 이름만 쓰고, 조회할 때 서버에서 한 번 더 확인한다. clean 필터는 [Git 상태](#git-상태)와 같은 남는 위험이다. 앱의 로그와 진단 내보내기에는 diff 내용과 의견을 남기지 않는다. 다만 프롬프트에 넣은 의견은 터미널 출력이므로 [세션 로그](#세션-로그)를 켜 두었으면 기록된다.
- **상한**: 파일 5,000개, 파일 하나 2 MB, 조회마다 10초다.

### CLI 에이전트와 함께 쓰기

서버나 로컬에서 도는 CLI 에이전트의 작업 상태를 탭에 표시하고, 다른 일을 하는 동안 OS 알림으로 알려 준다. **터미널 설정**에서 각각 끌 수 있다. 서버에 별도 설정을 넣을 필요는 없으나, 프로그램이 상태 보고를 지원해야 한다.

- **줄바꿈**: Shift+Enter가 전송 없이 줄을 바꾼다. 프로그램이 지원하지 않으면 Enter로 동작한다.
- **링크**: Ctrl/Cmd+클릭으로 연다. 서버의 `localhost` 주소는 PC에서 바로 열리지 않으므로 [서버 포트 열기](#서버-포트-열기) 창이 뜬다.
- **탭 상태**: `완료`와 `오류`는 키를 입력하거나, 그 터미널로 포커스를 옮기거나, 그 탭을 열면 지워진다. `입력 대기`는 프로그램이 다음 상태를 알릴 때까지 남는다.
- **복사**: 프로그램이 요청한 복사는 사용자가 보고 있는 패널에서만 클립보드에 들어간다. **프로그램의 클립보드 복사 허용**으로 끌 수 있다.

**이미지와 파일 첨부**: 서버의 프로그램은 PC의 클립보드와 파일을 읽을 수 없다. 앱이 파일을 서버로 올리고 경로를 프롬프트에 입력한다. Enter는 누르지 않으므로 내용을 확인하고 직접 전송한다.

- **이미지**: 클립보드에 이미지가 있을 때 Ctrl/Cmd+Shift+V, Shift+Insert, 우클릭, **붙여넣기** 버튼 또는 macOS의 Cmd+V를 쓴다. 텍스트가 함께 있으면 텍스트를 붙여넣는다. Ctrl+V는 Vim 등이 쓰는 터미널 입력이라 가로채지 않는다. 프로그램이나 tmux(`mouse on`)가 마우스를 쓰는 중에는 우클릭이 그쪽으로 전달되므로 단축키나 Shift+우클릭을 쓴다. tmux에서는 경로가 활성 패널에 입력된다.
- **파일**: 터미널 패널 위로 끌어다 놓는다. 폴더와 심볼릭 링크는 보낼 수 없다.
- **확인**: PC의 데이터가 서버로 나가므로 보내기 전에 이름, 크기, 서버, 저장 위치를 보여 준다. 드롭은 매번 확인한다. 클립보드 이미지는 **이 연결에서는 다시 묻지 않음**을 고를 수 있고, 이 선택은 연결이 끝나면 사라진다.
- **저장 위치**: 서버의 `~/.cache/dachsterm/prompt/`에 본인만 읽을 수 있게 저장한다. 파일 이름의 영문, 숫자, `.`, `_`, `-` 외 문자는 `_`로 바뀐다. 7일이 지난 파일은 다음 전송 때 지운다. 이 폴더의 다른 파일은 건드리지 않는다.
- **상한**: 파일당 20MiB, 한 번에 10개다. 더 큰 파일은 파일 탐색기로 올린다.
- **로컬 탭**: 파일은 올리지 않고 경로만 입력한다. WSL에서는 드라이브 경로를 `/mnt/<드라이브>/…`로 바꾼다. 네트워크 경로(`\\서버\…`)는 거부한다. 클립보드 이미지는 프로그램의 이미지 붙여넣기 키를 쓴다.

### 에이전트 시작

서버의 폴더에서 CLI 에이전트를 새 탭으로 시작한다. 실행 전에 최종 명령을 보여 주고, 확인한 명령만 실행한다.

- **시작하는 곳**: 사이드바 **연결**에서 SSH 연결을 우클릭하거나, 사이드바 **파일** 트리에서 서버 폴더를 우클릭해 **에이전트 시작…**을 고른다. 연결에서 시작하면 폴더를 입력하고(비우면 로그인 폴더), 파일 트리에서 시작하면 그 폴더로 정해진다. 폴더는 `/`로 시작하는 절대 경로다.
- **확인 창**: 폴더, 프리셋, 프리셋에 `{name}`이 있으면 이름, 그리고 실제로 실행하거나 입력할 텍스트를 보여 준다. 이름이나 폴더가 올바르지 않으면 **시작**이 꺼진다. 시작하면 같은 연결 설정으로 새 SSH 연결과 탭을 연다. 저장된 인증은 그대로 쓰지만 OTP를 쓰는 서버는 다시 묻고, 동시 연결 상한(32개)에 포함된다.
- **tmux 세션 이름이 있는 연결**: 그 tmux 세션이 없을 때만 세션을 새로 만들고 그 폴더에서 명령을 실행한 뒤 붙는다. 세션이 이미 있으면 **붙기만 하고 실행하지 않는다**. 세션 이름은 연결의 tmux 세션 이름이므로, 에이전트마다 다른 tmux 세션을 쓰려면 연결을 나눠 저장한다. 서버에 tmux가 없으면 일반 셸만 열고 명령은 실행하지 않는다.
- **tmux가 없는 연결**: 새 탭에서 셸 프롬프트가 나타나면 `cd <폴더> && <명령>`(폴더는 필요하면 따옴표로 감싼다)을 한 번 입력하고 Enter를 누른다. 10초 안에 프롬프트를 찾지 못하면 입력하지 않고 **명령을 입력하지 않았습니다** 창에 그 줄을 보여 주며, 복사해서 직접 실행할 수 있다.
- **재접속**: 어느 경우에도 명령을 다시 실행하지 않는다. tmux 세션은 같은 세션에 붙기만 한다.

**시작 프리셋**: **설정 → 에이전트**에서 고친다. 이름(40자)과 명령(1000자)으로 이루어지고 20개까지 둘 수 있다. 틀린 행이 있으면 고칠 때까지 저장하지 않으며, **기본값으로 되돌리기**로 처음 목록을 되살린다. 기본 프리셋은 다음과 같다.

| 이름         | 명령                       |
| ------------ | -------------------------- |
| 에이전트     | `claude`                   |
| 이어서       | `claude --continue`        |
| 세션 선택    | `claude --resume`          |
| 새 worktree  | `claude --worktree {name}` |

`{name}`에는 시작할 때 입력한 이름이 들어간다. 영문·숫자로 시작하고 영문, 숫자, `.`, `_`, `-`만 쓰는 64자 이내다. worktree를 어디에 만들고 언제 지우는지는 그 에이전트의 동작을 따른다. 프리셋 명령은 셸에 그대로 입력되므로 직접 확인한 명령만 넣는다.

프리셋마다 **프로그램**(`claude`, `codex`, 직접 입력)을 고르면 **모드**와 **시작 방식**으로 명령을 만들 수 있고, 만들어진 명령은 명령 칸에서 고칠 수 있다. 선택지로 나타낼 수 없는 명령은 직접 입력으로 열린다.

| 프로그램 | 모드                                                                                                                                    | 시작 방식                                                                           |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `claude` | 기본, 편집 자동 승인(`--permission-mode acceptEdits`), 계획(`--permission-mode plan`), 권한 확인 생략(`--dangerously-skip-permissions`) | 새로, 이어서(`--continue`), 세션 선택(`--resume`), 새 worktree(`--worktree {name}`) |
| `codex`  | 기본, 자동(`--approve-for-me`), 승인·샌드박스 생략(`--dangerously-bypass-approvals-and-sandbox`)                                        | 새로, 이어서(`codex resume --last`), 세션 선택(`codex resume`)                      |

옵션은 서버에 설치된 도구의 버전에 따라 다를 수 있다. 권한 확인이나 샌드박스를 끄는 명령은 프리셋 목록과 시작 확인 창에 **위험**으로 표시되고 경고가 나온다. 이런 모드에서는 에이전트가 묻지 않고 파일을 바꾸고 명령을 실행한다. SSH 키 서명과 Git 자격 증명은 모드와 상관없이 앱의 승인을 따른다.

### 에이전트 현황

여러 탭에서 돌고 있는 CLI 에이전트의 상태를 한눈에 본다. 상태를 알린 탭이 하나라도 있을 때만 상태바 오른쪽에 `입력 대기 2 · 작업 중 1`처럼 상태별 개수가 나타난다.

- **목록**: 개수를 누르면 상태바 위에 목록이 열린다. 행마다 상태, 세션 이름, 독립 창이면 `독립 창`, Git 브랜치와 변경 수(`main ●3`, 좁은 창에서는 숨김), 그 상태가 된 뒤 지난 시간이 나온다. 마우스를 올리면 탭과 같은 설명이 보인다. `입력 대기`, `오류`, `작업 중`, `완료` 순이고 같은 상태에서는 오래된 것이 위다.
- **이동**: 행을 누르면 그 탭을 열고 터미널에 포커스한다. 독립 창의 탭이면 그 창을 앞으로 가져온다. 바깥을 누르거나 Esc로 닫는다.
- **다음 입력 대기 탭으로 이동**: `Ctrl+Shift+.`(macOS는 `Cmd+Shift+.`)는 목록 순서로 지금 탭 다음의 `입력 대기` 탭으로 간다. 메인 창에서만 동작한다.
- **포함하는 탭**: 연결된 탭 중 프로그램이 상태를 알렸거나 [서명 승인](#ssh-키-전달)을 기다리는 탭이다. 이미 열어 본 `완료`·`오류`는 빠진다. 독립 창의 탭은 그 창이 닫히면 빠진다. Git 표시는 마지막으로 조회한 값이며 목록을 연다고 다시 조회하지 않는다.

### tmux 세션

연결이 끊겨도 서버의 작업을 유지하려면 세션 편집의 **고급 옵션 → tmux 세션 이름**을 입력한다. 영문, 숫자, `_`, `-`로 64바이트까지 쓸 수 있다. 서버에 tmux를 설치해 두어야 하며, 앱은 tmux나 서버 설정을 바꾸지 않는다.

- **재접속**: 같은 세션에 다시 붙어 실행 중이던 프로그램이 그대로 보인다. 명령을 입력해서 시작하지 않으므로 실행 중인 프로그램에 글자가 들어가지 않는다.
- **탭 닫기**: 서버의 tmux 세션은 계속 실행된다. 끝내려면 서버에서 tmux를 종료한다.
- **같은 이름**: 같은 이름을 쓰는 탭은 같은 화면을 공유하고 입력도 함께 들어간다.
- **서버에 tmux가 없을 때**: 일반 셸로 시작하고 안내를 표시한다.
- **스크롤 기록**: tmux가 관리하므로 앱의 스크롤 기록에는 남지 않는다.
- **경로 따라가기**: 셸에 입력하지 않으므로 자동으로 따라가지 않는다. 탭을 열 때 활성 패널의 폴더로 이동하고, 탐색기의 **경로 가져오기**로 다시 가져온다.
- **가져오기**: 세션 JSON에는 tmux 세션 이름이 포함되지 않는다.

CLI 에이전트를 쓸 때 권장하는 서버의 `~/.tmux.conf` 설정이다.

```text
set -g allow-passthrough on
set -g focus-events on
set -g mouse on
set -s extended-keys on
set -as terminal-features 'xterm*:extkeys'
```

**tmux 안의 작업 상태**: tmux 안의 CLI 에이전트는 상태를 직접 보낼 수 없어 훅 설정이 있어야 탭과 [에이전트 현황](#에이전트-현황)에 표시된다. **설정 → 터미널 → tmux 안에서 CLI 에이전트 상태 표시**의 **훅 예시 복사**로 전체 예시를 복사해 서버에서 쓰는 에이전트의 사용자 설정 JSON에 합친다. 앱은 서버의 설정 파일을 바꾸지 않는다. 예시는 다음 이벤트마다 고정 JSON을 출력하는 `printf` 한 줄이며 `jq` 같은 도구가 필요 없다.

| 훅 이벤트                                                                                           | 탭 상태   |
| --------------------------------------------------------------------------------------------------- | --------- |
| `UserPromptSubmit`, `PostToolUse`                                                                   | 작업 중   |
| `PermissionRequest`, `PreToolUse`(`AskUserQuestion`), `Notification`(`permission_prompt`, `elicitation_dialog`, `elicitation_url_dialog`) | 입력 대기 |
| `Stop`                                                                                              | 완료      |
| `StopFailure`                                                                                       | 오류      |

이벤트 하나의 모양은 다음과 같다. 나머지는 이벤트 이름, `matcher`, 끝의 상태 단어(`working`, `blocked`, `done`, `error`)만 다르다.

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "printf '%s' '{\"terminalSequence\":\"\\u001b]777;DachsTerm;status;done\\u0007\"}'"
          }
        ]
      }
    ]
  }
}
```

앱은 이 네 단어만 받고 다른 값은 무시한다. `Notification`을 종류 제한 없이 받으면 답을 마친 뒤 약 60초가 지나 나오는 유휴 알림이 `완료`를 `입력 대기`로 바꾸므로 예시의 `matcher`를 그대로 둔다. 다음 제한이 있다.

- 지금 보이는 tmux 창의 상태만 전달된다. 다른 tmux 창에 가려진 패널의 상태는 오지 않는다.
- 한 탭의 여러 tmux 패널은 구별되지 않고 하나의 상태로 표시된다.

### 터미널 인코딩

세션 폼의 **고급 옵션**에서 UTF-8(기본), CP949/EUC-KR, Shift_JIS, GBK, Big5, Windows-1252를 선택한다.

- 서버의 로케일과 실제 출력 인코딩에 맞춘다. 변경은 새 연결부터 적용된다.
- UTF-8 입력과 TUI를 쓰려면 서버 셸도 UTF-8 로케일이어야 한다.
- 수신 패킷 사이에 걸친 문자를 이어서 해석하고, 선택한 인코딩으로 표현할 수 없는 문자는 보내지 않는다.
- Unicode 정규화와 줄바꿈 변환은 하지 않는다.

매핑은 [WHATWG Encoding Standard](https://encoding.spec.whatwg.org/)와 [encoding_rs](https://docs.rs/encoding_rs/latest/encoding_rs/)를 따른다. CP949는 WHATWG EUC-KR의 Unified Hangul Code 매핑을 쓴다.

## 로컬 터미널

사이드바 **로컬**의 셸 이름을 누르거나 **로컬** 구역 메뉴의 **로컬 터미널**을 고르면 등록 없이 새 탭이 열린다.

- **Windows**: Windows PowerShell, 명령 프롬프트, 표준 경로의 PowerShell 7, 설치된 WSL 배포판을 자동으로 찾는다. 목록을 갱신해도 WSL 배포판을 시작하거나 설치하지 않는다. 새로 설치했다면 사이드바 **로컬**을 우클릭해 **목록 새로고침**을 고른다.
- **macOS**: `$SHELL` 또는 계정의 기본 셸을 로그인 셸로 연다.
- 시작 폴더는 사용자 홈이고, WSL은 배포판 홈이다.
- 최대 32개까지 열 수 있다. 탭이나 앱을 닫으면 셸을 정리하며, 재접속은 새 셸이다.
- 검색, 테마, 붙여넣기 확인, 분할, 동시 입력과 왼쪽 **파일**의 로컬 파일 트리를 쓸 수 있다. 모니터링, 터널, 새 창 분리는 제공하지 않는다.
- 로컬 파일 트리는 이 컴퓨터의 파일을 바로 다루므로 전송 큐를 쓰지 않는다. 새 파일·폴더, 이름 변경, 복사·이동·삭제, 외부 편집기로 열기를 제공한다. WSL 탭은 Linux 경로(`/home/...`)로 표시하고 복사·붙여넣기는 Windows 탭과 WSL 탭 사이에서도 된다. 탐색기에서 파일을 끌어 패널에 놓으면 지금 보이는 폴더로 복사한다(같은 이름이 있으면 덮어쓰지 않고 오류로 알림). WSL 파일은 우클릭 **다운로드…**로 고른 폴더에 복사한다.

### 로컬·WSL 탭의 키와 자격 증명

**설정 › 에이전트**에서 켠다. 세션이 없는 탭이라 앱 전체 설정이고, 바꾸면 새로 여는 탭부터 적용된다. 이미 열린 탭은 열 때의 설정을 유지한다.

**로컬 탭의 SSH 키** (**로컬 탭에 이 앱의 SSH 키 제공**, 기본 꺼짐)

- 로컬·WSL 탭의 git과 ssh가 이 앱의 키를 쓴다. Windows의 `ssh-agent` 서비스를 켜지 않아도 암호화된 키로 push할 때마다 Passphrase를 다시 입력하지 않는다.
- 키 목록은 [전달할 키](#ssh-키-전달)와 같다. 최대 8개이고 Passphrase는 처음 서명을 허용할 때 묻는다.
- 앱의 키로 서명할 때마다 그 탭에 "이 탭의 프로그램이 앱의 키로 서명하려고 합니다" 카드가 뜬다. **거부**, **이번만 허용**, **이 탭에서 10분 허용** 중에서 고른다. 이 PC의 SSH agent에 등록된 키는 원래 로컬 프로그램이 바로 쓸 수 있었으므로 카드 없이 그대로 쓴다.
- Windows는 탭마다 현재 사용자만 열 수 있는 통로를 만들어 `SSH_AUTH_SOCK`에 넣는다. Git for Windows에 함께 들어 있는 ssh는 이 통로를 쓰지 못하므로 `GIT_SSH`를 Windows의 `ssh.exe`로 정한다. 사용자가 정한 `GIT_SSH`, `GIT_SSH_COMMAND`, `core.sshCommand`가 있으면 그것을 따른다. macOS는 탭마다 사용자 전용 소켓을 쓴다.
- 탭을 닫으면 통로도 사라진다.

**WSL 탭**

- WSL의 git은 `GIT_SSH`로 Windows의 `ssh.exe`를 거쳐 이 키를 쓴다. Linux 쪽 `SSH_AUTH_SOCK`과 WSL 안의 agent 설정은 바꾸지 않는다.
- **WSL 안에서 직접 치는 `ssh`는 지원하지 않는다.** Linux의 `ssh`는 이 키에 닿지 못하고 원래 설정대로 동작한다.
- Windows의 `ssh.exe`는 WSL의 `~/.ssh`가 아니라 **Windows 쪽 `%USERPROFILE%\.ssh\known_hosts`와 `config`**를 쓴다. 처음 보는 호스트의 질문은 탭에 보이고, 답하면 Windows 쪽 파일에 기록된다.
- `C:` 드라이브가 마운트되지 않은 배포판은 탭을 열 때 `wsl: Failed to translate` 한 줄이 나오고, git은 원래대로 Linux의 `ssh`를 쓴다.

**WSL 탭의 HTTPS Git 자격 증명** (**WSL 탭에 이 PC의 HTTPS Git 자격 증명 제공**, Windows, 기본 꺼짐)

- WSL의 git은 Windows의 Git 자격 증명 관리자를 보지 못한다. 켜면 WSL의 git이 `https://` 저장소의 자격 증명을 물을 때 그 탭에 "WSL의 git이 HTTPS 자격 증명을 요청합니다" 카드가 뜬다. 선택지와 값을 찾는 순서는 [HTTPS 자격 증명 전달](#https-자격-증명-전달)과 같다(**이 탭에서 10분 허용**). 허용한 값은 그 탭의 git으로만 간다.
- 앱 실행 파일을 git의 helper로 덧붙인다(`GIT_CONFIG_PARAMETERS`). WSL에 아무것도 설치하지 않고 WSL의 git 설정도 바꾸지 않는다. git의 `get` 요청만 받는다.
- WSL의 git에 helper를 이미 설정해 두었으면(예: Windows의 Git 자격 증명 관리자를 직접 지정) 그 helper가 먼저 불리고, 값을 주면 카드가 뜨지 않는다. 그 helper가 `store`처럼 값을 저장하는 종류면 git이 push에 성공한 뒤 받은 값을 저장할 수 있다.
- 앱 실행 파일이 WSL에서 보이지 않는 곳(마운트되지 않은 드라이브, 네트워크 경로)에 있으면 helper가 조용히 빠지고 git이 원래대로 묻는다.
- Windows·macOS 로컬 탭의 HTTPS는 이 PC의 Git 자격 증명 관리자가 처리하므로 앱이 끼어들지 않는다.

## 스니펫·명령 모음·조작표

맨 위의 **명령** 아이콘(Ctrl+Shift+S)을 누르면 **내 스니펫**과 **기본 명령** 탭이 있는 창이 열린다. 검색칸에서 ↑·↓로 항목을 고르고 Enter로 사용 영역으로 이동한다.

### 스니펫

**＋ 새 스니펫**이나 항목 우클릭(수정, 복제, 삭제)으로 이름, 설명, 본문, 그룹·태그를 관리한다. 목록은 그룹별로 묶인다.

- `{{경로}}` 같은 자리 표시자의 값은 보낼 때 입력하며 저장하지 않는다. 입력한 값은 **보낼 명령**에 바로 반영된다.
- 비밀번호, 개인키, Passphrase, OTP는 스니펫에 저장하지 않는다. 저장할 때 인증정보가 없다는 확인란을 선택해야 한다.
- **보낼 명령**과 **보낼 터미널**을 확인한 뒤 **입력만 넣기** 또는 **실행**(Enter 포함)을 누른다. 처음에는 포커스된 터미널만 선택되어 있다. 선택한 대상에만 한 번씩 전달되며 동시 입력 그룹과 별개다. 여러 줄이나 제어문자가 있으면 확인란을 먼저 선택해야 한다.
- **복사**는 값을 채운 명령을 클립보드에 넣는다.
- 원격 명령의 성공 여부는 터미널에서 직접 확인한다.
- 독립 SSH 창에서도 제목 줄 메뉴의 **명령**으로 쓸 수 있다.

### 기본 명령·로그 필터

**기본 명령** 탭에서 기본 명령 26개, 필터 7개, Git 읽기 명령 7개를 설명과 함께 복사한다. 교체할 부분을 강조하고 Enter 없이 복사한다. GNU/Linux 기준이다. **내 스니펫으로 저장**을 누르면 강조된 부분이 자리 표시자로 바뀐 스니펫 초안이 열린다.

### 조작표

Bash·Zsh에서 vi, vim, less, tail을 실행하면 상태바 가운데에 핵심 키가 자동으로 나타나고, 끝나면 사라진다. **전체 보기**를 누르면 전체 표가 열린다. 경로 따라가기와 같은 방식으로 셸에 지금 세션에만 함수를 더해 프로그램의 시작과 끝을 알린다. 셸 설정 파일은 바꾸지 않고 입력한 키, 명령 인자, 이력은 수집하지 않는다. **터미널 설정 → vi·vim·less·tail 실행 중 조작표 자동 표시**로 끄며, 다시 켜면 새로 여는 셸부터 적용된다.

- Bash에서 별칭이나 함수로 바꿔 둔 이름(예: `vi`)은 그 이름만 건너뛰고 나머지는 그대로 표시한다.
- `sudo vim`, `command vim`, 파이프로 이어진 실행, tmux 안, 다른 셸, Windows 셸과 WSL에서는 자동으로 나타나지 않는다. 이때 전체 화면 프로그램이면 **전체 화면 프로그램 실행 중** 안내가 나온다. 탭 메뉴의 **조작표 보기·고정**에서 vi/vim, less, tail, cat 표를 직접 고르면 그 탭에 고정되어 상태바에 계속 보인다.
- cat은 바로 끝나므로 직접 고를 때만 표시한다.

## 세션 로그

탭 메뉴의 **세션 기록**으로 SSH, 로컬, WSL 출력을 UTF-8 파일로 기록한다. 기본은 꺼짐이다. 기록 중에는 탭과 상태바에 `REC`가 표시되고, 기록이 중단되면 상태바에 이유가 나온다.

- 시작·일시정지·재개·종료, 저장 폴더, 줄 타임스탬프, 크기·UTC 날짜 회전, 보관 파일 수, 이번 기록에만 적용되는 문자열 마스킹을 설정한다.
- 자동 기록은 해당 SSH 프로필이나 로컬 환경에 명시적으로 켠 경우에만 동작한다.
- 입력 이벤트와 인증 대화는 기록하지 않는다. **프로그램이 화면에 출력한 비밀은 자동으로 판별할 수 없다.**
- 미완성 줄은 최대 64KiB이고, 일시정지 경계의 조각은 버린다.
- 기록마다 새 폴더를 만들며 이전 폴더는 사용자가 관리한다.

## 분할과 동시 입력

- **배치**: 칸마다 탭 표시줄이 있다. **보기** 메뉴의 **모든 탭 좌우·상하·2 × 2·하나로**로 한 번에 정리하고, 분할선을 끌어 크기를 맞춘다. 분할선을 더블클릭하면 같은 크기로 돌아간다. 탭을 끌어 다른 탭 표시줄에 놓으면 그 위치로 옮기고, 터미널의 바깥쪽 가장자리에 놓으면 그 방향으로 나누고, 가운데에 놓으면 그 칸의 탭으로 합친다. 끄는 중에 Esc를 누르면 취소한다. SSH 탭은 앱 창 밖에 놓으면 새 창으로 분리된다. 패널 너비, 칸의 모양과 크기, 창 크기는 저장된다. 탭은 재시작 후 복원되지 않으므로 다시 시작하면 빈 칸이 있는 모양으로 열리고, 새 탭이 빈 칸을 앞에서부터 채운다.
- **입력 범위**: 터미널이 두 개 이상 보이면 상태바에 **개별 | 전체 | 선택**이 나타난다. **전체**는 보이는 터미널 모두에, **선택**은 각 칸 탭 표시줄의 **입력 받기**를 체크한 창에만 같은 입력을 보낸다. 두 개 이상 체크해야 전달된다. 동시 입력 중에는 대상 칸에 테두리가 생기고 상태바가 경고색으로 바뀌며, 대상이 아닌 칸에는 **입력 전달 대상 아님**이 표시된다. SSH, 로컬 셸, WSL을 함께 고를 수 있지만 셸마다 명령의 의미는 다를 수 있다. FTP와 파드 터미널 탭은 대상이 될 수 없다.
- **Ctrl+Shift+M**은 동시 입력 중이면 바로 중지하고, 아니면 **선택**만 연다. 실수로 눌러도 입력이 퍼지지 않도록 전체로 바로 들어가지 않는다.
- 보이는 창이 바뀌거나(탭 전환, 배치 변경, 이 창 확대 포함) 대상 연결이 끊기면 개별 입력으로 돌아가고 상태바에 이유가 잠시 표시된다. 새 연결과 재접속한 터미널은 자동으로 포함되지 않는다. 여러 줄을 붙여넣으면 확인창에 몇 개 창에 들어가는지 함께 표시한다. 독립 창은 터미널이 하나라 그룹을 만들 수 없다.
- **전체화면**: F11로 전환하고 다시 누르면 사이드바 배치를 복원한다. **이 창 확대**(탭 메뉴, Ctrl+Shift+Enter 또는 탭 표시줄 빈 곳 더블클릭)는 현재 칸만 확대했다가 되돌린다. 터미널은 유지되지만 다른 칸이 가려지므로 동시 입력은 해제된다. 동시 입력 상태와 중지 버튼은 전체화면에서도 상태바에 보인다.
- 창 너비가 700px 이하이면 포커스된 칸만 표시하고, 탭 표시줄의 **다음 칸** 버튼으로 다른 칸으로 옮겨 간다.

## Git 보기

사이드바 **Git** 보기는 선택한 탭의 저장소를 보여 주며, 스테이지와 커밋을 앱 안에서 끝낼 수 있다. SSH, 로컬, WSL 탭의 화면과 동작은 같다. SSH 탭은 서버의 git, 로컬 탭은 이 PC의 git, WSL 탭은 그 배포판 안의 git을 실행한다. FTP 탭에서는 쓸 수 없다. 저장소 밖이면 **Git 저장소가 아닙니다**만 나오고, git을 찾지 못하면 설치 안내와 **설정 → Git** 링크가 나온다.

위쪽에 브랜치와 업스트림 대비 앞섬·뒤처짐, **새로 고침**, **⋯**(더 보기)가 있다. 브랜치 이름을 누르면 [브랜치 전환](#브랜치-전환)이 열린다. 변경은 **스테이지됨**, **변경**, **추적 안 함**, **충돌**로 나뉜다. **⋯ → 폴더로 묶어 보기**로 트리와 목록을 바꾼다. 항목은 앞 5,000개까지만 표시하며, 묶음 제목의 우클릭 동작은 화면에 보이는 파일에만 적용한다. **⋯ → 모두 스테이지**와 **모두 스테이지 취소**는 저장소 전체에 적용한다. 변경 목록과 그래프 사이의 경계를 끌면 위아래 크기가 바뀌고 다시 열어도 유지된다. 경계를 더블클릭하면 반반으로 돌아간다. 단축키는 따로 없고 상태바의 Git 항목을 누르면 이 보기가 열린다.

### 스테이지와 커밋

- **파일 행**: 한 번 클릭하면 [diff 탭](#diff-탭)을 미리보기로 열고, 더블클릭하면 고정한다. 충돌 행은 파일 탭으로 열린다.
- **아이콘과 설명**: 파일 앞의 아이콘은 확장자별 종류를 나타내며 **파일** 트리에도 같게 나온다. **파일** 트리의 폴더는 행을 누르면 열리고 닫힌다(더블클릭은 그 폴더로 이동). 버튼에 마우스를 올리면 설명이 나오고, 누를 수 없는 **커밋** 버튼에는 그 이유가 나온다.
- **행 버튼**: 파일 행이나 묶음 제목에 마우스를 올리면 오른쪽에 **파일 열기**, **변경 버리기**, **스테이지**(스테이지됨은 **스테이지 취소**) 버튼이 나타난다. 우클릭 메뉴의 같은 동작이다.
- **행 우클릭**: **파일 열기**, **diff 열기**, **스테이지** 또는 **스테이지 취소**(충돌은 **해결됨으로 스테이지**), **변경 버리기…** 또는 **파일 삭제…**, **경로 복사**, **외부 편집기로 열기**, 로컬·WSL 탭에서는 **탐색기에서 보기**(macOS **Finder에서 보기**).
- **묶음 제목 우클릭**: **모두 스테이지**, **모두 스테이지 취소**, **변경 모두 버리기…**, **추적 안 함 파일 모두 삭제…**.
- **커밋**: 메시지를 쓰고 **커밋**이나 `Ctrl+Enter`를 누른다. 옆의 메뉴에 **이전 커밋 고치기 (--amend)**가 있다.
- **⋯ 메뉴**: **브랜치 전환…**, **새 브랜치…**, **태그…**, **stash 넣기…**(추적 안 함 파일 포함 선택), **stash 꺼내기**, **모두 스테이지**, **모두 스테이지 취소**, **이 저장소의 Git 설정…**. SSH 탭에는 [변경 검토](#변경-검토)도 있다.
- **되돌릴 수 없는 동작**: 변경 버리기와 추적 안 함 파일 삭제는 대상 파일 목록을 보여 주고 다시 묻는다. 기본 선택은 취소다. 변경 버리기는 스테이지하지 않은 변경만 버리며, 스테이지한 내용은 남는다.
- **커밋 실패**: 이름·이메일이 없으면 **설정 → Git**으로 안내하고, 훅 실패 같은 다른 원인은 Git이 낸 첫 줄을 보여 준다. 머지 충돌을 푸는 전용 편집기와 대화형 rebase, 서브모듈 관리는 없다.
- **출력**: 아래쪽 **출력**을 펼치면 실행한 Git 명령 최근 50개와 결과가 보인다. 앱을 닫으면 사라지며 로그와 진단 내보내기에 남지 않는다.

조회와 스테이지·커밋은 [Git 상태](#git-상태)와 같은 안전 설정으로 실행한다. **커밋 훅은 저장소 설정이므로 그대로 실행되고**, `--no-verify` 메뉴는 없다. 커밋은 훅을 포함해 120초를 넘으면 중단한다. 다른 사람이 만든 저장소에서는 훅과 [clean 필터](#git-상태)가 프로그램을 실행할 수 있음을 알고 쓴다.

### fetch, pull, push

그래프 머리줄의 아이콘이나 **⋯**의 **fetch**, **pull**, **push**는 그 탭의 터미널에 명령을 입력해 실행한다. 비밀번호, 2단계 인증, 호스트 키 질문이 터미널에 그대로 나오고, [SSH 키 전달](#ssh-키-전달)과 [HTTPS 자격 증명 전달](#https-자격-증명-전달)도 셸에서처럼 동작한다.

- **입력하지 않는 경우**: 터미널이 명령을 실행 중이거나 전체 화면 프로그램을 쓰는 중이면 **터미널이 사용 중입니다**로 막는다. 프롬프트에 입력 중인 글자가 있거나 터미널이 저장소 폴더에 있지 않아도 막는다.
- **상태를 모르는 터미널**: PowerShell, 명령 프롬프트, 프롬프트를 알리지 않는 셸, tmux는 실행 중인지 알 수 없다. 입력할 명령을 보여 주고 확인을 받으며 기본 선택은 취소다.
- **강제 push**: **push 강제(안전)…**만 있고 `--force-with-lease`를 쓴다. 다시 물은 뒤 입력한다. `--force` 메뉴는 없다.
- **원격 브랜치 체크아웃**: **브랜치 전환…**의 **원격**에서 고르면 터미널에서 추적 브랜치를 만든다. 글자, 숫자, `_`, `.`, `/`, `-`로만 된 이름만 입력하고, 그 밖의 이름은 직접 입력하도록 안내한다.
- 업스트림이 없는 브랜치의 `push`는 Git이 터미널에 내는 안내를 따른다.

### 브랜치 전환

Git 보기 위쪽의 브랜치 이름이나 **⋯ → 브랜치 전환…**으로 연다. 글자를 입력해 좁히고, 위아래 화살표와 Enter로 고른다. 입력한 이름과 맞는 브랜치가 있으면 Enter는 그 브랜치로 전환하고, 없으면 그 이름으로 새 브랜치를 만든다. **로컬** 브랜치는 앱이 바로 전환하고, **원격** 브랜치는 터미널에서 추적 브랜치를 만든다.

### 그래프

Git 보기 아래쪽 **그래프**를 펼치면 변경 목록과 세로를 나눠 커밋 이력을 보여 준다. 읽기 전용이며, 접어 두면 조회하지 않는다.

- 처음 100개를 보여 주고 **더 불러오기**로 100개씩 늘린다. 최대 1,000개다. 조회는 15초, 출력 4MiB가 상한이고 넘으면 이유와 **다시 조회**가 나온다.
- 머리줄의 버튼은 왼쪽부터 **자동·모두**(현재 브랜치와 업스트림만 / 모든 브랜치와 태그), **현재 커밋으로 이동**, **fetch**, **pull**, **push**, **이력 새로 고침**이다.
- 커밋에 마우스를 올리면 옆에 작성자, 공동 작성자, 시각, 전체 메시지, 바뀐 파일 수와 추가·삭제 줄 수, 브랜치와 태그, 해시 복사 버튼이 있는 카드가 나온다. 키보드로 행을 옮겨도 나오고 Esc로 닫는다.
- 커밋을 누르면 바뀐 파일 목록이 그 행 아래로 펼쳐진다. 파일을 누르면 그 커밋과 부모를 비교하는 [diff 탭](#diff-탭)을 미리보기로 열고, 더블클릭하면 고정한다. 병합 커밋은 첫 번째 부모와 비교한다. 양쪽 다 Git에 저장된 내용이라 편집할 수 없다.
- 우클릭에는 **해시 복사**, **제목 복사**가 있고, 파일 행에는 **diff 고정해서 열기**, **경로 복사**가 있다. 위아래 화살표로 행을 옮기고 Enter나 Space로 펼친다.

### diff 탭

Git 보기의 파일을 누르면 열린다. **스테이지됨**은 HEAD와 인덱스, **변경**은 인덱스와 작업 트리를 비교하고, **추적 안 함**은 새 파일 내용을 보여 준다. 그래프의 파일은 그 커밋과 부모를 비교한다. 위쪽에서 **좌우**와 **한 줄**을 고른다.

- 작업 트리 쪽은 바로 고치고 `Ctrl/Cmd+S`로 저장한다. 저장과 충돌 처리는 [파일 탭](#저장)과 같고, 저장하면 Git 보기가 다시 조회된다. Git 보기에서 스테이지하면 열린 diff도 다시 읽는다. 터미널에서 친 `git add`는 탭 우클릭 **파일 다시 읽기**로 맞춘다.
- 한쪽이라도 2MiB를 넘거나 바이너리면 비교하지 않고 이유만 보여 준다. UTF-8로 읽을 수 없는 파일은 편집을 막는다. 인코딩을 바꾸려면 파일 탭을 쓴다.
- 심볼릭 링크는 Git 쪽이 링크 대상 문자열이고 작업 트리 쪽은 대상 파일 내용이라 전부 달라 보인다.

### 터미널 안 브랜치

프롬프트에서 입력을 기다리는 동안 입력 줄 오른쪽 끝에 `⎇ main ●3` 같은 배지가 보인다. 앱이 위에 그리는 표시라서 터미널 내용에 글자가 들어가지 않고 복사, 검색, 세션 기록에도 남지 않는다. 누르면 Git 상태를 다시 조회한다.

SSH의 Bash·Zsh, WSL의 Bash, macOS 로컬 Bash·Zsh에서 보인다. tmux, PowerShell, 명령 프롬프트, 경로 알림을 연결하지 않은 셸에서는 보이지 않는다. 명령 실행 중과 vim 같은 전체 화면 프로그램에서는 숨겨지고, 입력이 배지 앞까지 오거나 터미널 폭이 40칸보다 좁아도 숨겨진다. 프롬프트에 같은 브랜치 이름이 이미 있으면 그리지 않는다.

### 설정 → Git

**설정**의 **Git** 분류에서 정한다.

- **Git 위치 (이 PC)**: 찾은 경로와 버전을 보여 준다. **파일 선택…**으로 직접 지정하고 **자동 찾기로 되돌리기**로 되돌린다. 지정한 파일을 실행할 수 없으면 자동 찾기로 넘어가지 않고 오류로 알린다. WSL과 서버는 각자의 `PATH`에 있는 git을 쓴다.
- **표시 방식**: 미리보기를 보면서 **터미널 안 브랜치**(프롬프트 줄 오른쪽, 끔), **표시 내용**(브랜치만, 변경 수, 앞섬·뒤처짐까지), **파일 트리**(글자, 파일 이름 색, 둘 다), **상태바 표시**, **Git 상태 자동 조회**, **추적 안 함 파일**(폴더로 묶어서, 파일 하나씩)을 고른다. 추적 안 함 파일 설정은 상태바와 파일 트리에만 적용되고 Git 보기는 항상 파일 단위다.
- **Git 설정 편집**: **대상**(이 PC, WSL 배포판, 현재 SSH 서버)의 `git config --global` 값을 읽어 온다. 저장소 범위는 Git 보기의 **⋯ → 이 저장소의 Git 설정…**로 연다. 이름, 이메일, 기본 브랜치, pull·fetch·push 방식, 줄바꿈, 커밋 메시지 편집기, 충돌 표시 방식, `rebase.autoStash`, `rerere.enabled`, `safe.directory`를 바꿀 수 있다. 바꾼 항목만 **변경 N개 검토…**에서 최종 명령을 확인한 뒤 **실행**으로 쓴다. `safe.directory`의 `*`는 경고한다.
- `credential.helper`는 바꾸려면 직접 입력한다. 값에 비밀이 있을 수 있으면 표시하지 않는다.
- **HTTPS 자격 증명**은 [HTTPS 자격 증명 전달](#https-자격-증명-전달)을 본다.

## 파일 탐색과 전송

### 탐색기

파일 트리가 패널의 중심이다. 폴더 왼쪽의 화살표는 그 자리에서 펼치고, 더블클릭은 그 폴더로 들어간다. 위쪽 아이콘은 상위 폴더, 새로 고침, 새 폴더·파일, 업로드, 붙여넣기이며 마우스를 올리면 이름이 보인다. 선택한 항목의 다운로드, 외부 편집기로 열기, 이름 바꾸기, 권한, 복사·잘라내기, 경로 복사, 압축·압축 해제, 삭제는 항목을 우클릭한다. 아래쪽에는 선택한 항목의 이름과 크기만 보인다. 전송 충돌 정책과 인코딩 정보는 아래쪽 **전송 및 편집**을 펼쳐서 본다. 이 영역은 진행 중인 전송이나 편집이 있으면 자동으로 열린다.

파일을 한 번 클릭하면 [파일 탭](#파일-탭과-편집)에 미리보기로 열리고, 더블클릭하면 탭이 고정된다. 우클릭의 **열기**와 **외부 편집기로 열기**도 쓸 수 있다. Ctrl/Cmd·Shift를 누른 클릭은 선택만 한다. 링크는 폴더일 수 있어 클릭으로 열지 않으며 **열기** 메뉴를 쓴다.

Ctrl/Cmd·Shift 다중 선택, Ctrl/Cmd+C/X/V/A, F2, Delete, F5, 컨텍스트 메뉴, 이름 검색과 정렬, 새 파일·폴더, 복사·이동·재귀 삭제, 권한 체크박스를 제공한다.

- 다른 SSH 연결 사이에서도 복사할 수 있다. FTP 복사는 같은 연결 안에서만 된다.
- 기존 대상은 덮어쓰지 않고 거부한다. 같은 폴더에 복사하면 `복사 1` 이름을 쓴다.
- 링크와 특수 파일의 복사는 거부하고, 삭제할 때 링크를 따라가지 않는다.
- SFTP 파일명은 UTF-8이다. 라이브러리가 손실 변환한 이름을 감지하면 경고하고 작업을 막는다. 비 UTF-8 파일명은 서버에서 먼저 UTF-8로 바꿔야 한다.
- 목록은 20,000개·20초가 상한이며, 하위 경로로 이동해 볼 수 있다.

### 터미널 경로 따라가기

기본으로 켜져 있고 탐색기의 **터미널 경로 따라가기**로 연결별로 끌 수 있다. 터미널 설정에서 새 연결의 기본값도 끌 수 있다. 경로 따라가기와 [조작표](#조작표) 자동 표시를 모두 끈 상태로 연결하면 셸에 아무것도 입력하지 않는다. OSC 7·1337 경로 알림을 받아 따라간다.

- **SSH**: 로그인 셸이 Bash·Zsh이고 첫 프롬프트가 뜨면 현재 세션에 경로 알림(조작표를 켜 두면 실행 알림 포함)을 자동으로 연결한다. 이 입력은 화면에 보이지 않고, Bash는 명령 기록에도 남기지 않는다. Zsh는 `HIST_IGNORE_SPACE`가 꺼져 있으면 기록에 한 줄 남는다. 세션 로그를 켠 경우 로그에는 이 입력이 기록된다. 서버 설정 파일은 바꾸지 않는다.
- **자동 연결을 하지 않는 경우**: 네트워크 장비·강제 명령·다른 셸(fish 등)처럼 Bash·Zsh로 확인되지 않는 서버에는 입력하지 않는다. 이때는 셸이 명령을 기다릴 때 **셸 경로 알림 연결**을 누른다. 이 버튼의 입력은 화면에 보인다. 세션에 tmux 이름을 지정한 연결은 셸에 입력하지 않는다([tmux 세션](#tmux-세션)). 직접 실행한 tmux 안의 셸은 tmux가 알림을 전달하지 않으면 따라갈 수 없다.
- **로컬**: PowerShell, 명령 프롬프트, WSL의 Bash는 시작할 때 경로 알림이 함께 설정된다. WSL의 Zsh는 **셸 경로 알림 연결**을 누른다. macOS 기본 셸(Bash·Zsh)은 SSH와 같이 자동으로 연결한다.

탐색기에서 폴더를 골라도 터미널에 `cd`를 실행하지는 않는다.

### 업로드와 다운로드

**파일 내용은 항상 바이너리 그대로 전송한다.** 텍스트 인코딩, BOM, CRLF/LF를 자동으로 바꾸지 않는다.

- 파일·폴더를 다중 선택하거나 파일 패널에 드롭한 뒤 확인해 업로드한다. 다운로드도 다중 선택할 수 있다.
- 빈 폴더와 하위 경로를 보존한다. 링크와 junction은 따라가지 않는다.
- 같은 이름의 파일은 기본으로 건너뛰며, 이름 변경이나 선택 전체 덮어쓰기를 고를 수 있다. 같은 폴더는 병합한다.
- 시간·달력 예약은 제공하지 않는다.
- 로컬·WSL 파일 패널에 탐색기(macOS Finder)의 파일을 끌어 놓으면 지금 폴더로 복사한다. WSL 패널에서는 우클릭 **다운로드…**로 고른 Windows 폴더로 복사한다.

### 탐색기로 끌어내기

파일 패널의 항목을 끌어 탐색기(macOS Finder)에 놓으면 그 위치로 복사된다. 선택한 줄에서 끌면 선택 전체가, 다른 줄에서 끌면 그 줄만 담긴다.

- **로컬·WSL 파일**: 파일과 폴더를 그대로 넘긴다.
- **서버 파일(SFTP·FTP)**: 끌기를 시작할 때 임시 폴더로 먼저 받으므로, **받는 동안 버튼을 누르고 있어야 한다.** 합쳐 10MiB까지 파일만 된다. 폴더, 링크, 큰 파일은 다운로드를 쓴다. 받은 파일은 앱을 끝낼 때 지운다.
- 한 번의 끌기는 같은 폴더의 항목만 담을 수 있다. 앱 위에 놓으면 아무 일도 하지 않는다.
- 로컬·WSL 패널에서 항목 하나를 우클릭하면 **탐색기에서 보기**(macOS **Finder에서 보기**)가 있다. 서버 파일에는 없다.

### 전송 큐

동시 2개 묶음, 64KiB 버퍼, 최대 100개다. 각 전송 줄에는 지금 할 수 있는 동작 하나(**일시 중지** 또는 **확인 후 이어서 보내기/받기**)만 보이고, 맨 앞으로, 파일별 결과, 전송 취소, 기록 정리·부분 파일 삭제는 줄의 ⋯나 우클릭 메뉴에 있다. 여러 줄을 선택하면 선택 묶음의 일시정지, 재개, 취소 버튼이 나타난다.

- 일시정지하거나 취소해도 부분 파일, 생성한 빈 폴더, 복구 계획을 보존한다.
- 앱을 다시 시작한 뒤 같은 프로필과 서버에 연결해 **이어서 보내기/받기**를 누른다. 원본 크기·수정 시각과 부분 파일 전체 바이트를 검증하고 재개하며, 기존 대상 파일에 이어 쓰지 않는다.
- 크기와 시각을 유지한 채 원본의 미전송 구간만 수정된 경우까지 잡아내지는 못한다. 전체 원본 해시가 아니기 때문이다.
- **부분 파일 삭제**는 명시적으로 선택해야 하며 원본은 지우지 않는다.

폴더 전송의 탐색·기록 상한과 재개 범위는 [폴더 전송·큐 기록](verification/phase-6-1.md)에 있다.

### 압축과 해제

SSH 서버에서 ZIP, TAR, TAR.GZ를 압축하고 푼다. 서버에 Python3와 Linux `renameat2`가 필요하고, ZIP 파일명 CP949·CP932·GBK·Big5 선택은 Python 3.11 이상이 필요하다. 절대·상위 경로, 링크·장치, 중복 항목, 20,000항목 또는 설정한 해제 크기 초과를 거부하며 새 대상에만 확정한다.

## 파일 탭과 편집

파일 패널에서 파일을 열면 가운데 탭에서 형식에 맞게 보여 주고 바로 고칠 수 있다. SFTP, FTP, 로컬, WSL 파일을 모두 연다.

### 열기와 표시

- **문서 편집기**: 터미널을 열지 않아도 이 PC의 파일을 고칠 수 있다. **도구 → 문서 편집기**를 누르고 파일을 고르면 고정 탭으로 열린다. 저장과 닫기 확인은 다른 파일 탭과 같다. 빈 새 문서는 만들 수 없으니 파일을 먼저 만들어 둔다.
- **미리보기 탭과 고정 탭**: 한 번 클릭은 제목이 기울어진 미리보기 탭으로 열리고, 다음 클릭이 그 탭을 바꾼다. 더블클릭, 탭 더블클릭, 편집 시작은 탭을 고정한다. 이미 열린 파일은 그 탭으로 이동한다.
- **FTP**: FTP 탭 자체가 파일 목록이라, 파일은 다른 칸에 열린다. 칸이 하나뿐이면 오른쪽에 새 칸을 만든다.
- **형식**: 코드와 설정 파일은 구문 강조로 보여 준다. Markdown은 **미리보기**와 **원문**을, JSON은 **원문**과 **정리해서 보기**를 전환한다. 정리해서 보기는 값을 바꾸지 않고 공백만 옮긴다. PNG, JPEG, GIF, WebP, SVG는 그림으로 보여 주며 SVG 안의 스크립트는 실행하지 않는다.
- **Markdown 안전**: 미리보기는 HTML을 정화한다. 원격 이미지는 불러오지 않고, 링크는 물어본 뒤 기본 브라우저로 연다. 파일 기준 상대 경로 이미지는 표시하지 않는다.
- **크기**: 2MiB를 넘는 텍스트는 **크게 열기**를 누르면 읽기 전용, 구문 강조 없이 연다. 탭에서 여는 상한은 32MiB다. 바이너리 파일은 열지 않고 크기와 형식만 보여 준다.
- **인코딩**: UTF-8, BOM, UTF-16을 알아본다. FTP는 세션 인코딩을 따른다. 상태바의 인코딩을 누르면 다른 인코딩으로 다시 읽는다. 그 인코딩으로 그대로 저장할 수 없는 바이트가 있으면 원본을 망가뜨리지 않게 편집을 막는다.
- **연결이 끊긴 탭**: 읽기 전용으로 남고 저장할 수 없다. 편집 내용은 복사해 둘 수 있다.

### 편집

- 다중 커서, 세로 선택, 줄 복제·이동, 정규식 찾기·바꾸기를 쓸 수 있다.
- 편집기 우클릭의 **공백 문자 보기**와 **자동 줄바꿈**(`Alt+Z`)은 모든 탭에 적용되고 다음 실행에도 유지된다.
- 상태바에서 줄바꿈(LF/CRLF)과 들여쓰기(탭, 공백 2, 공백 4)를 바꾼다. 줄바꿈이 섞인 파일은 저장할 때 한 가지로 통일된다고 안내한다.
- 탭 우클릭 **파일 다시 읽기**로 바깥에서 바뀐 내용을 읽는다. 저장 안 한 편집이 있으면 먼저 묻는다.

### 저장

- 저장 안 된 탭에는 `●`가 붙는다. `Ctrl/Cmd+S`로 저장하고, 탭에 포커스가 있을 때 `Ctrl/Cmd+Shift+S`로 다른 이름으로 저장한다.
- 탭이나 앱을 닫을 때 저장 안 된 내용이 있으면 **저장**, **저장 안 함**, **취소**를 묻는다.
- **충돌**: 파일을 연 뒤 내용이 바뀌었거나 사라졌으면 저장하지 않고 카드로 묻는다. **서버 내용 보기**로 지금 편집본과 비교하고, **덮어쓰기**(사라졌으면 **다시 만들기**)나 **취소**를 고른다. 덮어쓰기는 한 번 더 묻는다.
- **서버 파일 교체**: SFTP는 임시 파일을 쓴 뒤 교체한다. FTP는 업로드 덮어쓰기와 같은 백업 방식이라 원자적이지 않고, `.dachsterm-*.backup` 백업을 지우지 못하면 저장은 끝난 것으로 두고 안내한다.
- **권한과 링크**: 파일 권한은 유지한다. FTP에서 `SITE CHMOD`가 안 되는 서버는 새 파일 기본 권한이 된다. 링크는 대상 파일을 고치며, FTP는 링크 대상을 알 수 없어 저장을 막는다.
- 쓸 수 없는 글자가 있으면 저장하지 않는다. 내장 편집은 사용자가 직접 저장하는 것이라 아래 [외부 편집](#외부-편집)의 저장 확인 카드를 띄우지 않는다.

## 외부 편집

파일을 우클릭해 **외부 편집기로 열기**를 고른다. SFTP 서버 파일과 로컬·WSL 파일에서 쓸 수 있고, 32MiB까지 지원한다. FTP 파일은 [파일 탭](#파일-탭과-편집)에서 고친다.

- **편집기**: 이 컴퓨터에 설치된 편집기를 찾아 카드로 보여 준다. Windows는 VS Code, Cursor, Windsurf, Zed, Sublime Text, Notepad++, EditPlus, 메모장, macOS는 VS Code, Cursor, Windsurf, Zed, Sublime Text, BBEdit, CotEditor, 텍스트 편집기를 표준 설치 위치에서 찾는다. 목록에 없으면 **다른 프로그램…**으로 실행 파일을 고르거나 **경로 직접 입력**에 절대 경로를 넣는다. 원격 파일은 JSON 인자 배열도 지정할 수 있다. 셸 문자열로 실행하지 않는다.
- **저장 후 동작**: 기본은 저장 후 업로드 확인이고, 자동 업로드나 수동 업로드를 고를 수 있다. 저장은 2초 간격으로 감지하고 350ms 안정 구간을 기다린다. 확인이나 업로드를 취소해도 로컬 수정본은 보존한다. 편집기 자체의 자동 저장과 DachsTerm의 자동 업로드는 별개다.
- **저장 확인 카드**: 저장 후 업로드 확인이면 사이드바가 어느 보기에 있어도 그 연결의 탭 위에 카드가 뜬다. **업로드**, **취소 · 수정본 보존**, **이 연결 동안 자동 업로드** 중에서 고른다. 마지막 선택은 저장되지 않아 재접속하거나 앱을 다시 켜면 다시 묻는다. 앱이 포커스를 잃었으면 터미널 설정의 OS 알림을 켜 둔 경우 알림도 보낸다. 로컬·WSL 파일은 업로드가 없어 카드도 없다.
- **파일 인코딩**: 기본 **원본 바이트 유지**는 편집기에서 인코딩을 고른다. 인코딩을 명시하면 로컬 UTF-8 작업 파일로 변환하고 저장할 때 원래 인코딩으로 되돌리며, 표현할 수 없는 문자가 있으면 업로드하지 않는다. 인코딩을 자동으로 추측하지 않는다.
- **충돌**: 원격 SHA-256이 편집 시작 시점과 다르면 카드에서 **다시 받기**, **다른 이름…**, **덮어쓰기…**, **취소 · 수정본 보존** 중에서 고른다. 다시 받기는 로컬 수정본을 `.bak`로 남긴다. 덮어쓰기는 한 번 더 묻는다.
- **원자적 교체**: 서버가 `posix-rename@openssh.com`을 지원할 때만 기존 파일을 원자적으로 교체한다. 미지원 서버에서는 다른 이름으로 저장한다. 파일 모드는 유지하지만 ACL, xattr, 소유자 전체를 복제한다고 보장하지 않는다. 검사와 rename 사이에 다른 쓰기가 끼어드는 경쟁은 SFTP만으로 제거할 수 없다.
- **작업 파일**: 앱 데이터의 `edits/<UUID>/`에 사용자 전용 권한으로 저장한다. 실패, 충돌, 종료 시 복구본을 자동으로 지우지 않으며, 같은 세션과 대상에 다시 연결해 재시도한다. **동기화된 파일 정리**는 업로드가 끝난 파일만 지운다.

## FTP와 FTPS

세션 폼의 프로토콜에서 **FTP · 암호화 없음** 또는 **FTPS · 명시적 TLS**를 선택한다. 기본 포트는 21번이다. SSH와의 기능 차이는 [README의 지원 범위](../README.md#지원-범위)에 있다.

- **FTPS**: OS 신뢰 CA와 선택한 추가 PEM CA로 인증서와 서버 이름을 검증하며, 평문으로 전환하지 않는다.
- **FTP**: 네트워크의 인증정보와 내용을 암호화하지 않으며 화면에도 이를 표시한다.
- 두 방식 모두 Binary·PASV로 파일 바이트를 유지하고, 데이터 연결은 제어 연결의 서버로 제한한다.
- 파일명과 명령 인코딩은 UTF8, CP949, Shift_JIS, GBK, Big5, Windows-1252 중에서 고른다.
- 파일 목록과 작업은 가운데의 FTP 탭에서 한다. 폴더 재귀 전송과 영속 전송 큐를 지원한다. 파일 내용은 [파일 탭](#파일-탭과-편집)에서 보고 고친다.
- 서버 간 복사, implicit FTPS, Active FTP, FXP는 제공하지 않는다.
- FTP RFC에는 원자적 no-replace rename이 없어, 확인과 rename 사이에 다른 클라이언트가 같은 이름을 만드는 경쟁을 완전히 막을 수 없다.
- 네트워크가 갑자기 끊긴 뒤 서버가 부분 파일을 잡고 있으면 정리될 때까지 기다렸다가 재개한다.

## 터널

맨 위의 **터널** 아이콘이나 **도구 → 터널**(Ctrl+Shift+U)에서 Local, Remote 목적지를 지정하거나 SOCKS5 TCP CONNECT를 쓴다.

- 127.0.0.1 루프백에만 바인딩한다. SOCKS5 UDP/BIND와 공개 인터페이스 바인딩은 지원하지 않는다.
- 실행 터널은 최대 32개, 터널당 동시 스트림은 64개다.
- 저장된 터널마다 **시작**·**중지** 버튼 하나가 있고, 수정, 연결 시 자동 시작 켜기·끄기, 삭제는 ⋯나 우클릭 메뉴에 있다. 자동 시작이 켜진 터널에는 `자동 시작` 표시가 붙는다.
- 자동 시작은 해당 SSH 세션이 연결되거나 재접속할 때 적용되며, 새 인증을 우회하지 않는다. 가져온 터널의 자동 시작은 꺼져 있다.

### 서버 포트 열기

서버에서 띄운 개발 서버를 PC 브라우저로 여는 임시 터널이다. **터널 → 서버 포트 보기**를 누르거나, SSH 탭에서 `localhost` 링크를 Ctrl/Cmd+클릭한다.

- 창을 열 때와 **새로고침**할 때만 서버의 포트 목록을 읽는다. Linux 서버에서만 동작하고, 1024 미만 포트는 기본으로 숨긴다.
- 사용자가 고른 뒤에만 터널을 연다. PC 포트는 서버와 같은 번호부터 시도하고, 사용 중이면 다음 번호를 최대 10개까지 시도한다.
- 저장되지 않으며 연결이 끝나면 함께 닫힌다. 같은 대상이 이미 열려 있으면 다시 쓴다. 실행 중인 터널은 이 창에서 중지한다.

## SSH 키 만들기

**도구 → SSH 키 만들기**에서 Ed25519 키 한 쌍을 만든다. 키는 이 PC에만 만들어지고 개인키 내용은 화면에 나오지 않는다.

| 항목 | 내용 |
|---|---|
| 파일 이름 | 기본 `id_ed25519`. 영문, 숫자, `.`, `_`, `-`만 쓴다 |
| 주석 | 기본 `사용자@PC`. 공개키 끝에 붙어 서버에서 키를 구분하는 데 쓴다 |
| Passphrase | 선택. 넣으면 개인키를 암호화하고, 접속할 때 묻는다. 잊으면 복구할 수 없다 |
| 저장 폴더 | 기본 `~/.ssh`. 직접 입력하거나 **찾아보기…**로 고른다. 기본 폴더가 없으면 만든다 |

- 개인키 파일(`이름`)과 공개키 파일(`이름.pub`)을 함께 만든다. 같은 이름의 파일이 있으면 만들지 않고, 기존 파일을 덮어쓰지 않는다.
- 개인키 파일은 만들 때부터 현재 사용자만 읽을 수 있다. 다른 폴더로 복사하면 권한이 달라져 `ssh`가 거부할 수 있다.
- 완료 화면에서 저장 위치, 지문, 공개키를 보고 **공개키 복사**로 복사한다.
- 서버에 접속하려면 공개키를 서버의 `~/.ssh/authorized_keys`에 직접 추가한다. 자동으로 등록하지는 않는다.
- 세션 편집 창의 개인키 파일 경로와 **전달할 키** 목록 옆의 **새 키…**로 만들면 그 칸에 바로 들어간다.
- 키 종류는 Ed25519만 제공한다. 아주 오래된 서버는 이 형식을 지원하지 않을 수 있다.

## 네트워크 도구

**도구 → 네트워크**의 도구는 가운데 탭으로 열리고, 세션 없이 바로 쓴다. 맨 위의 **출발지**에서 어디서 점검할지 고른다.

- **로컬**: 이 PC에서 점검한다.
- **리모트**: 등록된 SSH 세션의 서버에서 점검한다. 같은 세션의 터미널이 연결돼 있으면 그 연결을 함께 쓴다. 없으면 셸 없이 연결하고, 탭을 닫거나 5분간 쓰지 않으면 끊는다. 서버에 아무것도 설치하지 않는다.

### 포트 개통

출발지에서 대상의 TCP 포트로 연결이 되는지 확인한다. 연결되면 바로 닫고 아무것도 보내지 않는다.

- **대상**: 호스트 이름, IPv4·IPv6 주소, IPv4 대역(`10.0.0.0/24`). 쉼표나 공백으로 여러 개를 적는다.
- **포트**: `22,80,8000-8100`처럼 적는다.
- **시간 초과**: 1~30초, 기본 3초. 대상이 응답할 때까지 기다리는 시간이다. Windows는 연결 거부를 약 2초간 재시도하므로 로컬 점검은 2.5초 미만으로 정해도 2.5초까지 기다린다.

| 결과 | 뜻 |
|---|---|
| 열림 | 연결에 성공했다 |
| 닫힘 | 대상까지 닿았지만 그 포트를 쓰는 프로그램이 없다 |
| 응답 없음 | 시간 안에 답이 없다. 방화벽 차단일 가능성이 높지만 확정할 수는 없다 |
| 도달 불가 | 경로가 없다고 장비가 알렸다 |
| 확인 불가 | 점검 자체를 못 했다(이름 해석 실패 등). 이유가 옆에 표시된다 |
| 닫힘 또는 도달 불가 | 리모트에서 닫힘으로 보이는 대상이 64개를 넘어 사유를 하나씩 확인하지 않았다 |
| 닫힘 또는 응답 없음 | 서버의 `nc`로 확인해 둘을 구분할 수 없다 |

- 대상이 둘 이상이면 시작 전에 시도 수를 보여 주고 확인을 받는다. 허가된 망에서만 쓴다. 접속 시도는 상대 장비의 로그에 남는다.
- 한 번에 호스트 256개, 시도 4,096회까지다. 동시 연결은 로컬 64개, 리모트 16개다.
- 결과가 많으면 `256개 중 12개 열림`으로 요약하고 열린 포트만 보여 준다. **전체 결과 보기**로 나머지도 본다.
- 결과 행을 우클릭하면 **복사**(출발지, 대상, 포트, 결과, 시각), **다시 점검**, **서비스 연결로 보기**가 있다. **서비스 연결로 보기**는 같은 출발지로 [서비스 연결](#서비스-연결) 탭을 열어 바로 점검한다.
- 진행 중에 **취소**할 수 있고, 그때까지의 결과는 남는다.
- 리모트는 서버가 응답하지 않은 시도를 연결당 256개까지만 둔다. 서버는 응답 없는 대상을 약 2분간 붙들고 있으므로 이 수에 닿으면 `서버 응답 대기 중`으로 기다린다.
- 리모트 취소: 서버에 남은 시도는 연결을 끊어야 사라진다. 도구가 직접 연 연결이면 끊고(**다시 연결**로 잇는다), 터미널 연결을 함께 쓰는 중이면 끊지 않고 서버가 응답할 때까지 둔다.
- 서버가 더 연결을 시작하지 못하면(`서버가 연결을 더 시작하지 못함`) 새 시도를 멈추고, 시도하지 못한 대상은 `확인 불가`로 표시한다.
- 서버가 포워딩을 금지하면 서버의 `bash`, 없으면 `nc`로 대신 시도하고 결과 옆에 그 방식을 적는다. 둘 다 없으면 `확인 불가`다.

### 포트 사용 여부

출발지에서 어떤 포트를 쓰고 있는지 본다. TCP 대기와 UDP 바인드를 함께 보여 준다.

- 포트를 비우고 **확인**을 누르면 전체 목록이 나온다. 포트를 넣으면 `사용 중`인 포트의 프로세스와 주소, `사용 안 함`인 포트를 알려 준다. 포트 칸은 읽어 온 목록을 그 자리에서 거른다.
- 목록을 읽은 방법을 함께 표시한다.

| 출발지 | 읽는 방법 |
|---|---|
| Windows | 시스템의 소켓 표와 프로세스 목록 |
| macOS | `/usr/sbin/lsof`. 다른 계정의 소켓은 보이지 않을 수 있다 |
| 리모트 Linux | `/proc/net`으로 목록을 정하고 `ss`, 없으면 `netstat`으로 프로세스 이름을 붙인다 |
| 그 밖의 서버 | `lsof`, 없으면 `netstat -an`. 프로세스 이름이 없을 수 있다 |

- 관리자 권한을 쓰지 않는다. 다른 계정의 프로세스 이름은 `권한 없음`, 이름을 읽을 도구가 없으면 `알 수 없음`으로 나온다.
- SSH로 연결하지 못했거나 서버의 목록을 읽지 못했을 때, 포트를 입력했으면 그 세션의 주소로 이 PC에서 연결해 보고 **외부에서 확인한 결과**로 표시한다. 방화벽 때문에 서버 안의 상태와 다를 수 있다. 전체 목록은 낼 수 없다.

### 서비스 연결

출발지에서 대상에 실제로 연결해 무엇이 응답하는지 확인한다. 서버에 `curl`이나 `openssl`이 없어도 된다.

- **대상**: `api.example.com:443` 또는 `https://api.example.com/health` 같은 주소. 주소에 사용자 이름이나 암호는 넣을 수 없다.
- **형식**: **자동**, **HTTP**, **HTTPS**, **TLS**, **TCP 배너**. 자동은 서버가 먼저 보내는 내용을 2초 기다리고, 없으면 TLS, 그다음 HTTP를 시도한다. 시도마다 새로 연결하고 최대 3회다. 주소가 `http://`나 `https://`로 시작하면 자동일 때 그 형식을 쓴다.

결과는 `WAS01 → api.example.com:443   연결됨 · HTTPS 200 · 42ms`처럼 한 줄로 나오고, 누르면 상세가 펼쳐진다.

| 상세 | 내용 |
|---|---|
| 이름 해석 | 찾은 주소와 걸린 시간. 리모트는 서버가 연결하면서 해석하므로 시간을 잴 수 없고, 서버에 `getent`가 있으면 주소만 표시한다 |
| TCP 연결 | 성공과 걸린 시간, 또는 포트 개통과 같은 결과(닫힘, 응답 없음 등) |
| TLS | 버전, 인증서 만료일, 신뢰 결과. 인증서의 주체·발급자·이름을 함께 보여 준다 |
| 응답 | HTTP 상태, `Server`, `Location` |
| 서버가 보낸 내용 | 배너나 HTTP가 아닌 응답 |

- 인증서는 신뢰할 수 없어도 읽어서 보여 주고 결과를 따로 표시한다(자체 서명, 만료됨, 이름 불일치 등). 이 연결로 인증정보를 보내지 않는다.
- HTTP는 `HEAD`만 보내고 본문을 읽지 않는다. 배너와 응답은 4KiB까지만 읽고 제어 문자를 지운다.
- `연결됨`이어도 L4 장비나 프록시가 대신 받은 것일 수 있다. 응답 내용과 인증서를 함께 보고 실제 서비스인지 판단한다. 응답으로 구분할 수 없으면 `서비스 확인 안 됨`으로 표시한다.
- 서버가 포워딩을 금지하면 서비스 연결은 할 수 없다. 포트가 열렸는지만 보려면 [포트 개통](#포트-개통)을 쓴다.

#### 경로 추적

펼친 결과의 **경로 추적** 옆 **실행**을 누를 때만 동작한다. 최대 30홉이고 진행 중에 **취소**할 수 있다.

| 출발지 | 방법 | 표시 |
|---|---|---|
| Windows | ICMP(IPv4만, 관리자 권한 불필요) | 참고용 |
| macOS | `/usr/sbin/traceroute`, TCP를 먼저 시도하고 안 되면 UDP | TCP면 점검한 포트 기준, UDP면 참고용 |
| 리모트 root | `traceroute -T`, 안 되면 아래 줄 | 점검한 포트로 보낸 TCP |
| 리모트 일반 계정 | `traceroute`, `tracepath` 순서 | 참고용 |
| 도구가 없거나 실행할 수 없는 서버 | 실행하지 않음 | `이 서버에서는 경로 추적을 할 수 없습니다` |

- 결론은 `대상까지 도달했습니다` 또는 `마지막 응답 장비는 X, 그 다음 구간에서 끊김`까지만 적는다. 방화벽은 대개 응답하지 않으므로 특정 장비가 막았다고 단정하지 않는다.
- 참고용은 그 포트의 방화벽 정책과 무관하므로, 경로가 보여도 해당 포트가 열렸다는 뜻은 아니다.

## 서버 모니터링

Linux의 `/proc`과 `df -Pk`를 별도 SSH 채널로 수집한다. 서버에 아무것도 설치하지 않는다. 기본 5초 간격이고 2~60초로 바꾸거나 끌 수 있다.

- **CPU, NET**: 첫 샘플과 카운터 리셋 때는 측정 중으로 표시한다.
- **NET**: 기본은 loopback을 제외한 인터페이스 합계다. 브리지와 가상 인터페이스가 중복 집계될 수 있으며, 상세 보기에서 인터페이스 하나를 고를 수 있다.
- **RAM**: MemAvailable 기준이다.
- 상태바 오른쪽의 `CPU · RAM`을 누르면 상세 보기가 열린다.
- **DISK**: 상세 보기에 마운트별 사용량을 표시한다.
- 수집 출력은 256KiB·10초, 기록은 120개가 상한이다. 터미널과는 별도 채널, 별도 취소 범위로 동작한다.

## 쿠버네티스 작업 화면

SSH로 접속한 서버의 `kubectl`이나 이 컴퓨터의 kubeconfig로 클러스터를 조회하고 간단히 제어한다. kubeconfig를 PC로 가져오지 않아도 되며, 서버와 클러스터에 아무것도 설치하지 않는다.

### 여는 방법

- **세션**: 세션 편집의 **접속 후 화면**을 **쿠버네티스**로 저장하면 접속 즉시 열린다. 처음 접속하면 `kubectl`과 kubeconfig를 찾아 context와 namespace를 고르게 하고, 다음부터는 저장된 값으로 연다.
- **열린 SSH 탭**: 탭 헤더 우클릭 → **쿠버네티스 화면 열기**. 이렇게 연 화면은 세션을 바꾸지 않고 조회 모드로만 동작한다.
- **이 컴퓨터의 클러스터**: 연결 목록 **로컬**의 **로컬 클러스터**. context를 바꾸면 운영 모드가 꺼진다.
- `kubectl`을 찾지 못했거나 kubeconfig를 읽을 수 없으면 화면이 이유와 해결 방법을 안내한다. 터미널에서 할 일은 **서버 터미널** 탭에서 하고 **다시 확인**을 누른다.

화면 위쪽 탭은 **트리, 대시보드, 문제 목록, 변화 기록, 인그레스, 실시간 로그, 로그 검색**이고, 오른쪽 **서버 터미널**(로컬 클러스터는 **로컬 터미널**)로 셸을 볼 수 있다. 목록은 화면을 보는 동안 주기적으로 갱신되고, 다른 탭을 보거나 터미널로 가면 멈춘다. 권한이 없는 항목은 그 항목만 비우고 이유를 적는다.

### 트리

노드, namespace, 워크로드(또는 서비스), 파드를 접고 펴며 본다. **묶기**에서 묶는 기준을, 열 제목으로 정렬을, 위쪽 칸으로 필터를 바꾼다. 필터는 공백이 AND이고 `!단어`는 제외다. **문제만**은 문제가 있는 파드만 남긴다.

| 키                      | 동작                          |
| ----------------------- | ----------------------------- |
| 방향키, `H` `J` `K` `L` | 이동, 접기·펴기               |
| `Enter`, `Space`        | 파드는 로그, 그룹은 접기·펴기 |
| `/`                     | 필터                          |
| `G`                     | 묶는 기준 바꾸기              |
| `S` / `E`               | 파드 셸 / 이벤트              |
| `Esc`                   | 옆 패널 닫기                  |

대상별 조작은 행 우클릭에 있다. **보이는 트리 복사**는 접히지 않은 행을 context, namespace, 묶기, 필터 머리글과 함께 클립보드에 넣는다.

### 파드 패널

파드를 열면 옆에 **로그, 장애 원인, 개요, 런타임, 이벤트, YAML, 관계** 탭이 있다. 문제가 있는 파드는 **장애 원인**부터 연다.

- **로그**: 키워드 필터와 직전 인스턴스 로그. 파드 하나를 계속 따라가려면 터미널 탭으로 연다.
- **셸**: 파드 안에서 bash, 없으면 sh를 연다. 같은 SSH 연결에 채널을 추가하므로 OTP를 다시 묻지 않는다.
- **런타임**: 파드 안에서 앱에 고정된 읽기 명령만 실행해 프로세스·워커 수, 스레드, FD, TCP 연결 상태, LISTEN 대기 큐, SYN 넘침·드롭·재전송을 수집한다. 워크로드마다 처음 한 번 확인을 받고, 버튼으로 수집하며 직전 수집과의 증가량을 표시한다. `pods/exec` 권한이 없으면 그 사실만 표시한다.

### 대시보드, 문제 목록, 변화 기록

**대시보드**는 클러스터 전체를 한 화면에, **문제 목록**은 NotReady 노드, 미달 워크로드, 대기 PVC, 실패한 Job, 최대치 HPA, 문제 파드, 최근 재시작을 모아 보여 준다. 문제 목록 위 체크박스로 이 세션의 새 문제를 OS 알림으로 받을 수 있고, 기본은 꺼져 있다.

**변화 기록**은 앱이 켜진 동안의 상태 변화를 최대 500건 메모리에만 쌓는다. 앱을 끄면 기록과 알림도 멈춘다.

### 인그레스

호스트별로 경로, 백엔드, 준비 수, TLS를 묶어 보여 주고 백엔드 없음, 준비 0, 주소 미할당, TLS Secret 없음을 표시한다. 요청률과 2xx·4xx·5xx 비율, 평균 지연은 ingress-nginx 컨트롤러의 메트릭이 있을 때만 나온다.

### 실시간 로그와 로그 검색

**실시간 로그**는 여러 파드의 로그를 나란히 또는 시간순으로 합쳐 본다. 트리 우클릭의 **실시간 로그에 추가**나 그룹의 **실시간 로그 보기**로 대상을 넣고, 인그레스 행에서는 컨트롤러 로그와 서비스 파드를 위아래로 연다. 파드가 바뀌면 대상을 다시 계산한다. 소스는 최대 20개이고 로그는 메모리에만 있으며 파일로 저장하지 않는다.

**로그 검색**은 범위, 시간, 키워드로 여러 파드의 지난 로그를 찾아 표로 보여 준다. 키워드는 공백이 AND, `!단어`는 제외이고 대소문자를 가리지 않는다. 결과 행 우클릭으로 복사할 수 있다.

### 조회 모드와 운영 모드

기본은 조회 모드다. 헤더의 모드 표시를 눌러 운영 모드를 켜면 트리 우클릭으로 **파드 삭제, 롤아웃 재시작, Cordon·Uncordon**을 실행할 수 있고, 실행 전에 대상과 영향을 확인받는다. 조회 모드에서는 메뉴에 남아 있되 비활성화되고 이유를 표시한다. 클러스터 권한은 기존 RBAC를 따르며, 전역 current-context를 바꾸지 않는다.

제공하지 않는 것: 패킷 캡처, YAML 적용, Helm, RBAC 관리, 포트 포워딩. 패킷을 봐야 하면 이미지에 tcpdump가 있는 파드의 셸에서 직접 실행한다.

## 세션 관리와 이관

- **설정 → 세션 일괄 수정 · 템플릿**에서 여러 세션을 한 번에 고치고 템플릿을 관리한다. 템플릿에 목적지, 사용자명, 비밀정보는 들어가지 않는다.
- **설정 → 세션 가져오기 · 내보내기**는 자체 JSON v3(v1, v2 읽기 지원), PuTTY `.reg`, 세션 북마크 파일(`.mxtsessions`, `.ini`), OpenSSH `config`를 미리 보고 선택해 추가한다. 제품별 기본 접속 정보만 변환한다.
- 내보내기에는 세션, 그룹, 터널, 템플릿만 포함한다. 비밀번호, Passphrase, 개인키 내용, OS 저장소 참조는 들어가지 않는다.
- 가져오기는 전체를 검증한 뒤 트랜잭션으로 추가하며 새 ID를 부여한다. 자동으로 접속하지 않는다.

지원표와 파일 규약은 [세션 가져오기·내보내기](session-transfer.md)에 있다.

## 복구와 진단

**설정 → 복구와 진단**에서 비밀정보 없는 설정 복구본을 만들거나 가져오고, 진단 JSON을 저장한다.

- 세션 수정·삭제, 그룹 삭제, 터널 변경, 설정 가져오기 전에 복구본을 자동으로 만들고 최근 10개를 보관한다.
- 복구본을 가져오면 기존 항목을 유지하고 새 ID로 추가한다. 저장 암호, 호스트키, 편집 파일은 포함되지 않으므로 PC 전체 백업을 대신하지 않는다.
- 앱은 같은 데이터 폴더를 동시에 수정할 수 없도록 인스턴스를 잠근다. DB가 손상되었거나 미래 버전이면 자동으로 초기화하지 않고 오류로 알린다.

## 로컬 게임

왼쪽 사이드바 아래의 **게임**을 펼쳐 고른다. 게임은 중앙 작업 영역의 일반 탭으로 열리고, 서버에서 프로그램을 실행하지 않는다.

- 탭을 전환하면 현재 판을 유지하고 실시간 게임을 일시정지한다. 돌아와서 **계속하기**(모험은 Space 또는 P)로 재개한다.
- **Esc / 작업으로 돌아가기**는 이전 작업 화면으로 돌아가고, 탭의 **×**는 현재 판을 끝낸다.
- 최고 기록은 로컬에 저장된다. 현재 판은 앱을 다시 시작하면 복원되지 않는다.

### 블록 퍼즐, 스네이크, 2048, 지뢰찾기

익숙한 규칙의 기본 미니게임이다.

### 닥스의 간식 타임

45초 동안 간식(+10)과 별(+30)을 받고 양파를 피한다. 목숨은 3개다. 놓친 간식은 감점 없이 연속 횟수만 초기화한다.

| 조작 | 키                  |
| ---- | ------------------- |
| 이동 | 방향키, A/D, 드래그 |

### 닥스의 모험

시드 기반 랜덤 횡스크롤 액션이다. 숲, 유적, 동굴, 설원이 순환하고 맵 선택에서 환경과 시드를 고를 수 있다.

| 조작            | 키          |
| --------------- | ----------- |
| 이동            | ←/→, A/D    |
| 점프            | ↑, W        |
| 물기, 시작      | Space, J, X |
| 빠른 밟기(공중) | ↓, S        |
| 일시정지        | P           |
| 효과음          | M           |

- **점수**: 간식 25, 물기 50, 밟기 75, 구간 통과 200. 체력 5, 쉼터 3곳.
- **보스전**: 구간 끝의 보스(체력 8)를 물기(1 피해)와 머리 밟기(2 피해)로 쓰러뜨리면 출구가 열린다. 처치하면 500점과 체력 2를 얻는다.
- **다음 구간**: 점수와 거리를 유지하고 체력 +1. **쉼터 재도전**: 점수와 획득을 유지하고 처치하지 못한 보스를 복원. **다시 시작**: 현재 맵을 처음부터 초기화.

### 닥스의 서바이버

자동 공격으로 버티는 생존 게임이다. 경험치를 모으면 전투가 멈추고 카드 3장 중 하나를 고른다. 일반 구간 60초를 버티고 3·6·9… 구간의 보스를 처치한 뒤, 성장과 HP를 유지해 다음 스테이지로 가거나 정산한다. 쉼터에서 골드로 영구 강화, 해금, 강화 환불을 할 수 있다.

| 조작           | 키                       |
| -------------- | ------------------------ |
| 이동           | WASD, 방향키, 8방향 패드 |
| 카드 선택      | 1/2/3, 방향키와 Enter    |
| 카드 다시 뽑기 | R                        |
| 일시정지·재개  | P                        |
| 음소거         | M                        |
| 작업으로 복귀  | Esc                      |

- 사망, 마무리, 포기, 탭 닫기는 보상을 정산한다. 저장에 실패하면 결과와 재시도 버튼을 유지한다.
- 다른 창에서는 읽기 전용이다. 저장을 지원하지 않는 환경의 임시 플레이는 보상을 저장하지 않는다.
- 앱을 다시 시작하면 전투 자체는 복원되지 않고, 마지막 체크포인트의 보상을 중단된 판으로 정산한다. 프로세스 강제 종료나 전원 차단에서는 저장이 유실될 수 있다.
