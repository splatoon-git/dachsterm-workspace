# DachsTerm 로드맵

- 제품명: DachsTerm. 코드·패키지·실행 파일의 내부 식별자는 `dachsterm`.
- 대상: Windows 11 / macOS 로컬 데스크톱 SSH 서버 관리 클라이언트.
- 이 문서는 범위·디자인·보안·완료 기준의 정본이다. 상태와 다음 작업은 [progress.md](progress.md), 코드 작성과 검증 보고 규칙은 [engineering-rules.md](engineering-rules.md)를 따른다.

## 1. 목표와 범위

SSH 작업 흐름을 중심으로 SSH, SFTP·FTP/FTPS, 외부 파일 편집, 멀티 터미널, 터널링, 서버 상태 모니터링을 한 앱에 제공한다. 별도 백엔드 서버, 서버 에이전트, 계정 없이 동작하는 무료 개인용 앱이다.

**Windows와 macOS는 모두 출시 대상이다.** macOS는 Apple Silicon만 지원한다. 지금은 개인 사용이며, 공개 배포 때 Apple Developer 등록 후 서명·공증을 구성한다. 개발은 주로 Windows에서 하고 macOS 네이티브 빌드와 OS 전용 동작은 MacBook에서 따로 검증한다. Mac 검증을 배포 직전으로 몰지 않는다. 남은 Mac 항목(M.*)은 [macOS 준비 상태](verification/macos-readiness.md)를 따른다.

제외: 참고 제품의 전체 기능 복제, 앱 안의 X 서버, RDP/VNC, 클라우드·팀 동기화, 팀 계정, 유료 외부 서비스 의존, UI 다국어, Linux·Intel Mac·Windows ARM 지원. 추가 요청을 이 제외 범위의 복제 요청으로 확대 해석하지 않는다.

## 2. 확정된 디자인 요구사항

### 2.1 참조 범위 — 컬러셋만

**`workspace-pms`에서는 라이트 레트로 컬러셋만 참고한다. 디자인 콘셉트, 화면 배치, 컴포넌트 스타일은 가져오지 않는다.**

- SSH 작업에 맞는 현대적이고 간결한 데스크톱 UI를 독립적으로 설계한다. 레트로풍 장식, 종이 질감, 픽셀 폰트, 옛 OS 스타일, 과장된 입체 테두리는 요구사항이 아니다.
- 색상 원본은 `D:/Work/workspace-pms/pms_front/src/plugins/vuetify/theme.js`의 `retroColors`다. Vue/Vuetify 구현과 업무 화면 구조는 이식하지 않는다.
- 크림색 라이트 테마를 기본으로 여러 테마를 제공하며(§2.6), 모든 테마가 공통 토큰 계약과 등록 구조를 쓴다.

### 2.3 공통 테마 토큰 구조

컴포넌트에서 테마 ID로 분기하거나 색상을 직접 지정하지 않는다. 앱 UI, 터미널, 차트, 팝업, 분리된 창이 같은 테마 계약을 쓴다.

| 계층 | 역할 | 예시 |
|---|---|---|
| 공통 토큰 계약 | 모든 테마가 제공할 키와 타입 | `ThemeDefinition` |
| 기초 토큰 | 간격·타이포그래피·모서리·테두리·그림자·모션·쌓임 순서 | `space`, `font`, `radius`, `borderWidth`, `shadow`, `motion`, `layer` |
| 의미 기반 색상 | 용도별 색과 상호작용 상태 | `surface`, `text`, `border`, `action`, `status`, `focus`, `overlay` |
| 전용 토큰 | 터미널·차트 렌더링 값 | `terminal`, `chart` |
| 테마 정의 | 계약을 만족하는 값의 묶음 | `pms-retro-light`(기본 테마 저장 ID) |
| 테마 레지스트리 | 제공 테마·기본값·조회 | `src/themes/` |
| 렌더러 어댑터 | 각 렌더링 방식으로 전달 | CSS 변수, xterm.js 옵션, 차트 팔레트 |

필수 계약:

- 의미 기반 색상은 기본·hover·active·selected·disabled·focus 상태를 포함한다.
- 토큰 이름은 색상명이 아니라 역할을 표현한다. 예: `--color-action-primary`, `--color-surface-panel`.
- CSS 변수와 xterm.js 테마는 같은 정의에서 파생한다. 색상 사본을 두지 않는다.
- 터미널 배경·전경·커서·선택 영역·ANSI 16색을 명시하고 실제 TUI 가독성을 확인한다. 차트의 계열·축·격자·툴팁도 토큰이다.
- 기초 토큰은 공통 기본값을 공유하고 테마별 재정의를 허용한다. 레이아웃 최소 크기 같은 동작 제약은 테마와 구분한다.
- 새 테마는 정의 추가와 레지스트리 등록만으로 적용되어야 하고 화면 컴포넌트 수정이 필요 없어야 한다.
- 필수 토큰 누락은 타입 검사로 잡는다. 저장된 테마 ID가 없으면 기본 테마를 쓴다. 테마 변경은 열린 터미널과 분리 창에도 반영한다.
- 마스코트 원본 색을 제외한 UI 색은 테마 파일에 모은다. 서버 TUI가 지정하는 truecolor는 바꾸지 않는다.

### 2.4 마스코트

`lh-dachs-workspace`의 장모 크림 닥스훈트 원본(`lh-dachs/assets/source/dachshund-full.png`, `dachshund-face.png`, 규칙은 같은 폴더의 `README.md`)을 재사용하고 외형과 화풍을 유지한다. 영문 이름은 `Dachs`다.

- 48px 미만은 얼굴, 이상은 전신. 체크무늬가 박힌 reference 이미지가 아니라 투명 source PNG를 쓴다.
- 원본을 프로젝트에 반입해 독립 빌드한다. 다른 워크스페이스 경로에 런타임 의존하지 않는다.
- 크림색은 유지하되 원래 프로젝트의 네이비 브랜드 색을 앱 테마에 강제하지 않는다.
- 아이콘·시작 화면·정보 화면에 두고 터미널 작업 영역을 가리지 않는다.

### 2.5 화면 구성

- 제목 줄: 앱 메뉴와 새 연결·터널·도구·설정 같은 작업 도구를 한 줄에 통합한다(§6.8).
- 왼쪽 통합 사이드바: `연결 | 파일 | Git`. 연결은 로컬 셸과 저장된 연결의 한 트리에 그룹·검색·즐겨찾기·최근 접속을 둔다. 파일은 활성 터미널과 동기화한 원격·로컬 트리다. FTP/FTPS는 중앙 파일 탭을 쓴다.
- 중앙: 칸별 탭 바를 가진 터미널·파일·도구 탭과 분할 화면. 하단: 활성 터미널의 상태바(서버 상태, Git, 입력 범위). 서버 상태를 누르면 상세 모니터링 패널.
- 사이드바 너비·접기·보기, 창 크기, 터미널 배치를 저장한다. 700px 이하에서는 사이드바를 오버레이로 열고 작업을 고르면 닫는다.
- 활성 터미널이 바뀌면 파일·모니터링·Git이 같은 연결을 가리키도록 연결 식별자를 공유한다.

### 2.6 여러 테마 (T)

- 기존 크림색 화면을 `DachsTerm Classic` 기본값으로 보존하고 저장 ID `pms-retro-light`를 유지한다.
- 제공: GitHub White·Dark, Solarized Light·Dark, Dracula, Nord, Catppuccin Mocha, Gruvbox Light·Dark, Retro Light·Dark, Retro Blue Light·Dark, Terminal Green·Amber.
- 공식 팔레트를 참고해 의미 토큰과 ANSI 대비를 조정한다. 공식 포트나 원본 복제라고 표기하지 않는다.
- 설정의 미리보기 카드에서 고르면 UI·열린 xterm·차트에 즉시 반영하고 저장해 새 창·재시작 때 복원한다. 알 수 없는 ID는 기본값, 저장 실패는 화면에 알린다. 레이아웃과 마스코트는 공통이다.

## 3. 기술 구조

Tauri 2, React + TypeScript + Vite, xterm.js, Rust 비동기 백엔드, `russh` + `russh-sftp`, SQLite(세션·그룹·설정·전송 큐·스키마 버전), Windows Credential Manager / macOS Keychain과 선택적 마스터 암호 금고, 타입 기반 테마 토큰.

역할 분리, 식별자, 재접속 규칙은 AGENTS.md의 아키텍처 절을 따른다. 추가 원칙:

- IPC는 명령은 요청/응답, 터미널 출력은 스트리밍 채널, 상태 변화는 명시적 이벤트다. 고속 출력에는 버퍼 상한과 흐름 제어를 두어 UI 멈춤과 메모리 무제한 증가를 막는다.
- 같은 연결의 터미널·SFTP·모니터링은 독립 채널과 취소 범위를 가지며, 물리 연결이 끊기면 종속 채널도 끝난다.

## 4. 단계별 구현

### 4.0 다른 세션에서 요청하는 단위

**사용자는 `Phase 1 구현해`처럼 큰 Phase 번호만 지정해도 된다. 세부 분할·선행 조건 확인·진행 기록·이어하기는 구현 담당 에이전트가 한다.**

- `Phase N 구현해`는 Phase 전체 요청이다. 소번호 하나만 끝내고 완료 처리하거나 다음 작업 승인을 반복 요청하지 않는다. `Phase N.M 구현해`는 그 소번호가 범위이며 필요한 선행 작업은 현황을 확인해 처리한다.
- 새 세션은 이 문서와 [progress.md](progress.md)를 읽고 실제 코드·검증 기록을 대조한 뒤 첫 미완료 작업부터 진행한다. 소번호는 한 세션의 출발 범위일 뿐 고정 단위가 아니다.
- 기능 범위는 각 Phase의 범위 목록이 기준이다. 소번호는 범위를 배분할 뿐 축소하지 않으며, 필수 항목이 남으면 Phase는 완료가 아니다.
- Phase 밖 기능 영역(AT, DX, KV 등)의 ID는 §6에 있고 같은 방식으로 요청한다(`KV 구현해`, `KV.5 구현해`).

소번호 순서:

- 0.1 도구 확인·Tauri 구성 → 0.2 토큰·기본 테마·마스코트·레이아웃·터미널 어댑터 → 0.3 테스트 OpenSSH·인증/호스트키/PTY 실증 → 0.4 SFTP 동시 처리·포워딩·취소 실증·라이브러리 결정(ADR)
- 1.1 인증·호스트키 신뢰·단일 터미널 → 1.2 SQLite 세션 관리·OS 비밀 저장소 → 1.3 다중 탭·재접속·KeepAlive·터미널 편의
- 2.1 SFTP 탐색·서버 동기화·파일 관리 → 2.2 전송·드래그 앤 드롭·진행률·취소 → 2.3 외부 편집기·저장 감지·충돌/복구
- 3.1 분할·탭 이동·배치 저장 → 3.2 독립 창·출력 소유권·창별 테마 → 3.3 Local/Remote 터널 → 3.4 SOCKS5·터널 재연결·JSON 입출력
- 4.1 수집 채널·지표 계산·주기 → 4.2 상태바·상세 패널·차트
- 5.1 Windows 종합 검증·장애/성능/보안/접근성 → 5.2 Mac 실기기 종합 검증·OS 전용 수정(M.*) → 5.3 설치 패키지·문서·릴리스
- 6.1 폴더 전송·큐 → 6.2 스니펫 → 6.3 세션 로그 → 6.4 점프 호스트 → 6.5 고급 세션 관리·이관 → 6.6 기본 명령·조작표 → 6.7 PodTree(KV로 대체)

### Phase 0 — 기반 구성과 기술 실증

- 범위: 앱 구성, 토큰 계약과 기본 테마·xterm 어댑터, 마스코트, 기본 레이아웃, 테스트 OpenSSH, SSH 라이브러리 실증(인증·호스트키·PTY, 출력 중 SFTP 동시 전송·취소, 포워딩·SOCKS5), ADR과 버전 고정, Windows 실행과 Mac 기본 빌드·접속.
- 완료 기준: UI와 터미널이 같은 정의에서 색을 받는다. 테스트용 테마(제품 비노출)가 컴포넌트 수정 없이 적용된다. 핵심 SSH 기능의 성공·실패·미검증이 기록되어 있다. API 문서만으로 실증 완료 처리하지 않는다.

### Phase 1 — 실제 사용 가능한 SSH 클라이언트 / v0.1

- 범위: 세션 관리(그룹·즐겨찾기·검색·최근 접속), 비밀번호·개인키·Passphrase 인증과 OS 보안 저장소(SQLite에는 참조만), `known_hosts`와 호스트키 신뢰, xterm·PTY(UTF-8·한글·TUI), 다중 탭과 재접속, 터미널 편의 기능, KeepAlive·타임아웃·상태 표시, 종료 시 정리.
- 완료 기준: 저장한 실제 서버에서 명령 실행. 동시 5개 연결, 한글 입력(물리 IME 포함), TUI, resize, 개별 탭 종료. 잘못된 인증, 호스트키 변경, 단절, 재접속. 인증정보가 DB·로그·설정에 평문으로 남지 않는다. Windows와 macOS 결과를 분리해 기록한다.

### Phase 2 — SFTP·FTP와 외부 파일 편집 / v0.2

- 범위: SFTP 탐색, 전송·드래그 앤 드롭·진행률·취소, 파일 관리(복사/이동, 다중 선택, 재귀 삭제, 권한, 압축·안전한 압축 해제, 우클릭 메뉴, 키보드), 활성 터미널과 동기화.
- FTP/FTPS: SSH/SFTP와 구분해 지원하고 암호화 여부를 UI에 명시한다.
- 이어받기·이어보내기: 부분 파일 식별, 원본 변경 검증, 오프셋과 내용 일치 확인. 잘못된 대상에 이어쓰지 않는다.
- 외부 편집: 사용자가 고른 편집기, 안전한 로컬 임시 파일, 저장 감지·순차 업로드. 저장 후 업로드 확인이 기본이고 자동 업로드를 고를 수 있다.
- 충돌 원칙: 편집 시작 때 원격 기준을 기록하고 업로드 직전 메타데이터·필요 시 해시로 비교한다. 확인과 쓰기 사이의 경쟁을 완전히 없앨 수 있다고 가정하지 않는다. 가능하면 같은 폴더 임시 파일에 올린 뒤 rename한다. 덮어쓰기·다시 받기·다른 이름 저장 중 고르게 하고, 충돌·실패·단절 시 수정본을 덮어쓰거나 지우지 않는다.
- 완료 기준: 실제 왕복 전송, 편집기 저장 반영, 동시 원격 수정 충돌, 업로드 중 단절·취소, 한글·공백 경로, OS 드롭과 파일 선택 창.

### Phase 3 — 멀티 터미널과 터널링 / v0.3

- 범위: 분할과 패널별 PTY resize, 독립 창(소유권·출력 구독), 창 간 테마·설정 동기화. Local(-L), Remote(-R, 서버 거부 표시), SOCKS5(-D, CONNECT와 도메인 대상) 터널의 저장·상태·포트 충돌·정리, 루프백 기본값, 선택적 자동 재연결. JSON 입출력(스키마 검증, 비밀 제외).
- 멀티 입력: 명시적으로 고른 터미널에만 보낸다. 대상을 표시하고 종료·재접속 때 다시 확인하며 새 연결을 자동으로 넣지 않는다.
- 완료 기준: 분할·창 이동 중 연결 유지, 각 터널의 실제 왕복, 포트 충돌·서버 거부·재접속·종료 후 자원 해제.

### Phase 4 — 서버 리소스 모니터링 / v0.4

- 범위: Linux, 서버 에이전트 없이 SSH 명령으로 CPU(`/proc/stat` 차분)·RAM(`/proc/meminfo` 가용)·NET(`/proc/net/dev` 차분 ÷ 실제 경과 시간)·DISK·Load Average를 수집한다. 기본 5초. 첫 샘플은 측정 중, 실패·오래된 값은 명확히 표시. 독립 채널, 중복 수집 방지, 서버별 분리. 하단 상태바와 상세 패널.
- 완료 기준: 차분·첫 샘플·카운터 리셋·수집 실패 검증. 모니터링 실패가 터미널 입출력을 멈추지 않는다.

### Phase 5 — 안정화와 배포 / v1.0

- 범위: 양 OS 실기기 검증(보안 저장소, 편집기, 한글 입력, 창 분리, 드롭). 대량 출력·대용량 전송·장시간·반복 연결의 자원, 절전·복귀, 네트워크 변경. 보안·토큰·접근성 검토. Windows 설치 패키지와 macOS 앱·DMG 실제 설치, 서명·공증 범위 구분, README.
- 출시 점검은 [Windows 릴리스 점검표](verification/windows-release-checklist.md)와 [macOS 점검표](verification/macos-checklist.md)를 쓴다. WebGL 렌더러는 5.1 대량 출력 측정 결과로 판단한다.
- 완료 기준: 양 OS에서 설치 → 세션 등록 → SSH → SFTP → 외부 편집 → 터널 → 모니터링 → 종료 흐름.

### Phase 6 — SSH 작업 기능 확장

6.6은 6.2 없이도 진행할 수 있고, 6.5의 점프 호스트 이관은 6.4가 선행한다. 범용 스크립트 엔진은 넣지 않는다.

- **6.1 폴더 전송·큐**: SFTP·FTP/FTPS 폴더 재귀 전송, SQLite 영속 큐(순서 변경, 일시정지·취소·재시도, 동시 수 제한, 시간 예약 없음), 탐색 상한. 충돌은 건너뛰기/이름 변경/명시적 덮어쓰기. 링크·junction을 따라가지 않고 경로 이탈·순환을 막는다. 재시작 후 미완료 작업은 확인·재인증 뒤 재개한다. 큐에 비밀을 두지 않고 취소 때 기존 파일을 지우지 않는다.
- **6.2 스니펫**: **입력만 넣기**와 **Enter 포함 실행**을 구분한다. 변수는 명시적 자리표시자만(셸 평가·명령 치환 없음). 고른 대상에 정확히 한 번 보내고 자동 실행하지 않는다. 기본 명령(6.6)과 한 창(**명령**)으로 합쳤다.
- **6.3 세션 로그**: SSH·로컬·WSL 출력을 세션별 UTF-8 텍스트로 저장. 기본 꺼짐, ANSI 제거, 회전·보관 한도. 인증 대화·키·OTP·입력 이벤트는 기록하지 않는다. 원격 프로그램이 출력한 비밀은 판별할 수 없으므로 안내·일시정지·사용자 마스킹만 약속한다. 출력 ACK와 분리된 유한 큐를 쓰고 누락은 알린다.
- **6.4 점프 호스트**: 저장된 프로필로 다단 경유. 순환·없는 참조 검증, 실패한 홉 표시. 홉마다 인증과 호스트키 신뢰를 독립 처리하고 경유지에 키·암호를 복사하지 않는다.
- **6.5 고급 세션 관리·이관**: 계층 그룹·태그·일괄 수정(미리보기·트랜잭션·복구본), 템플릿(비밀 복제 없음), 외부 어댑터의 계층·키 경로·터널·경유 변환. OpenSSH Include는 선택한 루트 안에서 미리보기 후 읽고, Match 같은 미지원 조건은 직접 접속으로 묵시 변환하지 않는다. 자체 JSON은 이전 버전 읽기 호환, 알 수 없는 버전·필드 거부, 참조 ID 재발급, 실패 원자성.
- **6.6 기본 명령·로그 필터·조작표**(사용자 확정): 일상 명령과 필터 예제(파일·설치 경로 찾기, tail/cat 필터, 기본은 `grep -F`)를 **짧은 설명 + 명령 + 복사**로 제공한다. 복사에 줄끝 Enter를 넣지 않고 앱이 입력·실행하지 않으며, AI 명령 생성·자동 완성으로 넓히지 않는다. 프로그램별 조작표(vi/vim, less, tail -f, cat)는 키를 보내거나 가로채지 않는다. 자동 표시는 셸의 명시적 실행 알림으로만 하고(기본 켜짐, 설정에서 끔) 출력·키 입력으로 프로그램을 단정하거나 셸 설정을 바꾸지 않는다.
- **6.7 PodTree 내장**: 쿠버네티스 작업 화면(§6.7)으로 대체해 KV.12에서 제거했다.

완료 기준: 실제 SSH·SFTP·FTP/FTPS·로컬 PTY에서 왕복 일치, 단절·취소·재시작 복구, 입력 격리, 인증 데이터 제외를 검증한다. OS 파일 선택·드롭, 실제 외부 제품 내보내기 파일, Mac 결과는 따로 기록한다.

## 5. 보안 기준

첫 연결부터 적용한다. 보안 점검 항목은 S.n ID로 관리한다.

- 호스트키 검증을 끄지 않는다. 미등록 키는 지문을 보여 최초 신뢰를 확인하고, 변경된 키는 기본 차단한다.
- 비밀번호·Passphrase는 OS 보안 저장소를 우선한다. 저장소를 쓸 수 없으면 평문으로 대체하지 않고 저장하지 않는다. 선택적 마스터 암호 금고는 OS 자격 증명의 안전한 이행, 잠금·자동 잠금, 암호 변경, 재인증 후 제한 시간 보기를 제공한다.
- 개인키 경로와 비밀 내용을 구분하고, 프런트엔드 상태·로그·오류에 비밀이 남지 않게 한다.
- 외부 프로그램은 경로와 인자 배열로 실행하고 사용자 입력을 셸 문자열에 붙이지 않는다. 원격 명령의 경로·인자는 안전하게 인용하고 파일 작업은 가능하면 SFTP API로 한다.
- Tauri 명령·파일 접근·창별 권한을 필요한 범위로 제한한다. 터널은 루프백 기본, 임시 파일은 사용자 전용 권한.
- 서버가 요청 없이 여는 채널(`session`, `direct-tcpip`, `direct-streamlocal`, X11)은 거부한다. X11은 포워딩을 켠 연결에서만 받는다(CG.9).
- 가져온 파일 안의 레지스트리·명령·Include를 실행하지 않는다. 명령 실행이 필요한 설정(ProxyCommand)은 사용자 승인을 거친다.

### S.1 — RSA·인증·터미널 기본 기능

- 취약한 RSA 의존성을 제거하고 RSA 키 인증과 RSA 호스트키 검증을 SHA-2로 유지한다(`vendor/ssh-key` 패치본). 무시 목록이나 인증 차단으로 해결하지 않는다.
- 일반·암호화 개인키, OS SSH agent, keyboard-interactive, 키 인증 뒤 MFA. 추가 인증 응답은 저장하지 않는다.
- 파일 패널의 터미널 경로 따라가기(OSC 7/1337, Bash/Zsh 세션 한정 알림). 기본 켜짐, 설정·연결별로 끈다. 서버 설정 파일은 바꾸지 않는다.
- 드래그 선택 자동 복사, 우클릭 붙여넣기, 표준 단축키, TUI 마우스 격리, 여러 줄·제어문자 붙여넣기 확인, 방향키·Home/End·Tab·Ctrl+C 유지, VERASE/IUTF8·Backspace 호환 선택.

### W — Windows 우선 안정화

Windows에서 가능한 보완을 먼저 하는 작업 순서이며 Mac 출시나 Phase 5 조건을 줄이지 않는다.

- W.1 삭제 원자성·마이그레이션 실패 보호·중복 실행 방지·복구본, W.2 민감 원문 없는 진단 내보내기, W.3 반복 가능한 검사·패키징·고지 산출, W.4 실제 앱 회귀·자원 검사.
- 물리 IME, OS 제스처, 절전·네트워크 전환, 장시간 실사용, 공개 배포 서명은 실제 결과 없이 완료로 처리하지 않는다.

## 6. 기능 영역

Phase 밖에서 사용자 요청으로 추가한 영역이다. ID별 상태는 progress를 따른다.

### 6.1 미니게임 (G)

- 앱 안에서 짧게 즐기는 게임. `src/features/games/`의 lazy 로드 영역이며 다른 기능의 완료 상태와 무관하다.
- 공통 계약: 사이드바 `게임` 목록에서 중앙 탭으로 연다. 게임마다 탭 하나, 탭을 닫아야 판이 끝난다. 탭 전환·포커스 이탈 때 자동 정지하고 명시적으로 재개한다. 터미널 입력은 격리한다. 테마 토큰·마스코트 사용, 오프라인, 새 IPC·네트워크·패키지 없음.
- 게임: 블록 퍼즐, 스네이크, 2048, 지뢰찾기(G.1·G.2), 간식 타임(G.3·G.5), 모험(G.4·G.6·G.7: 시드 기반 랜덤 구간, 환경 4종, 물기·밟기, 보스전), 서바이버(G.8.0~G.8.6, G.8.Q1).
- 서바이버(사용자 확정): HP·경험치·골드, 레벨업 때 카드 3장 중 1장, 성장을 유지하며 스테이지 연속 진행(각 60초, 3의 배수에 보스), 마지막 스테이지 없이 사망·포기·마무리 때 정산, 골드로 영구 강화·해금, 3스테이지 단위 지역 4종. 재시작 시 판 복원은 하지 않는다. 수치는 실플레이 미검증 초기값이다.

### 6.2 로컬 터미널과 UI 정돈 (U, F)

- U.1: Windows PowerShell·명령 프롬프트·PowerShell 7·WSL 배포판과 macOS 로그인 셸을 찾아 클릭으로 PTY 탭을 연다. 자동 실행·설치 없음. 로컬에 SSH 인증·원격 모니터를 적용하지 않는다.
- F.1: SSH 연결 시 파일 패널 자동 표시와 경로 알림 자동 연결(끌 수 있음), 로컬 탭의 로컬 파일 트리.
- U.2: 연결과 파일을 왼쪽 한 패널로 통합(§2.5). 보기 전환으로 경로·선택·진행 중 작업을 초기화하지 않는다. F11 전체화면, `Ctrl/Cmd+Shift+Enter` 칸 확대.
- U.3: 대화상자 액션은 같은 높이·정렬 규칙, 강조는 역할로. 터널은 목록과 편집을 분리하고 접속 주체·경유·목적지를 명시하며, 저장과 실행을 구분한다.

### 6.3 세션 교환과 외부 가져오기 (I)

- I.1: 자체 JSON 규약을 format/version과 JSON Schema로 고정한다. 정본은 [세션 교환 규약](session-transfer.md)과 `session-format*.schema.json`. 비밀번호·개인키 내용·Passphrase·비밀 참조·호스트 신뢰는 담지 않는다.
- 외부 형식(PuTTY `.reg`, `.mxtsessions`/`.ini`, OpenSSH `config`)은 프로그램별 어댑터로 변환하고 지원·제외 필드를 명시한다. 인코딩·BOM, 미리보기·선택·누락 경고, 새 ID, 자동 터널 해제, 롤백과 변경 전 복구본.
- 첫 접속 인증창에서 암호 저장을 고르고, 로그인 성공 때만 저장한다. OTP는 저장하지 않는다.
- I.2: 이 PC의 PuTTY 레지스트리, 세션 북마크 파일, `~/.ssh/config`를 읽기 전용으로 찾아 빈 연결 목록과 가져오기에서 제안한다. 같은 미리보기를 거쳐 원래 프로그램과 연결하지 않고 등록하며, 기본으로 출처 이름의 새 최상위 그룹에 넣는다. 이미 저장된 대상은 처음 선택에서 뺀다.

### 6.4 제품명과 내부 식별자 (N)

- DachsTerm, 내부 이름 `dachsterm`, 앱·저장소 ID `app.dachsterm.desktop`, 테스트 환경 변수 `DACHSTERM_*`. 저장 규약·임시 파일·셸 알림도 같은 이름을 쓴다. 이전 이름의 데이터 이전과 호환은 제공하지 않는다.

### 6.5 에이전트 터미널 (AT)

- CLI 코딩 에이전트에 필요한 터미널 기능을 전용 모드 없이 터미널 표준 신호로 제공한다.
- 범위: 실측 게이트(AT.0), Shift+Enter·macOS Option(AT.1), OSC 7501 상태(AT.2), 완료·입력 대기 알림(AT.3), OSC 52·URL 열기(AT.4), 이미지 붙여넣기·파일 드롭 업로드(AT.5), 서버 포트 임시 터널(AT.6), 문서·회귀·Mac(AT.7).
- 제외: 화면 글자 해석, 서버 설정·훅 자동 변경, 앱의 직접 모델 호출(§6.11), 로컬 모델 내장, 내장 브라우저, 외부 제어 API.

### 6.6 개발자 작업 흐름 (DX)

- 서버에서 CLI 에이전트와 Git으로 일하는 개발자용 흐름: 끊겨도 유지되는 작업, 내 PC의 키로 push, 입력 대기 에이전트 찾기, 앱 안 diff 검토.
- 범위: 실측(DX.0), 공용 원격 실행(DX.1), agent forwarding과 서명 승인(DX.2), tmux 연결과 훅 상태(DX.3·DX.4), Git 상태(DX.5), 읽기 전용 diff 검토(DX.6), 에이전트 시작(DX.7), 현황판(DX.8), 명령 경계 OSC 133(DX.9), 문서·회귀·Mac(DX.10), 앱 내장 agent와 키 선택(DX.11), HTTPS Git 자격 증명 전달(DX.12), 로컬·WSL 탭의 SSH 키(DX.13), WSL 탭의 HTTPS 자격 증명(DX.14), 로컬·WSL 탭의 Git 상태(DX.15), `claude`·`codex` 시작 옵션(DX.16).
- 사용자 결정: 호스팅 종류와 무관하게 SSH·로컬·WSL 탭에서 SSH·HTTPS 저장소로 push가 되게 한다. 브랜치와 변경 수는 상태바에 둔다. Git 조회는 사건이 있을 때만 하고 폴링하지 않는다. Git 쓰기는 GE.9로 옮겼다.
- 제외: Mosh, 훅·tmux 설정 자동 적용(안내서의 복사 예시만), 자격 증명 `store`·`erase` 전달, Windows·Mac 로컬 탭의 HTTPS 자격 증명(OS의 Git 자격 증명 관리자 몫).

### 6.7 쿠버네티스 작업 화면 (KV)

- 쿠버네티스 세션에 접속하면 파드 트리가 먼저 열리고, `kubectl` 반복 입력 없이 자원·에러·재시작·워커·인그레스·로그를 보고 파드에 들어간다. kubeconfig를 PC로 가져오지 않고 SSH만으로 쓰며 서버·클러스터에 아무것도 설치하지 않는다. 판단 기준: "화면에서 눌러 `kubectl`을 대신하는 일상 작업인가?"
- 범위: 실측(KV.0), kubectl 탐지·세션 연결(KV.1), 트리(KV.2), 대시보드(KV.3), 상세·로그·파드 셸(KV.4), 키워드 로그 검색(KV.5), 간단 제어(삭제·rollout restart·cordon, KV.6), 문제 목록·변화 기록(KV.7), 인그레스(KV.8), 워커·반환 안 됨 판정(KV.9), vLLM·GPU(KV.10), 로컬 kubeconfig(KV.11), PodTree 제거·문서(KV.12), 여러 파드 실시간 로그 보드(KV.13).
- 사용자 결정: 세션 폼의 **접속 후 화면**에서 종류만 고르고 탐지·context 선택은 첫 접속 때 탭 안에서 한다. 조건은 접속 계정으로 `kubectl`이 실행되는 것 하나이며 앱은 `sudo`를 실행하거나 root 암호를 받지 않는다. 기본 묶기는 `namespace > 워크로드 > 파드`. 키보드와 마우스가 같은 선택을 쓰고 행 버튼 대신 우클릭 메뉴. 인그레스·워커는 필수 범위. kubeconfig·토큰을 앱에 복사하지 않고 current-context를 바꾸지 않는다.
- 제외: 장기 기록, 앱 밖 감시, 여러 클러스터 통합 대시보드, YAML 적용, Helm, RBAC 관리, CRD 탐색, 임의 쓰기 UI, 인그레스 설정 변경.

### 6.8 터미널 작업 공간 (TW)

- 평소에는 탭 바, 터미널, 상태바만 보인다. 기능을 버튼으로 나열하지 않고 터미널 조작은 탭 헤더 우클릭에 모은다.
- 범위: 레이아웃 모델(TW.1), 칸별 탭 바·분할·저장(TW.2), 탭 드래그 배치(TW.3), 우클릭 메뉴·상태바(TW.4), 입력 범위(TW.5), 조작표 자동 표시(TW.6), 설정·단축키(TW.7), 제목 줄 통합(TW.8), 사이드바 한 트리·명령 창 통합(TW.9), 대화상자 공통 규격(TW.10).
- 사용자 결정: VS Code처럼 칸마다 탭 바. 터미널 안 우클릭은 바로 붙여넣기. 동시 입력 대상은 보이는 칸뿐. 단축키는 터미널 검색 `Ctrl/Cmd+Shift+F`, 세션 검색 `Ctrl/Cmd+Shift+O`. Windows 창 버튼은 외부 플러그인 없이 직접 그리고 호버 스냅 레이아웃 제약을 받아들인다.
- 제외: 여러 세션을 담는 독립 창. tmux 안 프로그램 감지는 후속 후보.

### 6.9 Git·파일 편집 작업 화면 (GE)

- Git과 파일 편집을 앱 안에서 끝낸다. SSH·로컬·WSL 탭에서 같은 화면과 동작.
- 범위: 외부 편집 저장 확인 카드(GE.1), 로컬 패널 끌어 놓기·WSL 다운로드(GE.2), 탐색기로 끌어내기(GE.3), 편집기 부품 시험(GE.4), 파일 탭(GE.5), 내장 편집(GE.6), 사이드바 Git 보기(GE.7), diff 탭(GE.8), Git 쓰기(GE.9), 설정 → Git(GE.10), 터미널 안 브랜치(GE.11), 상태바(GE.12), 문서·회귀·Mac(GE.13), 읽기 전용 커밋 그래프(GE.14), Git 보기 마감(GE.15).
- 사용자 결정: 파일 한 번 클릭은 미리보기 탭, 더블클릭·편집 시작은 고정 탭. 편집기 부품은 용량이 아니라 한글 입력 실측으로 정한다. Markdown은 미리보기가 기본. fetch·pull·push는 그 탭의 터미널에서 실행해 인증 질문이 보이게 한다. 터미널 안 브랜치는 SSH Bash·Zsh만.
- 제외: 머지 충돌 편집기, 대화형 rebase, 서브모듈 관리, 설치형 편집기를 탭에 넣기, 커밋 그래프의 쓰기 동작.

### 6.10 도구 메뉴와 네트워크 도구 (TL)

- 도구 메뉴를 세션 없이 쓰는 단독 도구의 입구로 만든다. "A에서 B까지 통신이 되는가, 어디까지 갔는가"를 앱 안에서 확인한다.
- 범위: 실측(TL.0), 터널(TL.1), 도구 탭 틀(TL.2), SSH 키 만들기(TL.3), 문서 편집기(TL.4), 셸 없는 SSH 연결과 출발지 선택(TL.5), 포트 개통(TL.6), 포트 사용 여부(TL.7), 서비스 연결(TL.8), 경로 추적(TL.9), 문서·회귀·Mac(TL.10).
- 사용자 결정: 출발지는 `로컬(기본) | 리모트`, 리모트는 등록된 세션으로 연결한다. 사용자는 출발지와 최종 목적지만 넣고 중간 장비는 경로 추적으로 찾는다. 서버에 설치하지 않는다.
- 제외: 호스트 키 관리, 전송 현황, 구간 표, UDP 개통 확인, ping 탐색, TCP 연결 외 스캔 기법, 결과 장기 보관, WSL 출발지.

### 6.11 에이전트 채팅 (AC)

- 저장된 SSH 세션을 채팅으로 연다. 서버에 설치·로그인된 `claude`·`codex`를 구조화 출력 모드로 실행하고 대화·도구·서브에이전트·diff·승인을 GUI로 보여 준다. [설계안](design/agent-chat.md), [검증 기록](verification/agent-chat.md).
- 범위: 실측(AC.0), 분리 실행기(AC.1), 어댑터(AC.2·AC.3), 채팅 탭(AC.4), 승인·권한·중단(AC.5), 전역 설정과 열기 방식(AC.6), 실행 그래프·현황판(AC.7), 터미널 탭의 서브에이전트 표시(AC.8), 재접속(AC.9), 문서·회귀·Mac(AC.10), 키 서명·Git 자격 증명 전달(AC.11).
- 사용자 결정: AT·DX의 "앱 안 AI 호출 제외"를 "앱이 직접 모델을 호출하지 않는다"로 좁힌다. 앱은 사용자의 CLI를 실행할 뿐이며 로그인 정보를 읽거나 저장·중계하지 않는다. 공개 배포 전에 CLI 구동 방식의 약관 허용 여부를 확인한다.
- 제외: IDE 확장 호환, API 키 입력, 서버 상주 서비스.

### 6.12 상용 제품 대비 보완 (CG)

새 영역을 늘리지 않고 사용자가 바로 막히는 접속·인증 기능과 출시에 필요한 업데이트를 채운다.

- CG.0 실측과 검사 환경(`npm run connect:fixture`: HTTP·SOCKS5 프록시, 경유지, Telnet, 가상 시리얼, Xvfb).
- CG.1 프록시: 세션별 HTTP CONNECT·SOCKS5(사용자 인증 포함). 점프 호스트와 함께 쓰고 SFTP·터널·모니터링도 같은 경로. 프록시 암호는 OS 저장소나 금고에 둔다. 세션 교환 v4를 여기서 만들고 이후 ID는 v4에 필드를 더한다.
- CG.2 ProxyCommand: 외부 명령의 표준 입출력으로 접속한다. 가져오기에서 자동 허용하지 않고 사용자 승인을 거친다. Finder 실행 앱의 `PATH`를 패키지 앱으로 확인한다.
- CG.3 인증: Windows Pageant, OpenSSH 인증서(`CertificateFile`) 지정과 가져오기.
- CG.4 Telnet 탭: 평문 전송 경고. 암호 저장·자동 로그인은 만들지 않는다.
- CG.5 시리얼 탭: 포트 목록(Windows `COM*`, macOS `/dev/cu.*`), 속도·데이터 비트·패리티·정지 비트·흐름 제어, Break, 장치 분리 처리.
- CG.6 자동 업데이트: 확인·내려받기·설치와 끄기. 이 저장소의 Releases(`latest.json` 고정 URL)로 배포한다. 서명 개인키는 저장소·문서에 넣지 않는다. OS 코드 서명은 비용이 드는 사용자 결정이다. 운영은 [앱 업데이트](verification/app-updates.md).
- CG.7 키워드 하이라이트·트리거: 정규식 규칙의 색(테마 토큰만)과 알림. 자동 입력은 명시적으로 켠 규칙만, 암호 자동 입력은 없음. 대량 출력 성능을 잰다.
- CG.8 ZMODEM(`rz`/`sz`)·trzsz 감지 전송. 점프 호스트 너머 서버가 주 대상.
- CG.9 X11 포워딩: 사용자가 띄운 외부 X 서버로 중계만 한다.
- CG.10 문서·회귀·Mac.
- 순서(사용자 확정): CG.0·CG.6 다음 연결 트랙(CG.1 → CG.3 → CG.2 → CG.9)과 터미널 트랙(CG.7 → CG.4 → CG.5 → CG.8)을 병렬로, 마지막에 CG.10. 트랙 안에서는 앞 ID가 `dev`에 병합된 뒤 다음을 시작한다.
- 제외: Mosh, GSSAPI/Kerberos, 터미널 이미지 표시(Sixel 등).

### 6.13 UI 배치·타이포그래피 일관성 (UI.1)

- 글자 역할·버튼·입력 높이·본문 시작선·빈 상태 배치를 [UI 일관성 기준](design/ui-consistency.md)으로 정리한다. 위계 역전, 임의의 중앙 폼, 작은 보조 글자를 없앤다. 시작 화면 제목·게임·코드·터미널은 별도 용도다.
- 설정 9분류와 팝업의 정상·오류·긴 경로·좁은 창을 전수 점검한다(터미널 작업 화면 제외). 정적 토큰 검사, 렌더링 치수·스크린샷, Windows/macOS 실제 앱·배율 검사를 구분하고 자동 테스트만으로 시각 품질을 완료 처리하지 않는다.

### 6.14 그림·문서 미리보기와 기본 프로그램으로 열기 (FV)

- 파일 탭에서 그림·PDF·오피스·한글 문서를 읽기 전용으로 보여 주고, 어떤 파일이든 연결 프로그램으로 넘긴다.
- 범위: 종류 판정·BMP/ICO·그림 확대(FV.1), 기본 프로그램으로 열기(SFTP는 받아서 열고 저장 감지·업로드, FV.2), PDF(FV.3), Word·Excel·PowerPoint(FV.4), hwp·hwpx(FV.5), 문서·검사·Mac(FV.6).
- 충실도: PDF·한글·Word는 쪽 모양, Excel은 저장된 값의 표, PowerPoint는 슬라이드별 개요. 원래 모양은 기본 프로그램으로 본다.
- 보안: 매크로·스크립트·폼 코드를 실행하지 않고, 바깥 자원을 불러오지 않으며, 링크로 창을 떠나지 않는다. ZIP은 풀기 전 선언 크기를 검사한다. 내용 정책에 `script-src 'wasm-unsafe-eval'`와 `connect-src 'self'`를 더한다. 실행될 수 있는 종류는 웹뷰 밖 확인 창을 거친다. 서버에서 받은 복사본에는 다운로드 표시(`Zone.Identifier`, quarantine)를 붙인다.
- 제외: 편집, 글자 선택·찾기, doc·xls·ppt 이진 형식, 암호 문서, FTP 파일 열기, PowerPoint 배치 재현.

### 6.15 후순위 후보

- 가상 데스크톱 화면: 앱이 그린 바탕화면에 파일·터미널·모니터링·로그를 창으로 띄우는 화면. 설계와 ID가 없고, 실제 Linux GUI 표시는 §1의 제외를 유지한다.

## 7. 검증과 완료 판단

[engineering-rules](engineering-rules.md) §2·§9와 AGENTS.md의 검증 규칙에 더해 아래를 따른다.

- SSH·SFTP·FTP·터널은 실제 서버와 통합 검증한다. 자동 테스트는 인증·호스트키·흐름 제어·충돌·취소·샘플 계산·토큰 계약처럼 실패 영향이 큰 동작에 집중한다.
- 접근성, 실제 TUI, 편집기, OS 보안 저장소, IME, 설치 패키지는 실환경 검증을 포함한다.
- 상태는 `미착수`, `진행 중`, `검증 대기`, `완료`, `차단`이다. 구현이 끝나도 실제 검증이 남으면 `검증 대기`다. Phase 상태는 소속 작업과 Phase 완료 기준으로 판단한다.
- 미검증 기능에 의존하는 작업은 위험과 선행 조건을 적는다. `완료` 보고에는 충족한 기준과 근거를, 완료가 아니면 남은 ID를 적는다.
