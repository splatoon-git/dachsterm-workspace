# DachsTerm 구현 로드맵

- 작성일: 2026-11-04
- 제품명: DachsTerm (2026-11-06 확정; 내부 식별자는 `dachsterm`)
- 대상: Windows 11 / macOS 로컬 데스크톱 SSH 서버 관리 클라이언트
- 진행 상태 정본: [progress.md](progress.md). 이 로드맵은 범위·순서·완료 기준을 관리한다.
- 진행 방식: 단계별로 실행 가능한 결과물을 만들고, 검증 결과를 기록한 뒤 다음 단계로 진행한다.

## 1. 목표와 범위

MobaXterm의 SSH 작업 흐름을 참고해 SSH, SFTP, 외부 파일 편집, 멀티 터미널, 터널링, 서버 상태 모니터링을 제공한다. 별도 백엔드 서버나 서버 에이전트를 설치하지 않는 무료 개인용 앱으로 개발한다.

**Windows와 macOS는 모두 출시 대상이다**(2026-11-06 사용자 재확인). macOS는 Apple Silicon만 지원하고, 지금은 개인 사용이며 Apple Developer 등록 후 서명·공증을 구성한다. Windows에서 대부분의 개발·실행·테스트를 수행한다. macOS 네이티브 빌드와 OS 전용 동작은 MacBook에서 별도로 검증한다. Mac 검증을 최종 배포 시점에만 몰아두지 않고 초기 SSH 연결과 OS 연동 단계에도 실시한다. 현재 상태와 남은 작업은 [macOS 준비 상태](verification/macos-readiness.md)를 따른다.

초기 범위에서 MobaXterm 전체 기능 복제, X 서버, RDP/VNC, 클라우드 동기화, 팀 계정, 유료 외부 서비스 의존은 제외한다.

## 2. 확정된 디자인 요구사항

### 2.1 참조 범위 — 컬러셋만

**`workspace-pms`에서는 라이트 레트로 컬러셋만 참고한다. 디자인 콘셉트, 화면 배치, 컴포넌트 스타일을 가져오지 않는다.**

- SSH 작업에 맞는 현대적이고 간결한 데스크톱 UI를 독립적으로 설계한다.
- 레트로풍 장식, 종이 질감, 픽셀 폰트, 옛 OS 스타일, 과장된 입체 테두리를 디자인 요구사항으로 삼지 않는다.
- 색상 참고 원본: `D:/Work/workspace-pms/pms_front/src/plugins/vuetify/theme.js`의 `retroColors`.
- 참고 프로젝트의 Vue/Vuetify 구현과 업무용 화면 구조는 이식하지 않는다.
- **초기 Phase 0에서는 라이트 테마 1개**로 시작했다. 2026-11-04 사용자 추가 요청으로 기존 크림색을 기본으로 유지하며 여러 테마를 제공한다(§2.6).
- 다크 테마를 포함한 모든 테마는 공통 토큰 계약과 테마 등록 구조를 사용한다.

### 2.3 공통 테마 토큰 구조

컴포넌트에서 테마 ID를 조건 분기하거나 색상을 직접 지정하지 않는다. 앱 UI, 터미널, 차트, 팝업, 분리된 창까지 동일한 테마 계약을 사용한다.

| 계층 | 역할 | 예시 |
|---|---|---|
| 공통 토큰 계약 | 모든 테마가 제공해야 하는 키와 타입 | `ThemeDefinition` |
| 기초 토큰 | 간격·타이포그래피·모서리·테두리·그림자·모션 | `space`, `font`, `radius`, `borderWidth`, `shadow`, `motion` |
| 의미 기반 색상 | 용도별 색상 및 상호작용 상태 | `surface`, `text`, `border`, `action`, `status`, `focus`, `overlay` |
| 전용 토큰 | 터미널·차트의 렌더링 값 | `terminal`, `chart` |
| 테마 정의 | 계약을 만족하는 실제 값의 묶음 | `pms-retro-light`(내부 식별자) |
| 테마 레지스트리 | 제공 테마·기본값·조회 | 초기에는 1개만 등록 |
| 렌더러 어댑터 | 테마 값을 각 렌더링 방식으로 전달 | CSS 변수, xterm.js 옵션, 차트 팔레트 |

필수 계약:

- 의미 기반 색상은 기본·hover·active·selected·disabled·focus 상태를 포함한다.
- 토큰 이름은 색상명보다 역할을 표현한다. 예: `--color-action-primary`, `--color-surface-panel`.
- CSS 변수와 xterm.js 테마는 같은 테마 정의에서 파생시킨다. 별도의 색상 사본을 유지하지 않는다.
- 터미널 배경·전경·커서·선택 영역·ANSI 16색을 명시한다. 기본 라이트 테마에 맞게 실제 TUI 가독성을 확인한다.
- 모니터링 차트의 계열·축·격자·툴팁도 토큰으로 관리한다.
- 기초 토큰은 공통 기본값을 공유할 수 있으며, 테마별 재정의를 허용한다. 기능 레이아웃의 최소 크기 등 동작 제약은 테마와 구분한다.
- 새 테마는 정의 파일 추가와 레지스트리 등록으로 적용 가능해야 한다. 화면 컴포넌트 수정은 필요 없어야 한다.
- 필수 토큰 누락은 타입 검사로 검출한다. 저장된 테마 ID를 찾지 못하면 기본 테마를 적용한다.
- 테마 적용 시 열린 터미널과 분리 창에도 반영한다. 여러 테마를 제공하는 현재 버전에서는 설정에 선택 UI를 제공한다.
- 고정된 마스코트 원본 색상을 제외하고, 앱이 정의하는 UI 색상은 테마 파일에 모은다. 서버 TUI가 직접 지정하는 truecolor까지 강제로 변경하지 않는다.

### 2.5 화면 구성

- 왼쪽: 통합 사이드바의 연결 / 원격 파일 전환. 연결에 로컬 셸·세션 그룹·검색·즐겨찾기·최근 접속을 모은다(2026-11-05 U.2 요청).
- 중앙: 터미널 탭과 분할 화면.
- 원격 파일: 활성 SSH 터미널과 동기화한 SFTP 탐색기를 왼쪽 통합 사이드바에 표시. 별도 오른쪽 패널은 제거한다. FTP/FTPS 파일 전용 중앙 탭은 유지한다.
- 하단: 활성 터미널의 서버 상태바. 클릭 시 상세 모니터링 패널.
- 상단: 새 연결·터널링·설정 등 작업 도구.
- 통합 사이드바 너비 조절·접기·보기 저장. 좁은 창에서는 왼쪽 오버레이로 열고 작업 선택 시 닫는다. 창 크기·터미널 배치 저장.
- 활성 터미널 변경 시 SFTP·모니터링이 동일 서버를 가리키도록 연결 식별자를 공유한다.

## 3. 기술 구조

| 영역 | 선택 또는 검토 대상 |
|---|---|
| Desktop | Tauri 2 |
| Frontend | React + TypeScript + Vite |
| Terminal | xterm.js + FitAddon, 검색 기능 |
| Backend | Rust, 비동기 작업 처리 |
| SSH/SFTP | `russh` + `russh-sftp` 우선 실증, `ssh2` 비교 |
| 저장 | SQLite: 세션·그룹·설정·스키마 버전 |
| 인증정보 | Windows 보안 저장소 / macOS Keychain |
| UI 상태 | Zustand 등 경량 상태 관리 |
| 테마 | 타입 기반 토큰 계약 + CSS 변수 + 전용 렌더러 어댑터 |

### 역할 분리

- React: 화면·입력·탭·패널·터미널 렌더링.
- Rust: SSH 연결·채널·전송·터널·모니터링·파일 접근·인증정보·DB.
- IPC: 연결·작업 명령은 요청/응답, 터미널 출력은 스트리밍 채널, 상태 변화는 명시적인 이벤트.
- 고속 출력의 버퍼 상한과 흐름 제어를 설계해 UI 멈춤과 메모리 무제한 증가를 방지한다.
- 저장된 연결 프로필, 실행 중 SSH 연결, PTY, 탭/패널, SFTP 작업, 터널을 서로 다른 식별자로 관리한다.
- Rust가 실행 중 연결을 소유한다. 창이나 탭의 이동이 연결 종료로 이어지지 않게 한다.
- 동일 연결의 터미널·SFTP·모니터링은 독립 채널과 취소 범위를 가진다. 물리적 SSH 연결이 끊기면 종속 채널도 종료됨을 상태 모델에 반영한다.
- 재접속은 새 셸 생성이다. 이전 명령을 자동 재실행하거나 원격 프로세스 복구를 보장하지 않는다.

## 4. 단계별 구현

### 4.0 다른 세션에서 요청하는 단위

**사용자는 `Phase 1 구현해`처럼 큰 Phase 번호만 지정해도 된다. 세부 작업 분할·선행 조건 확인·진행 기록·이어하기는 구현 담당 에이전트가 수행한다.**

- 기존 Phase 번호 0~5는 유지하고, 2026-11-05 요청한 SSH 작업 기능 확장은 Phase 6으로 추가한다. 아래 소번호는 구현·검증·인계를 위한 작업 단위다.
- `Phase N 구현해`는 해당 Phase 전체 구현 요청이다. 아래 작업 하나만 끝내고 임의로 완료 처리하거나 다음 작업 승인을 반복 요청하지 않는다.
- `Phase N.M 구현해`라고 지정하면 해당 소번호가 요청 범위다. 필요한 선행 작업은 현황을 확인한 뒤 처리한다.
- 새 세션에서는 이 문서와 [progress.md](progress.md)를 읽고 실제 파일·검증 기록을 대조한 다음, 요청한 Phase의 첫 미완료 작업부터 진행한다.
- 소번호는 한 세션에서 다루기 적절한 출발 범위다. 환경·문제 난도에 따라 여러 개를 완료하거나 같은 소번호를 다음 세션에서 이어갈 수 있으므로, 고정된 세션 수를 보장하지 않는다.
- 세션을 이어야 한다면 완료한 작업, 진행 중인 작업의 정확한 위치, 검증 결과, 다음 시작점을 `progress.md`에 기록한다. 사용자가 이전 대화를 다시 설명할 필요가 없게 한다.

## 5. 보안 기준 — 첫 연결부터 적용

### S.1 — RSA·인증·터미널 기본 기능 보완 (2026-11-05 사용자 요청)

- 취약한 RSA 의존성을 제거하고 RSA 개인키 인증·RSA 서버 호스트키 검증을 SHA-2로 유지한다. 무시 목록이나 인증 차단만으로 해결하지 않는다.
- 일반/암호화 개인키, OS SSH agent, keyboard-interactive 및 키 인증 후 MFA를 제공한다. 추가 인증 응답은 저장하지 않고 취소·시간 제한·호스트키 검증을 유지한다.
- SFTP 터미널 경로 따라가기 기본 켜짐/설정 및 연결별 켜기·끄기, OSC 7/1337과 Bash/Zsh 세션용 경로 알림. 서버 설정 파일은 자동 변경하지 않는다.
- 드래그 선택 자동 복사·우클릭 붙여넣기 및 설정, 표준 단축키, TUI 마우스 격리, 여러 줄/제어문자 확인. xterm 방향키·Home/End·Delete·Tab·Ctrl+C를 유지하고 PTY VERASE/IUTF8·Backspace 호환 선택을 제공한다.
- 실제 OpenSSH/Windows 앱에서 검증한다. 지원하지 않는 보안 방식과 서버 호환성·Mac 미검증은 별도로 기록한다.

### 2026-11-05 Windows 우선 안정화 추가 범위

사용자 요청에 따라 Mac 실기기 작업은 후순위로 두고 Windows에서 가능한 품질 보완을 진행한다. 기존 Phase 5 완료 조건을 축소하지 않는다. 이는 작업 순서이며 Mac을 출시 대상에서 뺀다는 뜻이 아니다.

- W.1: 세션/인증정보 삭제 원자성, DB 초기화·마이그레이션 실패 보호, 중복 앱의 저장소 경합 방지, 비밀정보 제외 설정 복구본과 가져오기 안전성.
- W.2: 민감한 원문을 수집하지 않는 진단 내보내기와 복구 UI.
- W.3: 반복 가능한 Windows 검사·패키징/서명 확인·보안/의존성 고지 산출, 업그레이드 및 복구 절차.
- W.4: 실제 엔진/Windows 앱 회귀·반복 연결 및 자원 검사. 물리 IME, 실제 OS 제스처/GUI 편집기, 절전·네트워크 전환, 장시간 실사용은 별도 합격 기준으로 관리.
- 공개 배포 서명/업데이트 서비스 운영 및 실제 장시간·수동 결과가 없는 항목은 완료로 처리하지 않는다. MFA/agent/점프 호스트/폴더 전송은 업무 호환성 확장 후보로 별도 관리하며 본 안정화 작업의 완료와 혼동하지 않는다.

- 호스트키 검증을 임의로 비활성화하지 않는다.
- 미등록 키는 지문을 표시하고 최초 신뢰를 확인한다. 변경된 키는 기본 차단한다.
- 비밀번호·Passphrase는 OS 보안 저장소를 우선 사용한다. 저장소를 사용할 수 없으면 평문 저장으로 대체하지 않고 저장하지 않는 방식을 제공한다.
- 개인키 경로와 비밀 내용을 구분하고, 프런트엔드 상태·로그·오류에 비밀정보가 남지 않게 한다.
- 편집기는 프로그램 경로와 인자 배열로 실행한다. 사용자 입력을 셸 명령 문자열에 직접 연결하지 않는다.
- 원격 명령의 경로·인자를 안전하게 처리한다. 파일 작업은 가능하면 SFTP API로 수행한다.
- Tauri 명령·파일 접근·창별 권한을 필요한 범위로 제한한다.
- 터널은 루프백 기본값, 임시 파일은 사용자 전용 접근 권한을 사용한다.

## 7. 검증과 완료 보고 규칙

- 단계마다 프런트엔드 타입 검사·린트·빌드와 Rust 포맷·정적 검사·빌드, 해당 기능 테스트를 수행한다.
- SSH·SFTP·터널은 실제 OpenSSH 대상과 통합 검증한다. Mock 성공으로 실접속 완료를 대신하지 않는다.
- 자동 테스트는 인증·호스트키·출력 흐름 제어·충돌·취소·샘플 계산·토큰 계약처럼 실패 영향이 있는 동작에 집중한다.
- 접근성·실제 TUI·편집기·OS 보안 저장소·설치 패키지는 실환경 검증을 포함한다.
- 실행하지 못한 항목은 성공으로 표현하지 않고 이유와 필요한 환경을 기록한다.
- 각 단계 보고에는 변경 내용, 실행 명령·결과, 남은 제한, 다음 작업을 포함한다.

### 7.1 진행 기록과 다음 세션 인계

- 루트 `AGENTS.md`를 새 세션의 진입점으로 사용한다.
- `docs/progress.md`에서 작업 ID별 상태와 현재 인계 정보를 관리한다. 실제 검증의 상세 기록은 `docs/verification/`에 두고 링크한다.
- 작업 상태는 `미착수`, `진행 중`, `검증 대기`, `완료`, `차단`으로 구분한다. Phase 상태는 소속 작업과 Phase 완료 기준으로 판단한다.
- 착수 시 요청 Phase·진행 중 ID를 기록한다. 의미 있는 구현·검증 완료 후, 그리고 세션 종료 전 상태를 갱신한다.

- 요청 Phase의 선행 구현이 없으면 필요한 선행 작업부터 수행하고 그 이유·범위를 알린다. 요청하지 않은 후속 Phase로 임의 확장하지 않는다.
- 작업 ID 하나가 끝났다는 이유만으로 세션을 종료하지 않는다. 요청 범위의 남은 작업을 계속 진행하며, 사용자의 중단 요청·실제 외부 제약 등으로 이어가야 할 때 인계 기록을 남긴다.
- `완료` 보고에는 충족한 기준과 근거를 적는다. 완료되지 않았으면 남은 ID를 명확히 표시한다.

## 15. 세션 교환 규약·외부 가져오기·첫 접속 암호 저장 (2026-11-05 요청 / I.1)

- 자체 JSON 교환 규약을 format/version과 JSON Schema로 고정한다. v1 가져오기 호환을 유지하고 v2로 내보낸다. 세션·그룹·터널·인코딩·인증 방식/키 경로를 담되 비밀번호·개인키 내용·Passphrase·보관함/비밀 참조·호스트 신뢰는 담지 않는다.
- 프로그램별 변환 어댑터를 둔다. 초기 입력은 PuTTY `.reg`, MobaXterm `.mxtsessions`/`.ini`, OpenSSH `config`의 기본 SSH 정보다. 표준 제품들의 전체 설정이 공통 표준이라고 가정하지 않으며 지원/제외 필드를 명시한다. 다른 제품은 검증된 어댑터 없이 호환으로 표시하지 않는다.
- 파일 인코딩 선택/BOM, 미리보기·항목 선택·빠진 사용자명 입력·누락 경고·건수 결과, 기존 데이터 유지와 새 ID 추가, 자동 터널 시작 해제, 트랜잭션 롤백 및 변경 전 복구본을 제공한다. 파일 안의 레지스트리/명령/Include를 실행하지 않는다.
- 첫 접속 인증창에서 암호 저장 여부를 선택하며 성공한 로그인에만 기존 보안 저장소에 저장한다. 다음 접속/앱 재시작 후 재사용, 저장 실패 안내, 인증 실패/취소·OTP 미저장을 검증한다.
- 계약/지원표: [세션 교환 규약](session-transfer.md), [JSON Schema](session-format.schema.json). 검증: 합성 형식 fixture·인코딩/스키마/롤백/UI와 Windows 실제 OpenSSH/보안 저장소. 실제 외부 제품별 내보내기 버전·OS 파일 대화상자·Mac 결과는 별도 기록한다.

## 16. Phase 6 — SSH 작업 기능 확장 (2026-11-05 사용자 요청)

요청 범위는 **폴더 전송·큐, 스니펫, 세션 로그, 점프 호스트, 고급 세션 관리·이관, 기본 서버 명령·로그 필터·초심자 조작표, PodTree 내장**이다. 각 소번호의 구현과 검증 상태는 아래 체크리스트 및 progress의 최신 기록을 따른다. 기존 Phase 0~5와 추가 작업의 구현·검증 상태를 유지한다.

- 기본 순서: **6.1 → 6.2 → 6.3 → 6.4 → 6.5 → 6.6 → 6.7**. `Phase 6 구현해`는 일곱 작업 전체, `Phase 6.4 구현해`는 해당 작업과 필요한 선행 구현을 뜻한다. 전체 요청에서는 소번호 완료마다 재승인을 요구하지 않는다. 6.6은 기본 명령어 모음·복사와 프로그램별 조작표를 제공하며 별도 요청 시 6.2 구현 없이도 진행할 수 있다.
- 6.5의 점프 호스트 이관은 6.4를 선행 조건으로 한다. 기존 I.1의 JSON v1/v2 및 외부 기본 가져오기와 호환을 유지하며 새 필드는 버전 있는 스키마로 확장한다.
- Windows 우선으로 구현·검증하고 Mac 결과는 별도 기록한다. UI는 공통 테마·통합 사이드바·기존 터미널 작업 흐름을 유지한다. 실제 SSH/파일 전송 검사를 Mock으로 대체하지 않는다.
- X11/RDP/VNC, 클라우드·팀 동기화, 내장 편집기, 범용 스크립트 엔진은 이번 추가 범위에 포함하지 않는다. 공개 배포·장시간·OS 수동 검증 등 기존 W/Phase 5 대기를 이 기능 구현으로 완료 처리하지 않는다.

### 6.1 — 폴더 전송·큐

- [x] SFTP 및 기존 FTP/FTPS의 폴더 재귀 업로드·다운로드. 다중 파일/폴더 선택·드롭, 빈 폴더·상대 경로 보존, 파일별/전체 진행률·결과를 제공한다. 서버 내부 복사와 로컬↔원격 전송을 구분한다.
- [x] 영속 전송 큐: 대기/탐색/전송/일시정지/실패/완료/취소 상태, 대기 순서 변경, 개별/묶음 일시정지·취소·재시도, 동시 전송 수 제한. 달력·시간 기반 예약은 제외한다.
- [x] 탐색을 포함한 작업 수·깊이·메모리 상한, 권한 오류·디스크 부족·파일 변경·중복 목적지 처리. 기존 파일 충돌은 건너뛰기/이름 변경/명시적 덮어쓰기를 선택하고 배치 적용 범위를 표시한다. 링크·Windows junction을 따라가지 않으며 경로 이탈·순환을 차단한다.
- [x] 기존 부분 파일/재개 검증을 재사용하고 완료 항목을 재전송하지 않는다. 앱 재시작 후 미완료 작업은 사용자 확인과 동일 대상 재인증 후 재개한다. 큐에는 비밀정보를 저장하지 않는다. 취소 시 부분 파일·생성된 빈 폴더의 보존/정리 정책을 표시하고 기존 파일을 삭제하지 않는다.
- 완료 기준: 실제 SFTP/FTP/FTPS에서 중첩·빈 폴더·한글/공백·동명 파일 왕복 및 내용 일치, 다수 작은 파일·대용량 전송의 상한, 탐색/전송 중 취소·단절·재시작 복구, 충돌/권한/디스크 오류, 큐 순서·다른 세션 작업 격리. OS 폴더 선택/드롭 및 Mac 결과는 별도 기록한다.

구현 체크리스트는 반영했다. Windows 자동·실제 프로토콜 검증과 OS 선택/물리 드롭·Mac 대기를 [6.1 검증 기록](verification/phase-6-1.md)에 구분하며, Phase 6 전체 완료를 뜻하지 않는다.

### 6.2 — 스니펫

- [x] 이름·설명·명령 본문·그룹/태그를 가진 스니펫 CRUD·복제·검색·로컬 저장. 자주 쓰는 명령을 목록에서 찾아 편집·재사용한다.
- [x] 실행 전 대상 세션과 최종 본문을 보여주며 **입력만 넣기**와 **Enter를 포함해 실행**을 구분한다. 여러 줄/제어문자는 기존 붙여넣기 확인 정책을 따른다. 변수는 명시적인 자리표시자와 실행 시 입력만 지원하며 로컬 셸 평가나 명령 치환을 수행하지 않는다.
- [x] 활성 SSH/로컬/WSL 터미널과 명시적으로 선택한 여러 대상에 적용한다. 기존 브로드캐스트와 중복 전송하지 않고 끊어진 대상·재접속으로 바뀐 연결 ID는 재확인한다. 접속·앱 시작 시 자동 실행하지 않는다.
- [x] 비밀번호·개인키·Passphrase·OTP를 스니펫 저장/내보내기 대상으로 삼지 않는다. 인증 입력창과 게임/설정 화면에는 스니펫 입력이 전달되지 않는다. 매크로 녹화·조건/반복 스크립팅은 후속 범위다.
- 완료 기준: CRUD/검색/재시작 복원, 여러 줄·인코딩·자리표시자·취소, 실제 SSH/로컬 PTY에서 입력만/실행 차이, 선택 대상에 정확히 한 번 전달, 브로드캐스트 중복 방지·실패 격리, 좁은 화면·키보드·테마 검증.

구현 및 Windows 실제 SSH/로컬/WSL·독립 창 검증 반영. 물리 IME·Mac·최신 설치본 대기는 [6.2/6.6 검증 기록](verification/phase-6-2-6.md)을 따른다. 전체 Phase 6의 모든 환경 검증 완료를 뜻하지 않는다.

### 6.3 — 세션 로그

- [x] SSH 및 로컬/WSL의 디코딩된 터미널 출력을 세션별 UTF-8 텍스트로 저장한다. 기본은 꺼짐이며 시작/일시정지/재개/종료, 저장 위치·현재 기록 상태를 표시한다. 접속 시 자동 기록은 세션별 명시적 설정으로만 켠다.
- [x] 세션명·시각 기반 안전한 파일명, 선택적 줄 타임스탬프, ANSI 제어문자 제거, 크기/날짜별 파일 회전과 보관 한도를 제공한다. 기존 파일을 묵시적으로 덮어쓰지 않는다.
- [x] 인증 대화·키/Passphrase/OTP·로컬 입력 이벤트·보안 저장소 데이터는 기록하지 않는다. 터미널 출력에 원격 프로그램이 직접 표시한 비밀은 완전한 자동 판별이 불가능하므로 기록 범위 안내·일시정지와 사용자 지정 마스킹을 제공하며, 무조건적인 비밀 제거를 보장하지 않는다. 개발 검증에는 실제 인증정보가 포함된 출력을 사용하지 않는다.
- [x] 로그 쓰기는 SSH 출력 ACK/렌더링과 분리된 유한 큐를 사용한다. 디스크 오류·큐 초과 시 조용히 누락하지 않고 기록 중단/누락 상태를 알리며 터미널은 유지한다. 창 분리·재접속에서 중복 기록을 막고 로그 소유권/종료 flush를 정의한다.
- 완료 기준: 실제 SSH/로컬 PTY 출력 순서·한글/CP949 변환·패킷 경계·ANSI 처리, 회전·재시작·일시정지, 디스크 오류/큐 상한·대량 출력, 창 이동/재접속 중복 방지, 인증 데이터 제외·마스킹 검증. 원시 키 입력 녹화나 세션 영상 재생은 제외한다.

구현 반영. Windows 실제 SSH/WSL·Kubernetes 검증과 환경별 대기는 [6.3/6.7 검증 기록](verification/phase63-67.md) 및 progress를 따른다. 모든 플랫폼/선택 기능의 검증 완료를 뜻하지 않는다.

### 6.4 — 점프 호스트

- [x] 저장된 SSH 프로필을 경유지로 지정하고 순서 있는 다단 경유 체인을 구성한다. 자기 참조·순환·최대 홉 수 초과·없는 참조를 검증하며 연결 화면에 실제 경유 경로와 실패한 홉을 표시한다.
- [x] 각 홉의 비밀번호/키/agent/keyboard-interactive 인증과 호스트키 신뢰를 독립적으로 처리한다. 최종 서버까지 SSH 채널로 연결하며 호스트키 불일치를 우회하지 않는다. 경유지에 개인키/암호를 복사하지 않는다.
- [x] 최종 연결의 PTY·SFTP·외부 편집·모니터링·Local/Remote/SOCKS5 터널을 기존 연결 모델에 통합한다. 경유 연결 소유권·참조 수·취소/타임아웃·중간 단절과 종속 채널 정리를 정의하고, 재접속 시 명령을 자동 재실행하지 않는다.
- [x] 경유 프로필 변경/삭제의 영향과 참조 해소를 안내하고 JSON으로 비밀정보 없는 경유 관계를 교환한다. OpenSSH ProxyJump 변환은 6.5에서 연결한다. 임의 ProxyCommand 실행·HTTP/SOCKS 접속 프록시·agent forwarding은 이번 범위에서 제외한다.
- 완료 기준: 실제 OpenSSH 1홉/2홉 경유와 혼합 인증, 각 홉의 최초/변경 호스트키·인증 실패·취소/타임아웃, 최종 PTY/SFTP 및 터널 왕복, 중간 서버 단절/재접속·자원 정리·다른 연결 격리. 직접 접속 회귀와 Windows UI, Mac 대기를 구분한다.

구현 반영. 실제 검증·환경 대기는 [6.4/6.5 검증 기록](verification/phase-6-jump-sessions.md)과 progress를 따른다.

### 6.5 — 고급 세션 관리·이관

- [x] 계층형 그룹/폴더·이동·정렬, 세션 태그·복합 검색·다중 선택·일괄 수정. 그룹 삭제 시 하위 그룹/세션 이동 또는 삭제 범위를 미리 보여주며 순환·고아 참조를 차단한다. 기존 평면 그룹은 손실 없이 이행한다.
- [x] 세션 템플릿으로 포트·인증 방식·인코딩·연결 옵션·경유 관계 등 공통 설정을 재사용한다. 비밀정보는 복제하지 않으며 일괄 변경에는 변경 필드와 대상 미리보기·트랜잭션·변경 전 복구본을 제공한다.
- [x] 기존 PuTTY/MobaXterm/OpenSSH 어댑터를 확장해 계층·키 경로·지원되는 터널/경유 설정을 변환한다. OpenSSH Include는 선택한 설정 루트 안의 파일을 목록/미리보기로 확인한 뒤 제한적으로 읽고 순환/이탈을 차단한다. ProxyJump는 6.4의 모델로 변환한다. Match·ProxyCommand 등 지원하지 않는 연결 조건은 해당 세션을 제외하거나 적용을 차단하며 직접 접속으로 묵시적 변환하지 않는다.

### 6.6 — 기본 서버 명령·로그 필터·초심자 조작표

- 사용자 확정(2026-11-05): 일반 서버 사용자가 자주 쓰는 명령을 짧은 설명과 함께 복사한다. **파일명/설치 경로 찾기**, **tail/cat의 원하는 내용 필터**, **vi/tail 등 사용 중 이동·검색·페이지·종료 키 범례**를 포함한다. 목적 문장 입력·AI 명령 생성·복잡한 옵션 폼·인라인 자동 완성으로 확장하지 않는다.
- [x] Linux 서버 일상 작업의 기본 명령 약20~30개와 필요한 필터 예제를 파일/폴더·내용/로그·용량/메모리·프로세스·네트워크로 간단히 분류한다. 각 항목은 **짧은 한국어 설명 + 명령 + 복사 버튼**이다. 파일명·검색어·경로 등 사용자가 바꿀 부분을 강조하고, 복사에는 설명/강조 마크업/줄끝 Enter를 넣지 않는다. 직접 붙여넣고 수정·실행하며 앱이 자동 입력하거나 실행하지 않는다.
- [x] 파일명 찾기: `find . -type f -name '*파일명*'`, 대소문자 무시 찾기 등 기본 예제를 제공한다. 현재 폴더 기준임을 설명하고 전체 서버 탐색을 기본값으로 삼지 않는다. 실행 파일 경로는 `command -v 프로그램명`, 관련 경로는 `whereis 프로그램명`, 링크가 가리키는 실제 경로는 `readlink -f 경로`로 구분한다. 실행 파일 위치를 설정/데이터를 포함한 전체 설치 경로라고 단정하지 않으며 미설치/PATH 밖/셸 내장 명령 차이를 설명한다.
- [x] tail/cat 필터는 흔한 목적을 목록으로 제공한다: 마지막100줄, 실시간 보기, 특정 문구 포함/제외, 여러 문구 중 하나 포함, 두 문구 모두 포함, 일치 줄 앞뒤 함께 보기. 예: `tail -n 100 파일명`, `cat 파일명 | grep -F -- '검색어'`, `grep -F -v -- '제외어' 파일명`, `grep -F -e '문구1' -e '문구2' 파일명`, `grep -F -C 3 -- '검색어' 파일명`. 단순 파일 검색은 cat 없이 grep만 써도 된다는 짧은 설명을 제공한다. 기본 검색은 정규식이 아닌 문자 그대로이며 `-e`의 OR와 파이프 연속 필터의 AND를 구분한다.
- [x] 실시간 필터 예제: `tail -f 파일명 | grep --line-buffered -F -- '검색어'`. 여러 필터를 연결할 때 각 단계의 버퍼링을 처리한다. `tail -f`와 로그 교체를 따라가는 `tail -F` 차이, Ctrl+C 종료, 출력이 없을 때 일치 항목 없음/권한/파일 경로 확인을 짧게 설명한다. `--line-buffered`·`readlink -f` 등은 지원 환경을 표시하며 GNU/Linux 예제를 다른 OS에 그대로 보장하지 않는다. 작은 따옴표를 포함한 검색어의 인용법도 도움말에 명시한다.
- [x] **프로그램별 조작표**: 터미널을 가리지 않는 접이식 하단/옆 패널에 동작명과 키를 표시한다. vi/vim은 먼저 Esc로 명령 모드 전환, i 입력, 방향키/hjkl 이동, Ctrl+f/b 페이지, gg/G(vim 기준) 처음/끝, `/검색어`+Enter·n/N 다음/이전, `:w` 저장·`:q` 종료·`:wq` 저장 후 종료·`:q!` 변경 버리고 종료. vi/vim 지원 차이와 저장 명령의 Enter를 명시한다. less는 Space/b 페이지·g/G 처음/끝·/검색·n/N·q 종료. tail -f는 Ctrl+C 종료, 화면 스크롤은 터미널 스크롤백 조작으로 구분한다. cat은 출력 후 종료하므로 자체 검색/페이지 키가 있다고 표시하지 않고 많은 내용을 탐색할 때 `less 파일명`을 안내한다.
- [x] 조작표 자동 표시는 지원되는 셸의 명시적 실행/종료 메타데이터로 프로그램을 확인할 수 있을 때만 수행한다. 자동 완성을 위한 셸 통합은 추가하지 않는다. 서버 출력 문자열이나 입력 키 수집만으로 실행 프로그램을 단정하지 않으며 명령 인자·이력·비밀정보를 저장하지 않는다. 감지 불가 환경에서는 사용자가 vi/tail/cat/less 조작표를 직접 선택·고정할 수 있다. 프로그램 종료 시 자동 표시만 해제하고 사용자 고정은 유지한다. 셸 설정을 자동 수정하지 않는다.
- [x] 조작표는 안내용으로 키를 서버에 보내거나 가로채지 않는다. 현재 vi 모드/검색 위치를 모르면 추정 표시하지 않는다. IME·인증 입력·TUI·브로드캐스트 동작을 유지하고 다른 탭의 조작표가 섞이지 않게 한다. 키보드로 접기/열기·끄기, 좁은 창·테마를 지원한다. 기본 명령/예제는 오프라인 제공하며 전문 Kubernetes/Git/Docker 명령 사전은 제외한다. 사용자 저장 스니펫은 6.2, PodTree는 6.7로 유지한다.
- 완료 기준: 격리된 Linux fixture에서 파일/실행 경로 검색 및 포함/제외/OR/AND/앞뒤 필터 결과, 실시간 필터의 지연·Ctrl+C·로그 교체 동작 확인. 표시 문자열/클립보드 일치·성공/실패·개행 없음, 인용 설명·GNU/vi/vim 차이를 검사한다. 실제 SSH/로컬 PTY의 지원 환경에서 vi/less/tail/cat 진입·종료/탭 전환과 조작표 자동 표시/해제, 미지원 환경의 수동 선택·고정, 키 입력/IME 격리 및 좁은 화면·테마를 검증한다. 미실행 환경은 대기로 기록한다.

구현 및 Windows 실제 SSH/로컬/WSL·독립 창 검증 반영. 물리 IME·Mac·최신 설치본 대기는 [6.2/6.6 검증 기록](verification/phase-6-2-6.md)을 따른다. 전체 Phase 6의 모든 환경 검증 완료를 뜻하지 않는다.
