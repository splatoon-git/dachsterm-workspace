# Windows 출시 전 수동 검증

작성: 2026-11-05. Mac은 이번 작업에서 보류한다. 아래 모든 항목은 실제 결과를 기록하기 전까지 **대기**다. 자동 composition/IPC/컨테이너 단절 성공으로 OS 동작을 대신하지 않는다. 운영 서버 대신 폐기 가능한 테스트 서버·파일을 사용하며 인증정보·터미널 원문을 결과에 붙이지 않는다.

## 배포·외부 자원 (W.3 / 5.3)

- **서명**: Windows 인증서로 EXE·설치 파일에 서명한 뒤 `Get-AuthenticodeSignature`가 `Valid`인지 확인. 서명 키를 저장소에 넣지 않는다. 인증서/배포 주체 미제공으로 대기.
- **깨끗한 PC**: 개발 도구 없는 표준 사용자 Windows 11에서 WebView2 설치/오프라인 실패 안내, 설치→사용→제거. 실제 SmartScreen 화면 확인. 서명이 경고 제거를 보장한다는 전제를 두지 않는다.
- **이전 버전 업그레이드**: 별도 Windows 사용자 또는 VM에 이전 설치본과 테스트 세션/암호/편집 복구본을 만든 뒤 새 버전 설치. 세션·암호 접속·신뢰 키·부분 전송·설정 유지 검사. 같은 버전 재설치 자동 검사는 이 항목을 대체하지 않는다.
- **배포 경로**: 소유한 HTTPS 배포 주소, 릴리스 노트, 지원/보안 신고 연락처, 앱/마스코트 배포 권리 결정. 현재 자동 업데이트 서비스와 서명된 업데이트 메타데이터는 구성되지 않았다. 주소나 키를 임의로 만들지 않는다.
- **출시 차단 항목**: Rust 보안 감사 잔여 항목과 라이선스 원문 누락은 [안정화 기록](windows-hardening.md)을 따른다. 공개 릴리스 검사 실패를 우회해 “검증 완료”로 표시하지 않는다.

## 결과 양식

각 항목에 실행일·Windows 빌드·앱 버전/설치 SHA256·환경·절차·기대/실제 결과·통과/실패·재현 조건을 기록한다. 필요한 스크린샷에서도 서버 주소/사용자 이름/인증정보를 제거한다. 다음 첫 수동 작업은 M1→M2→M3이며, 24시간 검사는 별도로 진행한다.
