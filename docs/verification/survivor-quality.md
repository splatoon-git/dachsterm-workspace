# 서바이버 지역·적·밀도 개선 검증

2026-11-05 사용자 요청 **G.8.Q1**. 그래픽 사양 확장보다 지역 구성·디테일·적 표현·전투 밀도 개선이 범위다. [설계](../design/dachs-survivor.md)의 Q1과 [진행 기록](../progress.md)을 함께 따른다.

## 구현

- `scenery.ts`: 3구간 단위 숲/유적/수정 골짜기/설원. 지역별 길 템플릿, 시드/지역 회차별 소품400개·랜드마크6개. 같은 지역의 세 구간은 같은 배치이며 13구간의 숲은 첫 숲과 다른 배치다. 고정 전장·카메라 유지, 장식은 통과 가능하며 전투 RNG와 무관하다.
- `enemyRenderer.ts`, `renderer.ts`: 기존8종의 실루엣·눈/표정·음영·날갯짓/탄성/보행, 왕관·갑옷·보스 뿔, 공격 예고 느낌표, 실제 HP바, 지역 이름. 테마 토큰과 기존 닥스 atlas 사용. 다크 테마에서도 눈동자는 밝은 눈과 구분된다. 새 AI 종류 추가는 아니다.
- `content.ts`, `enemies.ts`: 콘텐츠 버전4, 초기1.4/s에서 최대5.8/s. 초반 박쥐/버섯/멧돼지를 순차 소개하고 이후 지역별 5종 가중치. 일반/정예는 시야 경계+반경+64~144에서 생성하되 기존240 안전거리·화면 밖·월드 경계·16회 탐색·180/2/1 상한을 유지한다. 보스는 기존600~720 반경이다. HP/피해/XP/드롭/보스 보상 수식은 변경하지 않았다.
- 배경은 런당512px 타일12개, 적은 테마별4Mi픽셀 LRU 캐시로 제한한다. 테마/지역 교체 시 갱신, 런 데이터는 변경하지 않는다. 그림자·포즈는 캐시하고 HP바는 실시간이다. 모션 줄이기에서 정적 포즈를 사용한다.

## 규칙·화면 검사

- `node --max-old-space-size=1024 node_modules/vitest/vitest.mjs run src --maxWorkers=1`: **40파일649개 통과**. 새 지역/배치/범위/난수 분리·초반 혼합/밀도4개 포함. 기존 전투/상한/스폰 안전/30·60·120Hz/저장 회귀 유지.
- 첫 실행3실패는 이전75틱 생성 간격, 슬라임만 나온다는 최소 물기 횟수, 기존 원형 스폰 실패 좌표의 기대값이었다. 새 스폰 계약에 맞춰 실제 미생성 경계·상한/밀린 생성 방지·처치/레벨업 검증으로 갱신한 후 통과했다.
- `node node_modules/@playwright/test/cli.js test tests/ui/survivor-quality.spec.ts tests/ui/survivor.spec.ts --workers=1`: **13개 통과**. 최종 눈동자 색 보완 후 quality2개 재실행도 통과했다. `survivor-quality-browser.json`, `survivor-quality-browser-final.json`에 결과 보존.
- 지역4종×라이트/다크8장,360/560 좁은 화면,180마리 인위적 밀집/모션 감소·애니메이션, 렌더 전후 전체 run 일치, 반복 렌더 픽셀 일치를 검사했다. 지역/군집 캡처를 직접 확인했다. `target/verification/survivor-region-*.png`. 캡처의 적8종 동시 배치는 외형 검사용이며 실제 스폰 구성이 아니다.
- `tsc --noEmit`, 변경 소스/검사의 ESLint, Prettier, `git diff --check` 통과. `tauri build --debug --no-bundle`의 tsc-b/Vite/Rust 빌드도 통과. 기존 main 번들500KB 경고 유지.

## 렌더링 부하와 실제 Windows

- 처음 Chromium에서 RAF 없이120회를 연속 제출한 검사는 GPU 작업이 밀리면서 p95가236~330ms로 나왔다. 이 숫자를 실제 게임 프레임 시간이나 캐시 효과로 해석하지 않는다. 반복 그림 비용을 제한하는 타일/외형 캐시를 적용했고, 검사 드라이버도 RAF에 맞춰 측정하도록 수정했다.
- RAF에 맞춘 Chromium180마리/360프레임 검사: 정적 p95 1.0/0.8ms, 애니메이션 p95 4.5ms(눈동자 색 보완 직전 측정). Canvas 제출 CPU 시간이며 GPU/전체 게임 FPS는 아니다. 최종 재측정은 정적1.7/2.0ms·애니메이션9.3ms이며 browser-final JSON의 renderer-cost 첨부에 있다. 측정 중 호스트 부하 차이가 있어 정밀 성능 개선율로 환산하지 않는다.
- `target/measure-survivor-quality-native.mjs`: 기존 native 성능 드라이버의 기간만10초로 줄이고 별도 결과명으로 실행했다. 실제 WebView2에 현재 소스를 주입한 인위적 상한 부하이며183적/240공격/250드롭/100탄환을 유지했다. 엔진+Canvas CPU p95 **8.0ms**, 실제 SurvivorGame/controller/session/HUD 콜백 p95 **5.8ms**. RAF 간격 p95는 각각50/33.3ms여서 **60fps 보장이 아니다**. `survivor-quality-performance-native.json`. 타일 경계의64px 여유·최종 눈동자 색 수정 전 캐시 버전 측정이다.
- 이 성능 검사의 적 체력1조·격자형 탄환·장판240개는 테스트 전용 주입이다. 제품 진입점은 해당 fixture를 import하지 않는다. 사용자 첨부 화면은 이 인위적 부하 장면이며 정상 게임의 적 체력/배치가 아니다.
- 위10초 부하는 G.8.6의60초 검사나 일반 입력 보스 클리어를 대체하지 않는다. 같은 드라이버의11회 엔진 churn JS 힙은11,065,124~11,189,384바이트 범위였다. GPU 캐시/10개 장시간 실제 전투 메모리 검증은 아니다.
- 새 debug에서 `node scripts/test-survivor-ui-native.mjs` 실행: 일반 이동·자연 첫 카드·정지/재개·창 닫기 저장 실패 차단·재시도1회정산·정상종료/재실행 일치, pageerror0. 최종 debug SHA256은 `4e8d88da49233039077b2b19b0375e84334273901aac01488f3bae94a1e5d091`이며 native 검사 JSON과 일치한다. 파일 경로는 `target/debug/daxterm.exe`다.

## 남은 범위

현재 요청의 지역/외형/출현 구성 개선과 debug 빌드는 완료했다. 이번 변경의 release/NSIS/설치, Mac, 실제 OS 종료/절전, 사람의 다중 시드 플레이, 최종 캐시 버전60초 부하/장시간 전투 메모리는 미검증이다. 다른 G.8.6 작업에서 실행한 이전 소스 결과를 이번 콘텐츠버전4의 검증으로 옮겨 적지 않는다. 실제 SSH/PTY와 Rust 제품 코드는 변경하지 않아 이번 작업에서 재검사하지 않았다. 기존 진행 중인 UI/수명/검증/설치 스크립트 변경은 보존했다.
