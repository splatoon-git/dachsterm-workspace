# `test:native` 불안정 조사 (T5)

- 실행일: 2026-11-06 / 실행 파일: `64e1579` 시점 debug 빌드의 고정 사본 / 환경: Windows 11, Docker 28.5.1
- 전부 로컬 결과다. CI는 네이티브 검사를 실행하지 않는다.
- **결론**: 원인은 검사 스크립트의 경합과 짧은 대기였다. 제품 결함은 확인되지 않았다. 분할 단계 실패 1건은 원인을 찾지 못했다.

|---|---|---|
| 평상시 | 수정 전 | 4/8 |

평상시 수정 전 결과는 다른 작업의 빌드와 겹친 시간대가 포함되어 있어, 수정 효과만의 수치로 볼 수 없다. 포화 실험은 평상시와 다른 실패를 드러내는 데 쓰였고, 새 탭 대기의 효과를 입증하지 못했다.

## 원인과 수정 (`scripts/test-native.mjs`)

| 실패 | 근거 | 수정 | 판단 |
|---|---|---|---|
| CP949 단계 `output('한글')` | 실패 화면의 새 탭에 입력이 전혀 없다. 연결 클릭 후 `vault_status`를 기다리는 동안 `connected()`가 기존 탭을 보고 통과한다. | `connectNewTab()`으로 새 탭의 연결 ID를 기다린다. | 화면 근거로 확인 |
| 재시작 후 디버그 포트 없음 | 포화 상태 측정에서 앱 종료 후 WebView2 6개가 남고, 다음 실행의 포트가 15초 뒤 열리거나 30초 안에 열리지 않았다. 평상시에는 남지 않았다. | `shutdown()`이 이 검사의 WebView2 종료까지 기다린다. | 원인 측정. 수정 효과는 부하 상태 미검증 |

| 클립보드 읽기 | 포화 상태에서 복사 직후 값 비교가 실패했다. | `expect.poll`로 기다린다. | 부하 실패 1건 근거. 수정 효과는 부하 상태 미검증 |

평상시 첫 실행에서 나온 `master vault migration and reveal` 실패는 당시 줄 번호를 남기지 못해 위 금고 항목 중 어느 쪽인지 특정할 수 없다.

## 남은 것

- **분할 단계 `output('SPLIT_0')` 실패 1건은 원인 미확인이다.** 위 수정으로 설명되지 않고 재현되지도 않았다. 제품 문제 가능성을 배제하지 못한다.
- `run-phase1.mjs`의 `test-native.mjs` 300초 제한은 그대로 두었다. 포화 상태에서 모든 단계가 PASS한 뒤 이 제한에 걸린 적이 있다(평상시 약 120초).
- 같은 `launch()`를 가진 다른 네이티브 스크립트에는 WebView2 대기를 넣지 않았다. 공용 헬퍼(T2)에서 함께 처리한다.

## 실패 시 진단

실패하면 스택의 줄 번호 전체와 앱의 알림·연결 상태 문구를 출력한다. CP949와 분할 단계는 스크린샷도 남긴다. 금고 단계는 암호가 보일 수 있어 스크린샷을 남기지 않는다.
