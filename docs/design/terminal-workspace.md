## 1. 목표

**평소에는 탭 바, 터미널, 상태바만 보인다. 그 밖의 정보는 상태가 생겼을 때만 나타난다.**

1. VS Code처럼 탭을 끌어 옆, 아래, 다른 칸의 탭으로 자유롭게 배치한다.
2. 터미널 밖 도구 줄을 없앤다.
3. 조작표는 클릭 없이 자동으로 나타나고 화면을 가리지 않는다.
4. 개별·전체·선택 입력을 대화상자 없이 창에서 바로 고른다.
5. 설정은 실제 적용 범위에 맞는 곳에 둔다.
6. 기능을 화면 버튼으로 나열하지 않는다. 터미널 관련 조작은 탭 헤더 우클릭 메뉴에 두고, 터미널 안 우클릭은 바로 붙여넣기로 유지한다.
7. OS 제목 표시줄과 앱 헤더 2단을 한 줄로 합쳐 본 작업에 공간을 준다.

제외: 보기·도구 메뉴의 내용, 연결 목록과 파일 패널의 기능은 그대로 둔다. 독립 창은 한 세션만 담는 현재 구조를 유지한다.

| 상단 2단 | OS 제목 표시줄 아래 앱 헤더가 다시 있어 탭 위에서 약 100px를 쓴다(스크린샷 어림값). 앱 이름이 두 번 표시되고 `DESKTOP` 배지는 정보가 없다 |
| 터미널 밖에 도구 줄 4개, 약 200px | [App.tsx](../../src/app/App.tsx) `workspace-controls`, [TerminalPane.tsx](../../src/features/terminal/TerminalPane.tsx) `terminal-tools`, `connection-message`, `ProgramGuide`. 높이는 스크린샷에서 어림한 값이다. SSH는 `MonitorBar` 한 줄이 더 있다 |

| 탭 드래그 자체가 Windows에서 동작하지 않을 수 있음 | `tauri.conf.json`에 `dragDropEnabled` 설정이 없어 기본값(켜짐)이고, Tauri 문서는 Windows에서 HTML5 드래그를 쓰려면 끄라고 안내한다. 현재 동작은 실행해 확인해야 한다. 파일 드롭이 `onDragDropEvent`에 의존하므로([FilePanel.tsx](../../src/features/sftp/FilePanel.tsx), [usePromptAttachments.ts](../../src/features/terminal/usePromptAttachments.ts)) 끌 수 없다 |
| 조작표가 사실상 수동 | `guideEnabled` 기본값이 꺼짐이다. 자동 표시까지 ① 조작표 열기 ② 실행 알림 켜기 ③ 도구 메뉴에서 Bash 코드 복사 ④ 셸에 직접 실행이 필요하고, 창마다 반복해야 한다 |
| 터미널 설정이 창마다 있지만 값은 공통 | [TerminalSettings.tsx](../../src/features/terminal/TerminalSettings.tsx)의 항목은 전부 `saveTerminalPreferences`, `saveTerminalDisplay`로 저장되는 앱 공통 값이다. `session`은 오류 알림에만 쓴다 |
| 복사·붙여넣기 버튼이 중복 | 선택 시 복사와 우클릭 붙여넣기가 기본으로 켜져 있고 단축키도 있다 |
| 분할 비율이 전역 슬라이더 | `split` 값 하나를 모든 레이아웃이 공유한다 |
| 입력 범위 선택이 무거움 | 드롭다운 → 대화상자 → 체크 → 적용. 어느 창인지 이름과 ID로 판단해야 한다 |

## 3. 화면 구조

```text
┌ 제목 줄 36px: DachsTerm 보기 도구 ···끌어서 이동··· ＋새 연결 ─ □ × ┐
├──┬──────────┬───────────────────┬──────────────────┤
│연│ 사이드바 │ 탭 바 34px        │ 탭 바 34px       │
│결│ 240px    ├───────────────────┼──────────────────┤
│파│ 기본     │ 터미널            ┃ 터미널           │  ┃ 분할선
│일│          │                   ┃                  │
│  │          │                   ┃                  │
│설│          │                   ┃                  │
│정│          │                   ┃                  │
├──┴──────────┴───────────────────┴──────────────────┤
│ 상태바 24px: ● 대상 · 인코딩 │ 조작표 │ REC · 입력 범위 · CPU·RAM │

```

위아래 고정 영역은 36 + 34 + 24 = 94px다. 지금은 약 370px다(스크린샷 어림값, SSH의 모니터 줄 제외).

탭 바에는 평소 버튼이 없다. 마우스를 올리거나 포커스가 들어오면 탭 우클릭과 같은 메뉴를 여는 ⋯ 하나만 나타난다.

### 제목 줄 한 줄 통합

| | Windows | macOS |
|---|---|---|
| 창 설정 | `tauri.windows.conf.json`에 `decorations: false` | `tauri.macos.conf.json`에 `titleBarStyle: "Overlay"`, `hiddenTitle: true` |
| 창 버튼 | 앱에서 직접 그린다 (최소화, 최대화, 닫기) | 시스템 신호등 버튼을 그대로 쓰고 왼쪽 78px를 비운다 |
| 독립 창 | [windows.rs](../../src-tauri/src/windows.rs)의 빌더에 같은 값을 `cfg`로 적용 | 같음 |

- 빈 곳에 `data-tauri-drag-region`을 달아 이동과 더블클릭 최대화를 처리한다.
- [capabilities/main.json](../../src-tauri/capabilities/main.json)에 `core:window:allow-start-dragging`, `allow-minimize`, `allow-toggle-maximize`를 추가한다. `allow-close`는 이미 있다. 닫기 버튼은 `close()`를 호출해 서바이버 종료 정산 가드(`onCloseRequested`)를 그대로 지난다.
- 개발용 브라우저 실행(`desktop === false`)에서는 창 버튼을 표시하지 않는다.
- **창 버튼 결정(2026-11-07 사용자 승인):** Windows 창 버튼은 직접 그리고 외부 플러그인을 추가하지 않는다. Windows 11의 최대화 버튼 호버 스냅 레이아웃은 직접 그린 버튼에서 기본으로 나오지 않는 것으로 알고 있으며, 이 제약을 수용한다. 창 끌기 스냅과 `Win+방향키`, `Win+Z` 지원 여부는 실제 앱에서 확인한다. 테두리 크기 조절도 함께 확인한다.
- 헤더에서 빠지는 것: 앱 이름 큰 표시, `DESKTOP` 배지, `☰`(세로 아이콘 줄로), `로컬 터미널`(＋ 메뉴와 왼쪽 목록으로), 설정(세로 아이콘 줄로). `＋ 새 연결`은 강조 버튼에서 일반 버튼으로 낮춘다. 접근성 이름은 유지해 검사 수정을 줄인다.

### 우클릭 메뉴

| 대상 | 항목 |
|---|---|
| 터미널 안 | **메뉴 없음. 우클릭은 바로 붙여넣기** (사용자 결정) |
| 탭 헤더, 탭 바의 ⋯ | 터미널 검색, 세션 기록, 조작표 전체 보기, 오른쪽·아래로 분할, 이 창 확대, 새 창으로 분리, 연결 종료·재접속, 탭 닫기, 다른 탭 닫기. FTP 탭에는 터미널 전용 항목을 표시하지 않는다 |
| 연결 카드 | 연결, 수정, 즐겨찾기, 복제, 삭제. 더블클릭과 Enter로 연결하는 동작은 유지 |
| 파일 패널의 파일 | 기존 파일 메뉴 유지 |
| ＋ 새 연결 | 새 연결, 로컬 터미널 목록 |
| 보기 메뉴 | 기존 항목과 모든 탭 좌우·상하·2×2·하나로 |

- **공용 컴포넌트:** `src/components/ContextMenu.tsx`로 만든다. 항목 정의를 데이터로 받고, 창 경계 안 배치, 바깥 클릭·`Esc` 닫기, 방향키 이동, 닫을 때 포커스 복귀를 처리한다. 파일 패널 2곳의 메뉴도 이 컴포넌트로 옮겨 복사가 세 번째로 늘지 않게 한다(engineering-rules §4).
- **터미널 안 우클릭:** 지금 동작과 설정(`rightClickPaste`)을 그대로 유지한다. 마우스를 쓰는 TUI에서는 우클릭을 프로그램이 받고, `Shift+우클릭`이 붙여넣기다. 터미널 사용 경험상 붙여넣기가 우선이다.
- **복사·붙여넣기 버튼:** 메뉴로 옮기지 않고 제거한다. 선택 시 복사, 우클릭 붙여넣기, `Ctrl/Cmd+Shift+C`, `V`, `Shift+Insert`가 그대로 있다. 설정에서 마우스 동작을 끈 사용자는 단축키를 쓴다.
- **키보드:** 탭에 포커스가 있을 때 `Shift+F10`과 메뉴 키로 연다. 터미널에 포커스가 있으면 이 키는 지금처럼 터미널로 보낸다.
- **Mac:** 탭과 연결 카드에서 두 손가락 클릭과 Control+클릭이 `contextmenu` 이벤트로 오는지 실기기에서 확인한다. 터미널 안 Control+클릭의 지금 동작은 바꾸지 않는다.

상태바는 앱에 이미 있는 `<footer>`를 쓴다. 항상 있는 줄이라 내용이 바뀌어도 터미널 크기가 변하지 않는다. vim이 시작하는 순간 패널이 나타나 SIGWINCH가 발생하는 문제도, 오버레이가 vim 상태줄을 가리는 문제도 없다. 포커스된 창 하나의 정보만 표시한다.

### 기존 조작의 이동

| 지금 | 제안 |
|---|---|
| 단일·좌우·상하·2×2 | 탭 끌기. 일괄 정리는 보기 메뉴 |
| 분할 비율 슬라이더 | **제거.** 분할선 드래그 |
| 입력 드롭다운·대화상자 | 상태바 개별·전체·선택, 창에서 체크 (§5) |
| 선택 창 확대 | 탭 바 빈 곳 더블클릭, `Ctrl/Cmd+Shift+Enter`, 탭 우클릭 |
| 전체화면 | `F11`, 보기 메뉴 |
| 새 창으로 분리 ↗ | 탭 우클릭, 탭을 앱 창 밖으로 끌기 (SSH만) |
| 터미널 검색 입력칸 | 탭 우클릭 또는 단축키로 창 위에 표시. `Esc`로 닫기 |
| 로그 · 꺼짐 | 탭 우클릭. 기록 중이면 탭과 상태바에 `REC`, 오류면 상태바에 오류 문구 |
| 복사·붙여넣기 버튼 | **제거.** 터미널 우클릭 붙여넣기, 선택 시 복사, 단축키 사용 |
| 터미널 설정 톱니 | 앱 설정의 “터미널” 항목 (§7) |
| 연결 종료·재접속 | 탭 우클릭. 끊어지면 창 안 안내 카드에 재접속·탭 닫기 |
| 연결 카드 버튼 3개 | 카드 우클릭, 더블클릭으로 연결 |
| 연결 정보 줄 | 상태바 왼쪽. 오류·종료는 창 안 안내 카드로도 표시 |
| 조작표 열기 | 상태바 자동 표시 (§6) |
| 서버 모니터 줄 | 상태바 `CPU · RAM`, 누르면 기존 상세를 팝오버로 |
| 탭의 “연결됨” 글자 | 상태 점. 접속 중·오류·종료만 글자와 도형을 함께 표시해 색에만 의존하지 않는다. 프로그램 상태 배지(`StatusBadge`)와 확인 처리는 유지한다 |
| 독립 창의 입력, 스니펫, 기본 명령, 전체화면, 원격 파일 버튼 | 제목 줄 메뉴로 옮기고, 입력 범위와 터미널 정보는 같은 상태바에 표시 |

호스트 키 확인, 인증 입력, 붙여넣기 확인, 첨부 확인은 지금처럼 창 안에 둔다.

세션 로그 상태는 지금 `SessionLog`가 창마다 750ms 간격으로 조회한다. 버튼이 사라져도 `REC`와 오류를 표시해야 하므로 조회를 세션별 공용 훅 하나로 옮겨 탭과 상태바가 함께 쓰고, 이전 요청이 끝나기 전에는 다음 요청을 보내지 않는다(engineering-rules §7).

### 왼쪽 사이드바

기능은 그대로 두고 밀도만 높인다. 세션 검색, 로컬 터미널·WSL 목록, 저장된 연결(전체·즐겨찾기·최근·그룹), 연결 카드의 모든 작업, 게임 목록, 너비 조절을 유지한다. SSH·FTP·FTPS 프로필은 지금처럼 같은 목록에 나오고 연결 방법도 같다.

- 연결·파일 탭 줄과 `☰`를 44px 세로 아이콘 줄로 합친다. 켜진 아이콘을 다시 누르면 접힌다. 아래쪽에 설정을 둔다. `Ctrl/Cmd+Shift+B`, `E`는 유지한다.
- `워크스페이스` 제목 줄을 없애고 검색칸부터 시작한다.
- 연결 카드의 버튼을 우클릭으로 옮겨 두 줄로 줄인다.
- 너비 기본값을 240px로, 조절 범위를 200~420px로 바꾼다. 지금은 280~420px다.
- 연결 카드에 프로토콜 배지(`SSH`, `FTP`, `FTPS`)를 추가한다. 지금 카드는 `사용자@호스트:포트`만 표시해 FTP를 구분할 수 없다.
- 파일 보기와 모니터는 지금의 활성 탭 대신 **포커스된 칸의 활성 탭**을 따른다.

### FTP·FTPS 탭

FTP 탭에는 터미널이 없고 [FtpPane.tsx](../../src/features/sftp/FtpPane.tsx)가 파일 패널을 표시한다. 탭으로서는 터미널과 같게 동작해 끌기, 분할, 합치기를 모두 지원한다. 상단 `ftp-heading` 줄은 터미널의 도구 줄과 함께 없앤다.

| 항목 | FTP 탭의 동작 |
|---|---|
| 프로토콜·대상·상태 | 상태바 왼쪽. `FTP · TLS 없음` 같은 보안 표시를 유지한다 |
| 연결 종료·재접속 | 탭 우클릭, 끊어지면 창 안 안내 카드 |
| 파일 위 우클릭 | 기존 파일 메뉴 유지 (공용 컴포넌트로 교체) |
| 검색, 터미널 복사·붙여넣기, 세션 기록, 조작표 | 메뉴에 표시하지 않음 |
| 입력 범위 | 대상에서 제외. “입력 받기” 체크를 표시하지 않고, 동시 입력 중에는 “입력 전달 대상 아님”을 표시한다 |
| 서버 모니터 | 표시하지 않음 |
| 새 창으로 분리 | 지금처럼 불가. 앱 창 밖으로 끌면 취소한다 |
| 왼쪽 파일 보기 | 지금처럼 “파일 작업 탭 사용 중” 안내 |

파일 패널은 터미널보다 넓은 공간이 필요하므로 좁은 칸에서의 표시를 TW.2에서 확인한다. 탭 종류별 메뉴와 상태 표시는 engineering-rules §7에 따라 `session.podtree ? … : …` 분기를 늘리지 않고 탭 종류별 정의로 분리한다.

전체화면에서는 상태바를 숨기지 않는다. 지금은 `.terminal-fullscreen > footer`를 숨기지만, 조작표와 동시 입력 경고가 상태바로 옮겨 오므로 필요하다. 같은 이유로 독립 창에도 같은 상태바를 넣는다.

## 4. 탭과 분할

### 모델

칸(그룹)마다 탭 바를 갖고, 칸은 이진이 아닌 분할 트리로 배치한다.

```ts
type TabRef =
  | { kind: 'session'; tabId: string }
  | { kind: 'game'; id: GameId }
  | { kind: 'preview' };
type LayoutNode =
  | { type: 'group'; id: string; tabs: TabRef[]; active: string }
  | { type: 'split'; dir: 'row' | 'column'; sizes: number[]; children: LayoutNode[] };
```

- 레이아웃 연산은 순수 함수로 `src/app/workspaceLayout.ts`에 두고 단위 테스트한다: `openTab`, `closeTab`, `moveTab`, `splitWith`, `resize`, `rects`, `hitTest`, `applyPreset`, `parseSaved`.
- `paneCapacity`, `insertTab`, `layout`, `split`, `zoomed`와 관련 CSS(`layout-*`, `data-pane-count`, `.split-ratio`)는 제거한다.
- engineering-rules §4에 따라 `App.tsx`는 순증 없이 수정한다. 상태는 `useWorkspaceLayout`으로, 화면은 `WorkspaceGrid.tsx`, `GroupTabBar.tsx`, `StatusBar.tsx`로 분리한다.

### 렌더링: 터미널은 다시 마운트하지 않는다

트리 모양대로 DOM을 중첩하면 탭을 옮길 때 React가 터미널을 다시 만든다. 그래서 `rects(tree)`로 계산한 비율 좌표로 **평탄한 목록을 절대 배치**한다. `pane-cell`의 key는 지금처럼 `tabId`이고, 칸을 옮겨도 좌표만 바뀐다. 검색어, 스크롤, 확인창 같은 로컬 상태와 `TerminalSession`이 유지된다. 비활성 탭은 지금처럼 `hidden`으로 둔다.

### 드래그: 포인터 이벤트로 구현한다

HTML5 드래그는 쓰지 않는다. 파일 드롭 때문에 `dragDropEnabled`를 끌 수 없고(§2), WKWebView와 동작 차이도 피할 수 있다.

1. 탭에서 포인터를 누르고 5px 이상 움직이면 드래그를 시작하고 포인터를 캡처한다. xterm이 이벤트를 받지 않게 한다.
2. 포인터 좌표를 `hitTest`에 넘겨 대상과 영역을 얻는다.

| 영역 | 결과 | 미리보기 |
|---|---|---|
| 탭 바 | 그 위치로 이동·순서 변경 | 삽입 막대 |
| 창의 바깥 25% | 그 방향으로 분할 | 해당 절반 강조 |
| 창의 가운데 | 그 칸의 탭으로 합침 | 창 전체 강조 |
| 앱 창 밖 | SSH면 새 창으로 분리, 그 외는 취소 | 없음 |

- 칸에 탭이 하나뿐이면 자기 칸의 분할·합침은 일어나지 않는다.
- 나눈 뒤 칸이 최소 크기(240×120px)보다 작아지면 가장자리 영역을 가운데로 처리한다.
- `Esc`로 드래그를 취소한다. 드래그 중에만 처리하므로 터미널 입력과 겹치지 않는다.
- 칸의 마지막 탭이 나가면 칸을 지우고 트리를 접는다.
- 700px 이하에서는 포커스된 칸만 표시하고 분할 드롭을 끈다.

키보드 경로:

| 동작 | 입력 |
|---|---|
| 탭 메뉴(분할, 분리, 닫기) | 탭 우클릭, `Shift+F10` |
| 같은 연결로 오른쪽·아래 분할 | 탭 우클릭, `Ctrl/Cmd+Shift+\` (새 연결과 새 셸을 연다) |
| 칸 사이 포커스 이동 | `Ctrl/Cmd+Alt+방향키` |
| 분할선 크기 조절 | 분할선 포커스 후 방향키 |

### 분할선과 PTY 크기

- 칸마다 독립 비율을 갖는다. 더블클릭하면 균등 분할로 돌아간다.
- 끄는 동안 화면은 즉시 움직이되 `fit`은 약 60ms 간격으로만 호출하고 놓을 때 한 번 더 호출한다. 분할선을 끄는 동안 원격에 resize가 쏟아지지 않게 한다.
- 터미널 동작은 건드리지 않으므로 `ssh.rs`, `local.rs`, `podtree.rs`의 ACK와 상한은 변경 없다.

### 저장과 이전

roadmap 3.1의 “레이아웃 저장·배치 복원”을 유지한다. 탭은 재시작 후 복원되지 않으므로 탭을 뺀 **모양과 비율만** `dachsterm.layout`에 저장한다. 재시작하면 빈 칸이 있는 모양을 복원하고, 새 탭이 빈 칸을 앞에서부터 채운다. 탭이 하나도 없으면 시작 화면을 표시한다.

기존 값 `single`, `columns`, `rows`, `grid`는 대응하는 모양으로 변환한다. 읽은 값이 올바르지 않으면 칸 하나로 시작한다.

### 게임과 미리보기

탭의 한 종류로 칸 안에 넣는다. 지금은 게임이 작업 영역 전체를 덮는다. 칸 크기에 맞는지와 일시정지 동작은 TW.2에서 확인하고, 문제가 있으면 게임만 전체 영역을 쓰도록 되돌린다. 서바이버 종료 정산 가드는 유지한다.

## 5. 입력 범위

상태바에 `개별 | 전체 | 선택`을 둔다. 보이는 창이 2개 이상일 때만 표시한다.

```ts
type InputScope = { mode: 'off' } | { mode: 'all' } | { mode: 'pick'; ids: string[] };
```

- **전체:** 보이는 터미널 창 모두가 대상이다. 후보는 화면의 터미널 탭과 `broadcast_status.targets`가 모두 포함하는 연결로 한정한다.
- **선택:** 각 창 탭 바에 “입력 받기” 체크가 나타난다. 2개를 고르는 순간 `broadcast_set`을 호출하고 이후 체크할 때마다 갱신한다. 1개 이하에서는 전달되지 않으며 상태바가 이를 알린다.
- **표시:** 대상 창에 2px 테두리, 상태바 전체 경고색, `동시 입력 중 · N개 창`, `대상 변경`, `중지`.
- **해제:** 지금 규칙을 유지한다. 보이는 창이 바뀌거나 대상 연결이 끊기면 개별로 돌아가고 상태바에 이유를 잠시 표시한다. 새 연결은 자동으로 추가하지 않는다.
- **단축키:** `Ctrl/Cmd+Shift+M`. 동시 입력 중이면 바로 중지하고, 꺼져 있으면 선택 모드만 연다. 실수로 눌러도 입력이 퍼지지 않게 전체 모드로 바로 들어가지 않는다. `Esc`는 터미널에 보내야 하므로 쓰지 않는다.
- **붙여넣기:** 동시 입력 중에는 확인창에 대상 창 수를 함께 표시한다. 여러 창에 여러 줄이 들어가는 사고를 막기 위해서다.

백엔드 `broadcast.rs`는 변경하지 않는다. 대상을 보이는 창으로 한정하는 규칙도 유지한다(roadmap §13). PodTree, FTP처럼 후보가 아닌 탭에는 체크를 표시하지 않는다.

## 6. 조작표 자동 표시

### 표시

상태바 가운데에 핵심 키 5~6개를 표시하고, `전체 보기`를 누르면 기존 `guideKeys` 표를 팝오버로 연다. 프로그램이 끝나면 사라진다. 끄는 버튼은 평소 화면에 두지 않고 앱 설정에서 끈다. 표시 전용이며 키를 보내거나 가로채지 않는 규칙은 그대로다.

### 감지

| 상황 | 동작 | 근거 |
|---|---|---|
| Bash, Zsh에서 vi, vim, less, tail 실행 | 프로그램별 조작표 | 셸 훅의 실행 알림 |
| 그 밖의 전체 화면 프로그램 | “전체 화면 프로그램 실행 중”과 `Shift+드래그`만 표시 | xterm 대체 화면 전환. 이름을 추측하지 않는다 |
| 일반 셸 | 표시 없음 | |
| 사용자가 고정 | 고정한 조작표 | 전체 보기, 탭 우클릭에서 선택 |

- F.1에서 이미 경로 알림 훅을 자동 설치한다(`DirectoryHookInstaller`, 입력 에코 숨김 포함). 실행 알림을 **같은 훅에 합쳐** 수동 복사를 없앤다. 파일을 수정하지 않고 현재 셸 세션에만 적용되는 점은 같다.
- Bash는 기존 `guideHook`의 래퍼 함수를 쓴다. 지금은 별칭이 하나만 있어도 전체를 취소하는데, `alias vi=vim` 같은 흔한 환경에서 전부 꺼지지 않도록 **해당 프로그램만 건너뛴다.**
- Zsh는 `preexec`로 첫 단어만 허용 목록과 비교한다. 지금은 Zsh 조작표 연동이 없다.
- `cat`은 바로 끝나므로 자동 표시에서 뺀다. 수동 선택에는 남긴다.
- `guideEnabled`를 세션별 체크에서 앱 설정(`programGuide`, 기본 켜짐)으로 옮긴다. 기존 `followDirectory`를 끈 사용자에게는 훅을 설치하지 않으므로 이 분기를 합쳐 다시 정한다.

### 자동으로 표시되지 않는 경우

`sudo vim`, `command vim`, 파이프 안의 less, 서버에서 다시 접속한 ssh 안, tmux 안, 훅을 지원하지 않는 셸(Windows PowerShell 포함). 이때 전체 화면 프로그램이면 일반 안내가 나오고, 조작표는 직접 고를 수 있다. tmux는 이후 `pane_current_command`를 `remote_exec`로 조회하는 방법을 검토한다(TW 범위 밖).

### roadmap 규칙 변경

사용자 승인에 따라 roadmap 6.6의 “명시적 opt-in” 전제를 기본 켜짐으로 바꾼다. 셸 파일을 수정하지 않고, 입력 키·명령 인자·이력을 수집하지 않으며, 서버 출력 문자열로 프로그램을 단정하지 않는 규칙은 유지한다. 설정에서 끌 수 있어야 한다.

## 7. 설정

| 위치 | 항목 |
|---|---|
| 앱 설정 → 터미널 (공통) | 글꼴 크기, 스크롤 기록, 선택 시 복사, 우클릭 붙여넣기, Backspace, Option as Meta, 프로그램 상태 표시, 클립보드 쓰기, OS·벨 알림, 경로 따라가기 기본값, 조작표 자동 표시, 에이전트 훅 안내 |
| 세션 폼 (연결별) | 인코딩, tmux 세션, 인증, 점프 호스트 등 현재 항목 유지 |
| 탭 우클릭 (이 창) | 세션 기록, 조작표 고정 |

세션 로그 대화상자의 내용은 이번 범위에서 바꾸지 않는다. 다만 이후 “자동 기록”을 세션 폼으로 옮기는 것은 검토할 만하다. 로컬 터미널에는 세션 폼이 없어 별도 처리가 필요하다.

독립 창에는 앱 설정 대화상자가 없으므로 `TerminalSettings`를 제목 줄 메뉴에서 그대로 연다. 오류는 `session.notice` 대신 대화상자 안에 표시한다.

### 테스트 영향

- 도구 줄의 역할 이름과 선택자(`분할 입력 모드`, `연결 종료`, `터미널 설정`, `.connection-message`, `2 × 2` 등)를 네이티브 스크립트 11개와 `tests/ui`가 사용한다. 해당 UI를 바꾸는 작업에서 함께 고쳐 게이트를 통과한 상태로 다음 작업에 넘어간다. 예를 들어 `2 × 2`는 TW.2, 입력 모드는 TW.5에서 고친다. 접근성 이름은 가능한 한 유지해 수정 범위를 줄인다.

- 네이티브 검사: 실제 연결이 있는 탭을 옮겨도 `connectionId`와 xterm 인스턴스가 유지되는지(`test-workspace-native.mjs`의 `dataset.instance` 방식), 분할선 조절 후 `stty size`가 맞는지 확인한다.
- Windows 파일 드롭과 탭 드래그가 함께 동작하는지 실제 앱에서 확인한다.
- Mac 실기기 대기 항목: WKWebView 탭 드래그와 포인터 캡처, 파일 드롭 공존, IME 조합 중 상태바 변경, `Ctrl+Alt+방향키` 대신 `Cmd+Option+방향키` 동작.

| 메시지 | `role="alert"`는 본문 안에서 빨간 띠, `role="status"`는 보조 글자색. 입력 바로 아래 설명은 `.field-help` |
| 빈 상태 | `.dialog-empty`: 점선 상자 안 한 줄과 필요한 동작 |
| 긴 대화상자 | `.dialog-section`으로 나누고 구역마다 제목과 한 줄 설명을 둔다(세션 기록, 터미널 설정, 세션 일괄 수정) |
| 설정 창 | 왼쪽 분류(테마·터미널·암호 보관함·세션 일괄 수정·가져오기·내보내기·복구·진단), 오른쪽 내용. 설정 안에서 다른 대화상자를 열지 않는다(터미널 설정과 마스터 패스워드를 제자리 패널로 바꿈). 마지막 분류는 `dachsterm.settings.section`에 저장한다. 700px 이하에서는 분류가 위쪽 가로 줄로 바뀐다. 독립 창은 앱 설정이 없으므로 터미널 설정을 같은 패널로 감싼 대화상자를 계속 쓴다 |
| 마스터 패스워드 | 설정 패널(`VaultPanel`)과 연결 전에 묻는 대화상자(`VaultDialog`)가 같은 본문을 쓴다. 세션 폼의 **마스터 패스워드 · 잠금 해제** 버튼은 설정과 겹쳐 뺐고 **저장된 암호 보기**만 남겼다 |
| 파일 작업 대화상자 | 제목을 동작 이름으로(새 폴더, 이름 바꾸기, 3개 항목 삭제, 압축 풀기 등, `fileOperation.ts`). 주 버튼도 만들기·바꾸기·삭제·풀기처럼 동작 이름이고 삭제·덮어쓰기는 빨간 버튼 |
| 파일 패널 | 아래쪽 선택 항목 버튼 줄(원격 7개, 로컬 3개)을 없애고 우클릭 메뉴로 옮겼다. 메뉴에 빠져 있던 다운로드·이름 바꾸기·권한을 넣었다. 위쪽 도구 줄의 복사·잘라내기도 메뉴와 단축키로 옮기고 붙여넣기는 남겼다(선택이 없을 때 쓸 곳) |
| 전송 대기열 | 줄마다 지금 할 수 있는 동작 하나(일시 중지 또는 확인 후 이어서 보내기/받기)와 ⋯. 나머지는 ⋯·우클릭 메뉴. 묶음 버튼은 하나 이상 선택했을 때만 보인다 |
| 터널 목록 | 카드마다 시작·중지 하나와 ⋯. 수정·자동 시작 켜기/끄기·삭제는 메뉴. 자동 시작 체크박스 대신 `자동 시작` 표시. 카드는 `TunnelCard.tsx`, 타입과 종류는 `tunnelConfig.ts`로 떼어 냈다 |
| 상태바 | 로컬 셸은 이름 뒤에 `로컬 셸`/`WSL`만 붙이고, 연결된 뒤의 메시지(`로컬 · 이름`)는 감춘다 |

적용한 대화상자: 새 연결·세션 수정, 인증, 그룹(새 그룹·그룹 수정), 세션 삭제, 로컬 터미널 열기, 키보드 단축키, 설정, 마스터 패스워드, 세션 기록, SSH 터널, 서버 포트 열기, 파일 작업(원격·로컬), 외부 편집기, 명령. PodTree 열기는 진입점이 숨겨져 있어 틀만 바뀌고 내용은 손대지 않았다(KV.12에서 제거).
