# 쿠버네티스 작업 화면 — 설계안

- 작업 ID: **KV.0~KV.12**, 설계일: **2026-11-07**.
- 현재 상태: **설계 완료, KV.0 kind 실측 완료, KV.1 구현.** 상태 정본은 [progress.md](../progress.md), 범위 정본은 [roadmap.md §20](../roadmap.md)이다.
- 관계: [roadmap §16 6.7](../roadmap.md)의 PodTree 내장 후속이다. **PodTree는 기능 레퍼런스로 삼고 앱 화면으로 새로 만든다.** 공용 원격 실행은 [DX.1](developer-workflow.md)을 쓴다.
- 기준 자료: 저장소 코드 `a01efa6`, 내장 스크립트 `podtree.sh` 2.4.0, 사용자의 실사용 요구. kind 클러스터 실측은 [검증 기록](../verification/kubernetes-workspace.md#kv0-실측-2026-11-08)에 있고, 실제 운영 클러스터 결과는 아직 없다. 확정되지 않은 동작은 **KV.0 실측**으로 표시한다. 크기, 시간, 개수 값은 구현 출발점인 제안값이다.
- 기능 이름은 미정이다. 이 문서는 "쿠버네티스 작업 화면"이라 부른다.

## 1. 목표와 경계

**쿠버네티스 세션에 접속하면 파드 트리가 먼저 열리고, `kubectl`을 반복해서 치지 않고 전체 자원, 에러, 재시작, 워커, 인그레스, 로그를 바로 보고 파드에 바로 들어가는 앱**을 만든다.

사용자가 실제로 자주 찾는 정보를 기준으로 삼는다.

| 자주 필요한 것 | 담당 작업 |
|---|---|
| 전체 자원 현황 | KV.3 대시보드 |
| 에러, 재시작된 파드와 사유 | KV.3, KV.7 |
| 서비스·파드별 자원 | KV.2 트리 |
| 워커 수량, 반환되지 않는 워커 | KV.9 |
| 인그레스 상태 | KV.8 |
| 키워드 로그 검색 | KV.5 |
| 파드 터미널 연결, 로그 보기 | KV.4 |

핵심 가치는 **kubeconfig를 PC로 가져오지 않아도 된다**는 점이다. 클러스터 권한이 점프 서버나 폐쇄망 서버에만 있어도 SSH 접속만으로 쓸 수 있고, 서버와 클러스터에 아무것도 설치하지 않는다. **대시보드의 모든 정보는 `kubectl`로 가져올 수 있는 것으로 제한한다.**

| 만든다 | 만들지 않는다 |
|---|---|
| 대시보드, 트리, 필터, 문제 목록, 변화 기록 | CRD·임의 리소스 탐색기 |
| 파드·노드·클러스터 자원, 앱이 켜진 동안의 추세 | 장기 지표 저장, 시계열 DB |
| 워커·스레드·연결 수, 반환 안 됨 판정, vLLM·GPU | 서버나 클러스터에 수집기 설치 |
| 로그 보기, 여러 파드 키워드 검색, 파드 셸, 이벤트, YAML | YAML 편집·적용, Helm, RBAC 관리 |
| 인그레스 구성 점검과 컨트롤러 메트릭 | 인그레스 설정 변경 |
| 파드 삭제, rollout restart, cordon | 임의 `kubectl` 쓰기 명령 UI |
| 앱이 켜진 동안의 알림 | 앱을 꺼도 도는 감시, 여러 클러스터 통합 대시보드 |

새 기능을 판단하는 기준: **"화면에서 눌러 `kubectl`을 대신할 수 있는 일상 작업인가?"** Headlamp 같은 클러스터 관리 도구의 영역이면 넣지 않는다.

| 이 탭은 부모 연결 종료 시 함께 닫히고 정리된다 | `podtree.rs:421,479` | 수명 관리를 재사용한다 |

| `kubectl` 탐지가 `--noprofile --norc`로 실행된다 | `podtree.rs:103,172` | `.bashrc`의 `PATH`, `KUBECONFIG`를 못 찾을 수 있다. 앱 화면은 KV.1에서 고쳤고, 터미널 UI는 진입점이 숨겨져 그대로 둔다(KV.12에서 제거) |

| 수집은 `-o go-template`으로 필요한 필드만 받는다 | `podtree.sh:599-625` | 템플릿을 참고한다. `kubectl`이 서버에서 돌아 SSH로 오는 양이 크게 줄어든다 |
| 대시보드(`D`), 상태판(`w`), 문제 목록(`I`), 변화 기록(`H`), 관계(`v`)가 있다 | `podtree.sh:1347-1361` | 판정 기준의 레퍼런스로 쓴다 |
| Ingress는 구성 정보만 읽는다. 트래픽 수집은 없다 | `podtree.sh:329`, `:1659` | 구성 점검은 옮기고, 메트릭은 새로 만든다(KV.8) |

| 처리 정지는 vLLM만 판정한다(실행 중인데 출력 0 tok/s) | `podtree.sh:2511` | 판정 방식을 일반 워커로 넓힌다(KV.9) |
| **스레드 수 수집은 없다** | `podtree.sh` 전체 검색 | 새로 구현한다(KV.9) |
| vLLM·GPU는 `get --raw` proxy로 수집하며 기본 조회 모드에서 꺼져 있다 | `podtree.sh:2130`, `user-guide.md` | 허용 경로의 읽기만 조회 모드에서 연다(KV.10) |
| `session.ts` 399줄, `podtree.rs` 상한 초과, `App.tsx` 순증 금지 | `engineering-rules §4` | 새 파일로 분리하고 기존 터미널 분기를 늘리지 않는다(§3.3) |

## 3. 구조

### 3.1 세션과 화면

`Profile`에 추가한다. `serde(default)`이므로 DB 스키마 변경은 없다.

```ts
workspace: 'terminal' | 'kubernetes'; // 기본 terminal
kube?: {              // 첫 접속의 탐지가 채운다. 없으면 탭 안에서 KV.1 설정을 먼저 보여 준다
  context: string;     // 전역 current-context를 쓰거나 바꾸지 않는다
  namespace: string;   // 빈 값은 전체
  kubectl: string;     // 탐지 또는 사용자 입력 명령
  kubeconfig: string;  // 서버의 경로. 내용은 읽거나 저장하지 않는다
  operate: boolean;    // 기본 false
};
```

- 세션 폼에 **접속 후 화면**(터미널 / 쿠버네티스)을 둔다. 저장할 때는 종류만 고른다. 서버가 꺼져 있어도 저장할 수 있게 탐지와 context 선택은 **첫 접속 때 탭 안에서** 한다(사용자 결정 2026-11-08).
- 세션 JSON v3은 바꾸지 않는다. 내보내기와 가져오기에서 `workspace`, `kube`를 기본값으로 되돌린다. 가져온 파일이 운영 모드를 켜는 경로를 막기 위해서다. `tmuxSession`과 같은 규칙이다([DX §3.2](developer-workflow.md)).

**접속 흐름:** 일반 SSH 연결과 같이 인증·호스트키를 거친 뒤 탭에 **트리**를 표시한다(사용자 결정 2026-11-08). 탭 안 메뉴로 화면을 전환하고, 세션마다 마지막에 본 화면을 기억한다. 셸 PTY는 숨겨져 살아 있으므로 전환해도 상태가 유지된다.

**진입점:**

- 연결 트리에서 쿠버네티스 세션을 연다. 트리에서는 아이콘으로만 구분한다.
- 이미 터미널로 접속 중이면 **탭 헤더 우클릭 → 쿠버네티스 화면 열기**. 지금 연결을 그대로 쓰고 세션을 고치거나 다시 접속하지 않는다.
- SSH 없이 쓰는 경우는 연결 트리의 **로컬 클러스터**(KV.11).

- `app/SessionPane.tsx`가 `TerminalPane`과 `KubeWorkspace` 표시를 고른다. `Tab`을 옮겨 만든 `App.tsx` 예산 안에서 연결한다.
- 분할 화면에서는 일반 패널처럼 동작한다. 1차에서 독립 창 분리는 끈다.
- 쿠버네티스 세션에서는 경로 따라가기 훅을 설치하지 않는다. 숨겨진 셸에 글자를 입력하지 않기 위해서다.

```text
┌ 탭: prod-bastion ─────────────────────────────────────────────────┐
│ [트리][대시보드][인그레스][로그 검색][서버 터미널]  prod · 조회 모드 · 5초 전 │
├───────────────────────────────────────────────────────────────────┤
│ CPU  ▓▓▓▓▓░░░ 62% 요청 78%  메모리 ▓▓▓▓░░░░ 51%   노드 5/5   파드 241 │
├ 재시작·에러 ─────────────────┬ 자원 상위 ───────────────────────────┤
│ ✕ api-2b1d  OOMKilled 12분 전 │ gpu-worker-1   3.2 CPU  14Gi          │
│ ! batch-9  재시작 +3  1시간 내 │ api-7f9c       420m     512Mi         │
├ 워크로드·인그레스 ───────────┼ 워커 ────────────────────────────────┤
│ ! api 2/3 준비               │ api  사용 8/8 · 12분째 반환 없음 ⚠     │
│ ! ing/shop 백엔드 준비 0     │ web  사용 2/8                          │
├ 최근 경고 ───────────────────┴──────────────────────────────────────┤
│ 12분 전  BackOff  web/api-2b1d  Back-off restarting failed container │
└───────────────────────────────────────────────────────────────────┘
```

위는 대시보드 화면이고, 첫 화면인 트리는 KV.2에 있다. 각 항목을 누르면 해당 파드, 워크로드, 인그레스의 상세로 이동한다.

### 3.3 파드 셸과 로그 탭

기존 PodTree PTY 경로를 일반화한다. `TerminalSession`의 분기를 늘리지 않는다(규칙 §7).

```rust
enum Launch {
    Script { location, context, namespace, operational }, // KV.12 전까지 유지
    PodShell { connection, kube, namespace, pod, container },
    PodLogs { connection, kube, namespace, pod, container, tail, previous },
}
```

- `stage`(스크립트 배치)는 `Script`만 수행한다. 나머지는 고정 명령을 바로 실행한다.
- 셸: `kubectl exec -it <파드> -n <ns> -c <컨테이너> -- sh -c 'command -v bash >/dev/null 2>&1 && exec bash || exec sh'`. 원본(`podtree.sh:3252`)과 같다.
- 실시간 따라가기: `kubectl logs -f --tail=500`. 터미널 검색, 복사를 그대로 쓴다. 평소 로그 보기는 터미널 탭이 아니라 트리 옆 패널이다(KV.4).
- 기존 탭 상한 16개를 공유한다. 멀티 입력, 스니펫, 세션 로그, 창 분리에서 제외되는 기존 규칙도 유지한다.
- 이 작업에서 `podtree_*` 명령을 `kube_terminal_*`로 바꾼다(규칙 §5의 이름 규칙). 네 곳과 `permissions/autogenerated`를 함께 수정한다. `podtree.rs`는 순증 없이 고치고 `launch.rs`로 옮긴다.

### KV.1 — kubectl 찾기와 세션 연결

**이 작업은 기존 터미널 UI의 실행 문제도 함께 고치므로 다른 KV보다 먼저 한다.**

탐지는 세션 저장이나 첫 연결 때 한 번만 한다.

1. 현재 환경의 `command -v kubectl`.
2. 없으면 `"$SHELL" -lic`로 사용자 환경에서 `command -v kubectl`과 `$KUBECONFIG`를 읽는다. rc 출력이 섞일 수 있으므로 표식 뒤만 파싱한다(DX.1).
3. 그래도 없으면 잘 알려진 위치를 확인한다. `kubectl`은 `/var/lib/rancher/rke2/bin/kubectl`, kubeconfig는 `~/.kube/dachsterm.config`, `~/.kube/config`, `/etc/rancher/rke2/rke2.yaml`, `/etc/rancher/k3s/k3s.yaml`, `/etc/kubernetes/admin.conf` 순서다.
4. 찾은 **절대 경로**와 kubeconfig **경로**를 저장한다. 이후 호출은 rc 파일을 읽지 않아 빠르고 결과가 일정하다.
5. 찾지 못하면 사용자가 입력한다. `microk8s kubectl` 같은 두 단어 명령을 허용하되, 셸 메타문자는 거부한다.

호출은 항상 `KUBECONFIG=<경로> <kubectl> --context <이름> --request-timeout=8s ...` 형식이다. 전역 current-context를 쓰거나 바꾸지 않는다.

**탐지 구현(KV.0 결과):** 2단계 명령에는 `</dev/null`을 붙인다. `remote_exec.rs`가 채널에 EOF를 보내지 않아 rc 안의 `read`가 그대로 멈추기 때문이다. 앞뒤 표식 사이만 읽고 stderr는 무시하며, 끝 표식이 없으면 실패로 보고 다음 단계로 넘어간다.

**상태 판별(KV.0 결과):** `kubectl`은 대부분 종료 코드 1이므로, 먼저 kubeconfig에 `test -e`, `test -r`을 실행해 **없음**과 **읽을 수 없음**을 종료 코드로 가른다. 파일이 없을 때 `KUBECONFIG`를 그대로 넘기면 `localhost:8080` 연결 거부라는 엉뚱한 오류가 나오기 때문이다. 나머지는 klog 줄(`[EWIF]숫자4개 `로 시작)을 버린 stderr 마지막 줄로 판단한다.

| 마지막 줄 | 상태 | 화면 |
|---|---|---|
| `You must be logged in to the server` | 인증 실패 | 복사본이 낡았을 수 있다는 안내와 복사 버튼 |
| `Error from server (Forbidden)` | 권한 없음 | 그 항목만 비우고 이유 표시 |
| `context was not found` | context 없음 | context 다시 선택 |
| `was refused`, `Unable to connect to the server` | 클러스터 연결 불가 | 마지막 데이터 유지, 몇 초 전인지 표시 |

이 분류는 외부 프로그램의 출력을 읽는 유일한 함수에 두고 enum으로 돌려준다(규칙 §6). 실측 문구를 단위 테스트 입력으로 쓴다.

API 서버가 응답하지 않으면 `--request-timeout=8s`를 줘도 재시도 때문에 약 36초 걸린다. 이 인자에 의존하지 말고 앱 쪽 전체 시간 상한을 둔다(KV.2).

**권한(사용자 결정 2026-11-08):** 앱의 조건은 **접속한 계정으로 `kubectl`이 실행되는 것** 하나다. root, `sudo` 계정, 일반 계정을 구분하지 않고 앱은 `sudo`를 실행하지 않으며 `sudo`·root 암호를 받거나 보관하지 않는다. 앱이 `sudo`를 직접 쓰면 NOPASSWD, 암호 입력, `requiretty`마다 경로가 갈리고 암호 보관과 틀린 암호의 계정 잠금 방지가 필요해지기 때문이다.

kubeconfig를 읽을 수 없으면 탭에 안내를 보여 준다.

1. "이 계정은 쿠버네티스 설정을 읽을 수 없습니다"와 **터미널에서 설정 복사** 버튼, root로 접속하는 다른 방법을 표시한다. 대부분의 `sudo` 계정은 root 암호를 모르고 OpenSSH 기본값도 root 암호 로그인을 막으므로 복사를 먼저 보여 준다.
2. 버튼을 누르면 탭을 `서버 터미널`로 바꾸고 다음 명령을 입력한다. `sudo` 암호는 사용자가 터미널에 직접 입력한다. 셸이 프롬프트 상태가 아니면 버튼을 막는다(`gitTerminal.ts`와 같은 판단).

   ```sh
   mkdir -p ~/.kube && sudo install -m 600 -o "$(id -u)" -g "$(id -g)" <kubeconfig 경로> ~/.kube/dachsterm.config
   ```

3. **다시 확인**을 누르면 탐지를 다시 하고 `~/.kube/dachsterm.config`를 세션에 저장한다. 이후로는 일반 계정 경로와 같다.

자동 실행하지 않고 버튼으로 두는 이유는 클러스터 관리자 인증 정보가 홈 폴더에 파일로 남기 때문이다. 기존 `~/.kube/config`를 덮어쓰지 않게 전용 파일을 쓴다. 서버와 계정 조합마다 한 번이면 되고, 인증서 갱신이나 클러스터 재설치로 복사본이 낡으면 인증 실패로 판별해 같은 안내를 다시 보여 준다.

기존 터미널 UI(`podtree/launch.rs`, `PodTreeDialog.tsx`)는 고치지 않는다. TW.9에서 진입점을 숨겨 화면에서 열리는 경로가 없고 KV.12에서 제거하기 때문이다(사용자 결정 2026-11-08).

**구현에서 정한 것(KV.1):**

- **저장된 세션의 확인:** 다시 탐지하지 않고 저장된 경로로 `get namespaces`까지 확인한다(rc를 읽지 않는다). 인증 실패, context 없음, kubeconfig 없음·읽기 불가면 설정 화면을 다시 보여 주고, 클러스터 연결 불가면 화면을 열고 헤더에 표시한다.
- **복사본 우선:** `$KUBECONFIG`가 root 전용 파일을 가리켜도 읽을 수 있는 `~/.kube/dachsterm.config`가 있으면 그것을 쓴다. 안 그러면 복사 뒤에도 같은 안내가 반복된다. `kubectl`과 `$KUBECONFIG` 중 하나만 없어도 2단계를 실행한다.
- **지나갈 수 없는 폴더:** kubeconfig의 상위 폴더에 들어갈 수 없으면 `test -e`가 없음을 내므로(KV.0 미확인 항목) 읽기 불가로 본다.
- **복사 명령 입력:** 프롬프트를 보고하는 셸은 Enter까지 친다. 쿠버네티스 세션의 숨은 셸은 훅이 없어 상태를 모르므로(§3.1) 명령만 넣고 사용자가 Enter를 누른다. 전체 화면 프로그램이 돌면 막는다. 판단은 `features/terminal/shellReadiness.ts`로 옮겨 `gitTerminal.ts`와 함께 쓴다.
- **탭 헤더 우클릭으로 연 화면:** 세션을 고치지 않으므로(§3.1) 고른 context는 저장하지 않고 그 탭이 열려 있는 동안만 쓴다. `kube_save`는 쿠버네티스 세션만 받는다.
- **다시 확인 후 시작:** context가 하나면 바로 저장하고 화면으로 들어간다. 여럿이면 고르게 한다.
- **`MaxSessions`:** `remote_exec::run_refusable`이 채널 거부를 `Refusable::ChannelRefused`로 돌려주고 `KubeState::ChannelLimit`이 된다. 앱의 russh 경로 실측은 [검증 기록](../verification/kubernetes-workspace.md#kv1-앱-검증-2026-11-08)에 있다.
- **검사 환경:** `scripts/kube-fixture.sh`(`npm run kube:fixture -- <클러스터> [up|down|status]`), 합격 시나리오는 `scripts/verify-kube-detect.mjs`(`npm run test:kube-detect`).

**합격:** `.bashrc`에만 `PATH`, `KUBECONFIG`가 있는 서버에서 동작한다. 첫 접속에서 설정을 마친 세션은 다음 접속부터 바로 화면이 열린다. root 전용 kubeconfig 서버에서 복사 버튼과 다시 확인으로 대시보드까지 들어간다.

### KV.2 — 트리와 상태

**조회(`kube_snapshot`):**

| 데이터 | 명령 | 주기 |
|---|---|---|
| 파드 | `get pods` go-template | 5초. 다음 조회는 이전 조회가 끝난 뒤 `max(5초, 소요 시간 × 3)` 뒤에 한다 |
| 워크로드 | `get deployments,statefulsets,daemonsets` | 15초 |
| 서비스 | `get services,endpoints` | 30초 |
| 노드 | `get nodes` | 15초 |
| 사용량 | `top pods`, `top nodes` | 15초. metrics-server가 없으면 요청량·제한만 표시 |
| 경고 이벤트 | `get events --field-selector type=Warning` | 15초 |

- 작업 화면이 보일 때만 조회한다. 탭이 숨겨지면 멈추고, 다시 보이면 바로 갱신한다(예외: KV.7 알림을 켠 세션). 종류별 동시 요청은 1개다(규칙 §7).
- 동시 원격 실행은 연결당 3개로 제한한다(로그 검색은 별도 상한). 출력 32MiB, 시간 20초가 상한이다. 초과하면 namespace를 좁히도록 안내하고 주기를 늘린다. KV.0에서 파드 5,115개는 3.75MB, 약 6초였다(네트워크 지연 없음, 시간 10초는 여유가 부족해 20초로 올렸다). 전체 namespace 조회는 `-o json`을 쓰지 않는다(65.8MB).
- `MaxSessions` 기본값 10은 **셸, SFTP, 모니터링, Git 상태, 조회, 로그 검색, 파드 탭이 나눠 쓰는 한도**다. 채널을 열 수 없으면 조회는 다음 주기로 미루고, 파드 탭과 로그 검색은 서버의 동시 세션 한도 때문이라고 안내한다.
- 실패해도 마지막 데이터를 유지하고 **몇 초 전 데이터인지** 표시한다. 오래된 값을 현재 값처럼 보이지 않게 한다. 권한 없는 항목은 그 항목만 비운다.
- 서버 문자열은 일반 텍스트로만 표시한다. 명령 인자로 다시 쓰는 이름은 쿠버네티스 이름 규칙으로 검증한다.

**표시:**

```text
┌ prod-bastion ─ [트리] 대시보드 인그레스 로그 검색 서버 터미널    prod · 조회 모드 · 3초 전 ┐
│ / api !batch_                                                        12 / 241개 │
│ ▸ 노드                         5/5 준비                                         │
│ ▾ shop                         준비  재시작   CPU  메모리  노드    워커         │
│   ▾ Deployment/api              2/3       4   820m  1.5Gi          사용 8/8 ⚠   │
│     ✓ api-7f9c                  1/1       0   420m  512Mi  gpu-1                │
│   > ✕ api-2b1d  OOMKilled       0/1      +3      -      -  gpu-2                │
│   ▸ StatefulSet/redis           3/3       0   310m  1.1Gi                       │
│ ▸ 단독 파드                                                                     │
└ ↑↓ 이동  ←→ 접기  / 필터  Enter 로그  s 셸  e 이벤트 ──────────────────────────┘
```

- 묶기: `namespace > 워크로드 > 파드`(기본, 사용자 결정 2026-11-08), `namespace > 서비스 > 파드`, `노드 > namespace > 파드`. 키 하나로 전환한다. 어느 클러스터에서나 같게 나오도록 소유자(`ownerReferences`)로 묶는다. 소유자가 ReplicaSet이면 `pod-template-hash` 라벨을 떼어 Deployment 이름을 구하고, 소유자가 없으면 "단독 파드"에 둔다. 서비스 묶기는 Service selector와 파드 label로 하고, 어디에도 속하지 않는 파드는 "서비스 없음"에 둔다. 한 파드가 여러 서비스에 속하면 각각 표시한다.
- **노드:** 기본 트리 맨 위에 "노드" 그룹을 둔다. 준비 수를 보여주고 펼치면 노드별 상태, 자원, 파드 수를 표시하며, NotReady 노드가 있으면 펼친 채로 시작한다. 파드 행에는 노드 이름을 표시한다. `get nodes`로 이미 받는 값이라 조회가 늘지 않는다.
- **앱 워커:** 워커 감시를 켠 워크로드의 행에 `사용 8/8`을 표시하고, 판정이 "의심"이면 표시를 더한다(KV.9). 파드 전체를 주기 조회하지 않는다.
- 행: 상태 글자·기호, 준비 수, 재시작(최근 증가 강조), CPU, 메모리, 노드, 나이. 그룹 행은 파드 값의 합계를 보여준다. 색만으로 구분하지 않고 `status` 토큰을 쓴다.
- 필터: 입력 즉시 적용. 공백은 AND, `!단어`는 제외. **문제만**은 비정상, 최근 1시간 재시작, OOMKilled를 모은다.
- `role="tree"`, 5,000행 가상화. 접힘 상태와 묶기 방식은 세션별로 `dachsterm.*`에 저장한다.

**조작(사용자 결정 2026-11-08):** 기존 터미널 UI의 키 흐름을 유지하고 마우스로도 같은 일을 한다. 키보드와 마우스는 같은 선택 위치를 쓴다. 행마다 버튼을 넣지 않고 대상별 조작은 우클릭 메뉴에 둔다.

| 동작 | 키보드 | 마우스 |
|---|---|---|
| 선택 | `↑↓`, `j/k` | 클릭 |
| 접기·펴기 | `←→`, `h/l` | `▸` 클릭 |
| 필터 | `/`, `Enter`나 `↓`로 결과로 이동 | 입력창 클릭 |
| 파드 로그 | `Enter` | 더블클릭 |
| 셸, 이벤트, 상세 | `s`, `e`, 우클릭 메뉴 | 우클릭 메뉴 |
| 정렬 | | 열 제목 클릭 |
| 로그 패널 크기 | | 경계선 끌기 |
| 패널 닫기 | `Esc` | 닫기 표시 클릭 |

- 키는 트리에 포커스가 있을 때만 동작해 터미널 입력과 겹치지 않는다. 한글 입력 상태에서도 동작하도록 글자(`event.key`)가 아니라 물리 키(`event.code`)로 판단한다.
- 그룹 행의 `Enter`는 접기·펴기다.
- 로그나 셸에서 돌아와도 필터와 선택 위치를 유지한다.

**구현에서 정한 것(KV.2):**

- **`kube_snapshot` 입력:** 연결 ID, 종류와 함께 검증한 설정을 받는다. 탭 헤더 우클릭으로 연 터미널 세션은 고른 context를 저장하지 않기 때문이다(§3.1). 사용량은 `podUsage`, `nodeUsage`로 나눠 종류는 7개다.
- **동시 3개:** 연결별 세마포어(`kube/slots.rs`)가 지키고 조회 시간은 슬롯을 얻은 뒤부터 잰다. 다음 조회 간격은 서버에서 걸린 시간(`elapsedMs`)으로 계산한다.
- **요청 시간:** 조회의 `--request-timeout`은 18초다. 설정 확인의 8초를 그대로 쓰면 큰 목록이 앱 상한 20초에 닿기 전에 끊긴다. 앱 상한에 걸리면 `TimedOut`, 출력이 32MiB를 넘으면 `TooLarge`로 구분하고 안내한 뒤 주기를 4배(최대 2분)로 늘린다.
- **탐지와의 구분:** 설정 확인은 시간 초과를 계속 `Unreachable`로 본다. 목록이 거의 없어 시간 초과는 곧 연결 불가이기 때문이다. `metrics-server`가 없으면 `MetricsMissing`으로 분류한다.
- **조회 범위:** 탭과 앱 창이 보이고 작업 화면이 표시될 때 화면 종류와 무관하게 조회한다. KV.3이 같은 스냅샷을 쓴다.
- **파일:** `tree.ts`가 커져 파드 판정과 필터는 `treePods.ts`, 표시 형식은 `treeFormat.ts`, 키 판단은 `treeKeys.ts`, 행 그리기는 `KubeTreeRow.tsx`로 나눴다. 첫 화면 기억은 `screenPref.ts`, 응답 타입은 `snapshotTypes.ts`, 조회 훅은 `useKubeSnapshots.ts`다.
- **묶기 전환 키:** `g`로 워크로드 → 서비스 → 노드를 돌린다. 도구 줄의 선택 상자도 유지한다.
- **단독 파드:** namespace 아래에 둔다. 다른 namespace의 같은 이름 파드를 한 곳에 섞지 않기 위해서다.
- **노드 그룹:** 묶기가 노드일 때와 검색어가 있을 때는 숨긴다. **문제만**에서는 NotReady 노드가 있을 때만 보인다. 모두 Ready이면 접혀 있고 NotReady가 있으면 펼친다. 접기·펴기 기억은 두 경우를 따로 저장해, 정상일 때 접어 둔 것이 나중의 NotReady를 가리지 않는다.
- **정렬:** 숫자 열은 처음 누르면 큰 값부터, 이름과 노드는 가나다순이다. 값을 모르는 행은 어느 방향이든 아래에 두고, "서비스 없음" 같은 묶음은 항상 끝에 둔다. 정렬은 저장하지 않는다.
- **선택 유지:** 필터, 문제만, 선택, 정렬은 작업 화면이 보관해 서버 터미널이나 다른 화면에 다녀와도 남는다. 선택한 파드가 사라지면 같은 위치의 행을 고른다.
- **포커스:** 트리가 열리거나 칸이 포커스를 받으면 트리에 포커스를 준다. 키가 트리에 포커스가 있을 때만 동작하기 때문이다.

### KV.3 — 대시보드

트리 옆 화면이다. KV.2 스냅샷에서 계산하므로 별도 조회를 늘리지 않는다. 비어 있는 항목은 숨기지 않고 "문제 없음"으로 표시한다.

| 영역 | 내용 | 출처 |
|---|---|---|
| **전체 자원** | CPU·메모리의 사용량, 요청량, 할당 가능량. 노드별 막대 | `top nodes`, 파드 requests/limits, 노드 allocatable |
| **현황** | 노드 준비 수, 파드 상태별 수, 워크로드 준비 수 | `get nodes,pods,deployments...` |
| **재시작·에러** | 최근 재시작 파드, 사유(`OOMKilled`, 종료 코드), 마지막 시각, 앱 시작 후 증가 수. 비정상 상태 파드 | `containerStatuses.lastState`, `restartCount` |
| **자원 상위** | CPU, 메모리 상위 10개와 제한 대비 비율 | `top pods` |
| **미달 워크로드** | 준비 수가 부족한 Deployment, StatefulSet, DaemonSet | 워크로드 상태 |
| **인그레스** | 이상 있는 항목(KV.8) | 인그레스 조회 |
| **워커** | 점유율, 반환 안 됨 의심(KV.9) | 설정한 대상만 |
| **최근 경고** | 최근 10분 Warning 이벤트 | `get events` |

- 추세는 앱이 켜진 동안의 표본(최대 120개)만 메모리에 둔다. 차트는 기존 모니터링 코드를 재사용한다.
- metrics-server가 없으면(`error: Metrics API not available`) 사용량 대신 요청량과 할당량을 표시하고 이유를 밝힌다.
- 집계와 정렬은 `dashboard.ts`의 순수 함수로 두고 단위 테스트한다.

**구현에서 정한 것(KV.3):**

- **파일:** 집계는 `dashboard.ts`, 표본과 재시작 기준값은 `dashboardHistory.ts`, 경고 목록은 `dashboardWarnings.ts`(400줄 상한 때문에 나눔), 트리 이동 계획은 `treeReveal.ts`다. 모니터링의 차트는 기능 간 import 금지(규칙 §7)에 따라 `components/MetricChart.tsx`로 내려 함께 쓴다. CSS는 `kubeDashboard.css`다.
- **조회:** 새 명령과 kubectl 호출은 없다. 파드 템플릿에 `lastState.terminated.exitCode` 필드만 더했다(`lastExitCode`). 표본과 재시작 기준값은 화면과 무관하게 스냅샷이 도착할 때 갱신하므로 트리를 보는 동안에도 쌓인다.
- **"문제 없음"과 "모름"의 구분:** 목록이 비면 "문제 없음", 권한이 없거나 아직 못 받은 항목은 그 이유를 표시한다. 오래된 데이터를 유지 중이면 화면 위에 알린다.
- **요청량:** 노드에 배치됐고 끝나지 않은 파드만 합한다(스케줄러가 자리를 잡아 두는 기준). namespace를 정한 세션은 요청량이 그 namespace 분뿐이므로 그렇게 표시한다. 노드와 할당량은 항상 클러스터 전체다.
- **재시작·에러 목록:** 트리의 **문제만**과 같은 파드에 이 탭을 연 뒤 재시작이 늘어난 파드를 더한다. 첫 스냅샷의 재시작 수를 기준으로 삼고, 나중에 나타난 파드는 전부 증가로 친다. 수가 줄면 같은 이름의 새 파드로 본다. 표본과 기준값은 탭이 열려 있는 동안만 메모리에 둔다.
- **metrics-server 없음:** 자원 상위는 요청량 기준으로 바꿔 그렇게 표시한다. 추세 그래프는 숨기고 이유를 표시한다.
- **목록 상한:** 재시작·에러, 미달 워크로드, 경고, 노드는 30개까지 보여 주고 "외 N개"를 표시한다. 전체는 트리에 있다.
- **트리로 이동:** 파드는 지금 묶기를 유지한다. 워크로드 행은 워크로드 묶기에만 있으므로 그 묶기로 바꾼다. 노드는 맨 위 노드 그룹을 열거나, 노드 묶기면 그 그룹을 고른다. 대상을 가리는 필터만 지우고, 접힌 상위 그룹을 편다. 이미 사라진 파드나 파드가 없는 워크로드는 해당 namespace로 간다. 상세(KV.4)가 생기면 여기서 상세를 여는 동작을 더한다.
- **인그레스, 워커:** 인그레스는 KV.8에서 `IngressPanel.tsx`로 연결했다. 워커는 자리만 있고 KV.9에서 `KubeDashboard.tsx`의 주석 위치에 연결한다.

### KV.4 — 상세, 로그, 파드 셸

- **개요:** 상태, 노드, IP, 컨테이너별 이미지·재시작·마지막 종료 사유, 요청량·제한 대비 사용량, 추세.
- **이벤트:** 선택 항목의 이벤트.
- **YAML:** `get -o yaml` 읽기 전용, 검색, 복사. 환경 변수에 비밀이 있을 수 있으므로 저장하지 않는다. Secret 리소스 값은 어떤 화면에서도 조회하지 않는다.
- **관계:** Service, Endpoints(로테이션 포함 여부), Ingress, NetworkPolicy, PVC, ConfigMap 이름.
- **장애 원인(사용자 요청 2026-11-08):** 문제 파드는 한 화면에 사유·종료 코드·시각, 관련 이벤트, 직전 인스턴스 로그 마지막 100줄을 모아 보여준다. `kube_detail`과 `logs --previous --tail=100`으로 얻는다. 직전 인스턴스가 없으면 현재 로그를 보여준다.
- **로그:** 트리의 `Enter`나 더블클릭으로 **트리 옆 패널**에 연다. 탭을 새로 만들지 않고, 키워드 필터와 직전 인스턴스 전환을 둔다. `Esc`로 닫으면 커서는 그 파드에 있다. 실시간 따라가기만 터미널 탭(§3.3)으로 연다.
- **셸:** `s`나 우클릭 메뉴로 탭을 연다. 기존 SSH 연결에 채널을 추가하므로 OTP를 다시 묻지 않는다. `exit`하면 탭이 닫히고 트리의 같은 파드로 돌아간다. 탭 제목에 context와 파드 이름을 표시한다.
- **조회 모드에서도 셸을 연다.** 사용자가 직접 연 터미널이고 안에서 할 수 있는 일은 RBAC가 결정한다. 조회 모드가 막는 것은 앱의 쓰기 동작(KV.6)이다.
- **컨테이너:** 여럿이면 `kubectl.kubernetes.io/default-container`를 따르고, 없으면 고르게 한 뒤 마지막 선택을 기억한다.
- **재시작:** 파드가 사라져 셸이 끊기면 같은 워크로드의 새 파드로 다시 접속할지 묻는다. 명령을 재실행하지 않는다.

**구현에서 정한 것(KV.4):**

- **범위:** 상세 패널은 파드만 다룬다. 워크로드·노드 행의 상세와 이벤트는 만들지 않았다. 개요의 추세는 패널이 열려 있는 동안 받은 표본만 그린다.
- **셸을 열기 전 확인:** 탭을 먼저 열면 실패할 때 바로 닫히는 탭이 된다. 그래서 `kube_terminal_probe`(§5에 없던 명령)로 컨테이너 안에서 `sh -c 'exit 0'`을 실행하고, 셸 없음·컨테이너 정지·`pods/exec` 권한 없음·채널 거부를 트리 옆 한 줄로 알린다.
- **종료 판정:** kubectl의 종료 코드로는 사용자의 `exit 3`과 끊김을 구분하지 못한다(파드를 지우면 137). 셸이 끝나면 `kube_detail`로 파드를 다시 읽어 uid, `deletionTimestamp`, 컨테이너 ID를 열 때와 비교한다. 같은 파드면 탭을 닫고 트리로 돌아가고, 사라졌거나 컨테이너가 바뀌었으면 끝난 카드의 **재접속**으로 묻는다. 2초 안에 실패하면 시작하지 못한 것으로 보고 안내를 남긴다. 파드 조회 자체가 거부되면 부모 연결이 끝난 것이므로 탭을 정리한다.
- **재접속:** 같은 탭에서 대상 파드를 바꾸므로 탭 위치가 유지된다. 파드 목록을 새로 조회해 같은 워크로드의 준비된 파드 중 가장 새것을 고른다. `ownerOf`로 비교하므로 롤아웃으로 ReplicaSet이 바뀌어도 같은 워크로드다. StatefulSet은 이름이 같아 생성 시각으로 구분한다.
- **`--previous`의 두 가지 없음:** 이전 인스턴스가 없으면 `BadRequest`로 실패한다. 재시작 대기 중이면 kubelet이 이미 정리해 **stdout에 `unable to retrieve container logs for`가 찍히고 종료 코드는 0**이다(KV.4 실측). 둘 다 "직전 인스턴스 없음"으로 보고 현재 로그를 보여 준다.
- **`Launch`:** §3.3의 `PodLogs`에서 `previous`를 뺐다. 따라가기는 항상 현재 인스턴스이기 때문이다. 스트림에는 `--request-timeout`을 붙이지 않고 명령은 `sh -c`로 감싼다.
- **필드 이름:** 프런트의 `session.podtree`는 이름을 유지했다. 쓰는 파일이 많고 `Script` 경로를 지우는 KV.12에서 함께 정리하는 편이 낫다.
- **검사:** `scripts/verify-kube-detail.mjs`(`npm run test:kube-detail`).

### KV.5 — 키워드 로그 검색

여러 파드의 로그를 앱 화면에서 검색한다. 입력은 **범위, 시간, 키워드**이고 결과는 표로 나온다.

| 입력 | 내용 |
|---|---|
| 범위 | 파드, 서비스, 워크로드, namespace. 트리나 대시보드에서 바로 시작할 수 있다 |
| 시간 | 최근 15분(기본), 1시간, 6시간, 24시간, 직접 입력(`--since`) |
| 키워드 | 공백은 AND, `!단어`는 제외, 대소문자 무시. 정규식은 1차에서 뺀다 |
| 옵션 | 컨테이너 전체, 이전 인스턴스 포함, 앞뒤 N줄 |

**실행:** 파드별로 서버에서 거르므로 전체 로그를 SSH로 받지 않는다.

```sh
kubectl logs <파드> -n <ns> -c <컨테이너> --since=15m --timestamps | grep -aiF -- <키워드> | head -n 1000
```

- 키워드는 인용 함수를 거치고 `--` 뒤에 둔다. 단어가 여럿이면 `grep`을 잇고, 제외는 `grep -v`를 쓴다.
- 상한: 파드 100개, 동시 4개, 파드당 1,000줄, 결과 전체 5,000줄, 전체 시간 60초. 상한에 걸리면 **결과가 잘렸음을 표시**한다. 파드별 실패는 전체를 멈추지 않고 표시한다.
- 결과는 도착하는 대로 표시하고 언제든 취소할 수 있다. 취소하면 원격 채널을 닫는다.
- 표: 시각, 파드, 컨테이너, 강조된 줄. 시각순 정렬, 파드별 묶기, 복사. 줄을 누르면 해당 시각 주변의 로그를 보여준다.
- 저장은 사용자가 위치를 골랐을 때만 한다. 결과는 메모리에만 두며 세션 로그와 진단 내보내기에 넣지 않는다.
- **실시간 따라가기:** 터미널 탭에서 `kubectl logs -f | grep --line-buffered`를 연다. 여러 파드 합치기는 후속이다.
- `kube_log_search`는 고정 명령에 범위와 키워드만 넣어 조립한다. 임의 파이프를 받지 않는다.

**구현에서 정한 것(KV.5):**

- **범위 계산:** 트리가 조회해 둔 파드 목록으로 화면에서 계산해 파드와 컨테이너 이름을 넘긴다. Rust는 이름 규칙과 파드 100개 상한을 다시 확인한다. 아직 시작하지 않은 파드(`Pending`)는 로그가 없으므로 뺀다.
- **기본 컨테이너:** 스냅샷의 파드 템플릿에 `defaultContainer`(annotation, 없으면 spec 첫 컨테이너)를 더했다. 스냅샷의 컨테이너 목록은 status 순서라 spec 순서가 아니고, `-c` 없이 실행하면 결과에 컨테이너 이름을 표시할 수 없기 때문이다. **이전 인스턴스**는 `restartCount`가 있는 컨테이너만 읽는다.
- **종료 코드:** 파이프라인의 종료 코드는 `head`의 것이라 kubectl 실패를 알 수 없다. kubectl의 종료 코드를 stderr 끝에 전용 줄로 내보내 `classify`에 넘긴다. `head`가 닫아 생긴 SIGPIPE(141)는 성공으로 본다.
- **취소:** 채널을 닫아도 PTY가 없으면 kubectl은 stdout에 쓸 때까지 끝나지 않고, 일치가 없으면 쓰지도 않는다. 채널의 stdin이 닫히면 `cat`이 끝나고 그 kubectl만 `kill`하는 감시를 스크립트에 넣어 서버의 작업까지 멈춘다. 프로세스 그룹 전체에 시그널을 보내지 않으므로 서버의 세션 구조에 의존하지 않는다.
- **시각과 검색어:** `--timestamps`가 붙은 줄을 grep이 보므로 `200` 같은 검색어가 시각에 맞을 수 있다. 시각에 쓰이는 글자로만 된 제외어는 서버에서 걸지 않고, 모든 검색어를 앱에서 줄 본문에 다시 적용한다. 그래서 파드당 1,000줄 상한은 서버 쪽 일치 수 기준이며, 이 경우 잘림 표시가 먼저 뜰 수 있다.
- **앞뒤 N줄:** `grep -C`는 `grep`을 잇는 AND와 함께 쓰면 문맥이 사라지므로 서버에서 붙이지 않는다. 옵션은 줄을 눌렀을 때 보여 주는 앞뒤 줄 수다. 주변 로그는 `kube_logs`에 `sinceTime`을 더해 그 줄 60초 전부터 읽는다. 명령을 새로 만들지 않기 위해서다. 그 안의 양이 4MiB를 넘으면 해당 줄을 찾지 못했다고 표시한다.
- **채널 거부:** 거부되면 동시 수를 그 시점 실행 수(최소 1)로 낮추고 0.4초 뒤 그 파드를 다시 시도한다. 같은 대상이 5번 거부되면 그 대상만 실패로 표시한다. 낮춘 동시 수는 이번 검색 동안만 유지한다.
- **상한과 긴 줄:** 한 줄 4,096자에서 자르고 표시한다. 줄 수와 별개로 대상 하나의 출력을 16MiB로 막는다. 전체 5,000줄에 정확히 닿아 끝난 경우도 잘렸다고 표시한다.
- **화면:** 결과는 작업 화면이 보관해 트리에 다녀와도 남고 검색도 계속되며, 탭을 닫으면 취소한다. 결과 표는 가상 목록이다. 우클릭은 로그(패널), 셸, 이 키워드로 실시간 따라가기, 줄 복사, 결과 전체 복사다. 트리의 파드·namespace·워크로드·서비스 행과 대시보드 행 우클릭에서 범위를 채워 시작한다.
- **파일 저장은 넣지 않았다.** 설계의 저장은 사용자가 위치를 고를 때만 하는 제약이고 복사로 대신한다. 저장 대화상자 명령이 아직 없어 필요해지면 별도로 추가한다.
- **파일:** `kube/log_search.rs`, `log_scheduler.rs`, `log_keywords.rs`, `remote_exec::stream_refusable`, `features/kube/LogSearch.tsx`, `LogSearchForm.tsx`, `LogSearchResults.tsx`, `LogAround.tsx`, `logSearchModel.ts`, `useLogSearch.ts`. 트리와 함께 쓰려고 `usePodShell.ts`, `usePanelWidth.ts`로 분리했다. 대시보드 행은 `DashboardRows.tsx`로 옮겼다.
- **검사:** `scripts/verify-kube-log-search.mjs`(`npm run test:kube-log-search`), `tests/ui/kube-log-search.spec.ts`.

### KV.6 — 간단 제어

운영 모드는 세션 설정이며 화면에 항상 표시한다.

```rust
enum Action { DeletePod { .. }, RolloutRestart { .. }, Cordon { .. }, Uncordon { .. } }
```

- Rust가 프로필을 다시 읽어 `operate`를 확인한다. 화면 값을 믿지 않는다.
- 확인창에 context, namespace, 대상, 예상 영향(소유 워크로드가 있으면 다시 생성됨, 없으면 복구되지 않음)을 표시한다. 기본 선택은 취소다. 결과는 트리 갱신으로 확인하고, 조회 모드에서는 버튼을 숨기지 않고 비활성화해 이유를 알린다.
- 실제 권한은 RBAC가 결정한다. `auth can-i` 사전 조회 없이 서버 오류를 그대로 보여준다.
- 포트 포워딩은 `kubectl port-forward`와 SSH 터널을 묶어야 하므로 AT.6 이후 별도로 추가한다.
- **구현에서 정한 것(2026-11-09):**
  - 설계에 운영 모드를 켜는 경로가 없어 추가했다. 헤더의 모드 표시를 눌러 바꾸며, 켤 때만 확인창을 띄우고 끌 때는 바로 끈다. 저장은 `kube_set_operate_mode`만 한다. 탭 메뉴로 연 터미널 세션과 설정 전 세션은 저장할 곳이 없어 조회 전용이다.
  - `kube_action`은 설정을 인자로 받지 않는다. kubectl, kubeconfig, context, `operate`는 실행 직전 저장된 프로필에서 읽는다. 화면이 보낸 `context`는 사용자가 확인창에서 본 값이고, 저장값과 다르면 거부한다. 같은 세션의 다른 탭이 context를 바꾼 경우를 막기 위해서다. namespace를 좁힌 세션은 그 밖의 파드·워크로드를 거부한다. 노드는 namespace가 없어 허용한다.
  - 삭제는 `--wait=false`로 유예 시간을 기다리지 않는다. 시간 초과처럼 명령이 이미 나갔을 수 있는 실패는 적용 여부를 모른다고 표시한다. 재시도는 사용자가 정한다.
  - 메뉴: 파드 → **파드 삭제**, Deployment·StatefulSet·DaemonSet 그룹 → **롤아웃 재시작**, 노드 행과 노드별 묶기의 노드 그룹 → 상태에 맞는 **Cordon** 또는 **Uncordon**. 비활성 이유는 호버 없이 보이도록 항목 아래에 쓴다.
  - 정적 파드(소유자 Node)는 미러 파드만 지워지고 kubelet이 다시 만든다고 안내한다. kind에서 컨테이너가 유지되는 것을 확인했다.
- **파일:** `kube/action.rs`, `kube/action_cluster_test.rs`(`npm run test:kube-actions`), `features/kube/actionModel.ts`, `treeRowMenu.ts`, `KubeActionDialog.tsx`, `OperateModeControl.tsx`, `useOperateMode.ts`, `kubeActions.css`, `tests/ui/kube-actions.spec.ts`.

### KV.7 — 문제 목록과 변화 기록

앱과 탭이 켜져 있는 동안만 동작하고, 메모리에만 보관한다.

- **문제 목록:** NotReady 노드, 미달 워크로드, 대기 PVC, 실패 Job, 최대치 HPA, 문제 파드, 최근 재시작. 누르면 해당 항목으로 이동한다.
- **변화 기록:** 스냅샷 차이로 노드 전환, 재시작(사유 포함), 고장·회복을 시각과 함께 최대 500건 쌓는다.
- **알림(기본 꺼짐):** 세션별로 켠다. 문제가 새로 생기면 AT.3의 빈도 제한 경로로 OS 알림을 보낸다. 앱이 꺼져 있으면 동작하지 않는다.

**구현에서 정한 것(KV.7):**

- **조회 종류 3개 추가:** `pvcs`, `jobs`, `hpas`(30초). 스냅샷에 없던 자원이다. PodTree는 한 번에 받지만, 권한 없는 항목은 그 항목만 비우는 규칙(KV.2) 때문에 종류를 나눴다. 파서는 `kube/cluster_issues.rs`다. 트리와 대시보드는 이 세 종류의 실패를 표시하지 않는다(`overviewKinds`).
- **숨겨진 탭의 조회:** 조회는 원래 보이는 화면에서만 돈다. 그러면 다른 탭을 보거나 창을 내린 동안에는 알림이 올 수 없어, **알림을 켠 세션만** 숨겨져도 판정에 필요한 6종(파드, 워크로드, 노드, PVC, Job, HPA)을 계속 조회한다. 끈 세션의 동작은 KV.2 그대로다.
- **기준선:** 종류별 첫 조회는 기준선이다. 이미 있던 문제는 기록하지도 알리지도 않는다. 늦게 도착한 종류도 같다.
- **확정 시간(`ISSUE_HOLD` 60초):** 경고는 60초 지속돼야 확정되고, 확정된 문제는 60초 동안 사라져 있어야 끝난 것으로 본다. 오류는 바로 확정한다. 롤아웃의 `ContainerCreating`과 크래시 루프 사이의 `Running`이 줄과 알림을 반복해 만들지 않게 하려는 것이다. 실패한 조회의 오래된 데이터는 시간 경과로 치지 않는다.
- **판정(PodTree 기준):** `Bound`가 아닌 PVC(`Lost`는 오류), `Failed` 조건이 참인 Job(CronJob은 최신 실행만, 단독 Job은 실패 후 24시간), `current >= max`인 HPA. 재시도 중인 Job과 스케줄 중지 노드는 설계안 목록에 없어 넣지 않았다. `WaitForFirstConsumer` PVC는 첫 파드 전까지 `Pending`이라 경고로 보일 수 있다.
- **이동:** PVC는 트리에 행이 없어 namespace로 간다. HPA는 대상이 Deployment·StatefulSet이면 그 워크로드로, 아니면 namespace로 간다.
- **변화 기록 종류:** 노드 전환, 재시작, 고장, 회복, 사라짐. 재시작이 일어난 조회에서는 같은 파드의 고장 줄을 쓰지 않는다. 대상이 삭제된 문제는 회복이 아니라 사라짐이다. 시각은 앱이 데이터를 받은 시각이다.
- **알림:** `NotificationLimiter`와 본문 정리를 `lib/notifications.ts`로 내리고 인스턴스 하나를 터미널과 함께 쓴다. 제한에 걸린 문제는 버리지 않고 다음 조회 때 묶어 보낸다. 사용자가 이 작업 화면을 보고 있고 앱에 포커스가 있으면 보내지 않는다. 제목은 앱이 소유한 세션 이름만 쓴다.

### KV.8 — 인그레스 모니터링

**구성 점검(`get ingress`, `get svc,endpoints`, 30초 주기):**

| 표시 | 판정 |
|---|---|
| 호스트, 경로, 백엔드, 클래스, LB 주소, TLS 사용 여부 | 목록과 필터 |
| 백엔드 없음 | 가리키는 Service가 없음 |
| 백엔드 준비 0 | Service의 준비된 Endpoint가 0개 |
| 주소 미할당 | `status.loadBalancer`가 비어 있음 |
| TLS Secret 없음 | `get secret -o name`으로 이름만 대조한다. 값은 읽지 않는다 |

**트래픽(컨트롤러 메트릭이 읽힐 때만):** 컨트롤러 파드의 `/metrics`를 `get --raw` proxy로 읽어 호스트별 요청률, 2xx·4xx·5xx 비율, 지연을 표시한다. 사용자 환경인 ingress-nginx를 지원한다(`nginx_ingress_controller_requests`, `_request_duration_seconds`, `_nginx_process_connections`, KV.0에서 확인). 다른 컨트롤러는 후속이다. 메트릭을 못 읽으면 구성 점검만 표시한다.

KV.0 결과: v1.15.1 정적 매니페스트는 **메트릭이 꺼져 있다**(`--enable-metrics=true` 필요). `/metrics`가 읽혀도 이 이름이 없으면 오류가 아니라 "컨트롤러 메트릭이 꺼져 있음"으로 표시한다. `pods/proxy` get이 없으면 그 이유만 표시한다. 상류 저장소가 보관(archived) 상태이므로 트래픽 표시는 이 컨트롤러 안에서만 유지하고 범위를 넓히지 않는다. 구성 점검은 컨트롤러와 무관하다.

**이동:** 인그레스 행에서 백엔드 파드로 이동하고, 컨트롤러 로그를 해당 호스트로 검색한다(KV.5). 5xx 조사의 기본 흐름이다.

**구현에서 정한 것(KV.8):**

- **명령과 슬롯:** `kube_ingress` 하나가 `get ingress`, `get services,endpoints`, `get secrets`, 컨트롤러 파드 목록, 파드마다 `/metrics`를 슬롯 하나 안에서 차례로 읽는다. 연결당 동시 3개 상한을 조회 하나만큼만 쓴다. 인그레스가 없으면 서비스 조회를, TLS Secret 이름이 없으면 Secret 조회를 건너뛴다.
- **조회 주기:** 30초(느리면 소요 시간의 3배). 인그레스 화면과 대시보드를 볼 때만 조회하고, 이전 요청이 끝나기 전에는 다음 요청을 보내지 않는다.
- **Secret:** `-A -o name`은 namespace를 주지 않아 go-template으로 namespace와 이름만 출력한다. 값은 앱과 SSH로 오지 않는다. 권한이 없으면 "없음"으로 판정하지 않고 확인하지 못했다고 표시한다.
- **판정:** 경로 하나의 Service만 본다. `ExternalName`과 리소스 백엔드는 Endpoint를 셀 대상이 아니므로 문제로 보지 않는다. 서비스를 읽지 못하면 `미확인`이다. 대시보드에는 구성 문제만 나오고, 트래픽은 인그레스 화면에만 있다.
- **컨트롤러:** `app.kubernetes.io/name=ingress-nginx,app.kubernetes.io/component=controller` 라벨의 Running 파드를 `-A`로 찾고 최대 10개를 읽는다. 세션에 namespace를 정했어도 컨트롤러는 보통 다른 namespace에 있기 때문이다. 포트 10254는 선언되지 않아 고정값이다(KV.0).
- **메트릭 판정:** 서버에서 `grep`으로 쓰는 이름만 받아 히스토그램 버킷을 SSH로 보내지 않는다. kubectl 종료 코드는 KV.5와 같이 stderr로 전달한다. 응답에 `nginx_ingress_controller_*`가 한 줄도 없으면 **꺼짐**이고, 켜졌지만 요청이 없으면 준비 상태에 호스트가 비어 있다. `Forbidden`이면 `pods/proxy` 이유만 표시하고 남은 컨트롤러는 읽지 않는다. 일부만 읽으면 몇 개를 읽었는지 표시한다.
- **비율:** Rust는 누적 카운터만 넘기고 화면이 두 번의 조회를 비교한다. 그 구간에 요청이 있으면 구간 비율과 요청률, 없으면 누적 비율과 요청률 0을 표시한다(셀 설명에 기준 표시). 카운터가 줄거나 읽은 컨트롤러 수가 바뀌면 재시작으로 보고 기준을 다시 잡는다. 3xx와 나머지는 전체 수에만 들어간다. 지연은 평균이다(버킷을 받지 않음). 메트릭의 호스트는 인그레스 규칙에 있는 것만 남겨 namespace 세션에 다른 namespace의 호스트가 나오지 않는다. `_`는 호스트 없는 규칙으로 합친다.
- **이동:** 행 클릭은 문제 있는 파드(없으면 첫 파드)로, 파드가 없으면 namespace로 간다. 우클릭에 파드 목록과 컨트롤러 로그 검색이 있다.
- **컨트롤러 로그 검색:** 로그 검색 범위에 **인그레스 컨트롤러**를 더했다. 컨트롤러 파드는 트리 목록에 없을 수 있어 `kube_ingress`가 준 목록을 쓴다. **기본 접근 로그에는 호스트가 없다**(실측: `ok.local` 일치 0줄, 형식은 `[namespace-서비스-포트]`). 호스트 검색은 요청대로 두되, 로그 형식을 바꾸지 않은 환경에서는 결과가 없으므로 같은 메뉴에 `namespace-서비스-포트` 검색을 함께 둔다. 와일드카드 호스트는 `*.`를 뺀 부분으로 검색한다.
- **파일:** `kube/ingress.rs`, `kube/ingress_metrics.rs`, `features/kube/ingressTypes.ts`, `ingressModel.ts`, `useKubeIngress.ts`, `IngressView.tsx`, `IngressPanel.tsx`, `ingress.css`. 설계의 `metrics.rs`는 KV.9의 범위라 만들지 않았다. Prometheus 줄 파서가 KV.9와 겹치면 그때 공용화를 검토한다.
- **검사:** `scripts/verify-kube-ingress.mjs`(`npm run test:kube-ingress`), `tests/ui/kube-ingress.spec.ts`. fixture의 `metrics-on`·`metrics-off`는 metrics-server용이므로 `ingress-up`, `ingress-metrics-on`, `ingress-metrics-off`를 더했다.

### KV.9 — 워커·런타임 모니터링

**사용자가 필요로 하는 것은 워커가 몇 개인지와, 일을 받고 반환하지 않는 워커가 있는지다.** 대상 앱에 따라 얻을 수 있는 정보가 달라 두 경로를 둔다.

**경로 A: 앱 메트릭(정확, 우선).** 앱이 Prometheus `/metrics`를 제공하면 `get --raw` proxy로 읽는다.

- **vLLM을 첫 프리셋으로 삼는다**(사용자 환경). 실행·대기 요청, 처리량, 완료 수를 원본 탐지 규칙으로 찾는다.
- 특정 앱에 묶지 않는다. 파드의 `containerPort`와 `prometheus.io/*` annotation으로 `/metrics` 후보를 찾아, 읽히면 **그 파드의 유용한 지표**를 목록으로 보여주고 사용자가 고정할 수 있게 한다. KV.0에서 ingress-nginx의 10254처럼 선언되지 않은 메트릭 포트를 확인했으므로 **포트와 경로를 직접 입력하는 칸**을 함께 둔다. 후보의 404·연결 거부는 오류가 아니라 "메트릭 없음"으로 처리한다. 사용 중, 전체, 완료 수에 해당하는 메트릭을 지정하면 반환 판정을 켠다.
- GET과 `/metrics` 형식 경로만 허용한다. 감시 대상 합계 파드 50개, 동시 4개, 주기 15초.

**경로 B: 프로세스 프로브(앱 수정 불필요).** 파드 안에서 고정 읽기 스크립트를 실행한다.

```sh
# /proc의 프로세스별 comm, 상태, 시작 시각, Threads, FD 수, /proc/net/tcp 상태 집계. 쓰기 동작이 없다.
```

| 표시 | 계산 |
|---|---|
| 프로세스·워커 | 이름별 프로세스 수. nginx master/worker를 구분하고 gunicorn, uvicorn 등 같은 이름 프로세스를 묶는다 |
| 스레드 | `/proc/<pid>/status`의 `Threads` 합계와 프로세스별 값 |
| FD | 프로세스별 사용량과 한도 |
| 연결 | TCP 상태별 수(`CLOSE_WAIT` 증가 강조), LISTEN 포트, SYN backlog와 drop, 재전송 |

- 출력 1MiB, 시간 5초로 제한한다. `sh`나 `cat`이 없는 이미지는 "이 컨테이너에서는 읽을 수 없음"으로 표시한다. KV.0 기준 이 경우 종료 코드 1과 `executable file not found` 또는 `no such file or directory`가 나온다.
- 상세의 **런타임** 탭에서 **수집**을 누를 때 실행한다. 워커 감시를 켠 워크로드만 30초 이상 간격으로 반복한다.
- **조회 모드에서 허용한다.** 기존 터미널 UI는 조회 모드에서 exec를 전부 막았지만, 여기서는 앱에 고정된 읽기 스크립트만 쓴다. 임의 명령 경로가 아니다. 워크로드별로 처음 한 번 "파드 안에서 읽기 명령을 실행합니다"를 확인받는다. RBAC에 `pods/exec`가 없으면 그 사실만 표시한다.

**반환 안 됨 판정(`workers.ts`, 순수 로직):** 원본의 처리 정지 판정(`podtree.sh:2511`)을 일반화한다.

| 신호 | 판정 |
|---|---|
| 사용 중 > 0이고 완료 수가 N분 동안 그대로 | **반환 안 됨 의심** |
| 사용 중 = 전체가 N분 지속 | **워커 포화** |
| 프로브: `CLOSE_WAIT`가 표본마다 계속 증가 | **연결 미반환 의심** |
| 프로브: FD나 스레드 수가 표본마다 계속 증가 | **누수 의심** |

N은 기본 5분이고 워크로드별로 바꿀 수 있다. **모두 "의심"으로 표시한다.** 메트릭만으로 원인을 단정하지 않는다. 결과는 대시보드와 변화 기록에 올리고, 해당 파드의 런타임 탭과 로그 검색으로 이어 준다.

워커 감시를 켠 워크로드는 트리 행에도 `사용 8/8`과 판정을 표시한다(KV.2).

exec 없이 스레드 수를 얻는 경로(`get --raw /api/v1/nodes/<노드>/proxy/metrics/cadvisor`의 `container_threads`)는 KV.0에서 확인했다. `nodes/proxy` get이 필요하고, 노드 하나의 응답이 작은 시험 노드에서도 411KB이므로 트리 전체를 주기 조회하지 않고 **선택한 파드의 노드만** 읽어 상세의 런타임 탭에 표시한다. `container`가 빈 행은 cgroup 합계이므로 쓰지 않는다. 권한이 없으면 경로 B로 넘어간다.

**구현에서 정한 것(KV.9):**

- **파일:** 백엔드는 `kube/metrics.rs`, `kube/probe.rs`, 판정 문구는 `kube/state.rs`의 `classify_proxy`. 프런트는 `workers.ts`(판정·표본·요약), `workerSchedule.ts`(읽을 대상과 일정), `workerPrefs.ts`(세션별 저장), `useWorkerWatch.ts`(조회), `runtimeModel.ts`(프로세스 묶기·메트릭 목록), `PodRuntimeView.tsx`, `RuntimeSections.tsx`, `PodMetricsView.tsx`, `kubeRuntime.css`(런타임 탭), `WorkerPanel.tsx`와 `kubeWorkers.css`(대시보드). §3.2의 `WorkerView.tsx`는 이 파일들로 나뉘었다.
- **동시 실행:** `kube_metrics`, `kube_probe`는 연결당 4개인 `WatchSlots`를 쓴다. 트리 조회의 3개와 나눠, 파드 50개를 도는 동안에도 트리 조회가 밀리지 않게 했다.
- **허용 경로:** `/`로 시작하고 각 구간이 영문·숫자·`.`·`_`·`-`이며 `..`이 없고 마지막 구간에 `metrics`나 `prometheus`가 들어간 128자 이내 경로만 쓴다. 쿼리는 넣을 수 없다.
- **후보 확인:** `only: []`로 읽어 지표 수만 받는다. 감시 조회는 지정한 이름만 받아 웹뷰로 넘기는 양을 줄인다. 선언·annotation 후보는 최대 8개이고 동시에 4개씩 확인한다.
- **메트릭 지정:** 목록 행 우클릭으로 사용 중, 전체, 완료 수를 고른다. 라벨이 있는 이름은 합계 행과 계열별 행을 함께 보여 주며, 합계 행을 고르면 이름 전체를 더한다. Go·Python 런타임 내부 지표와 히스토그램 `_bucket`은 목록에서 뺀다.
- **판정 수치:** 사용 중·전체·완료 판정은 표본 사이가 150초를 넘으면 지속을 인정하지 않는다. 탭을 숨긴 동안은 본 적이 없기 때문이다. 프로브의 "표본마다 계속 증가"는 최근 5개 표본이 빠짐없이 증가한 경우다(30초 주기로 약 2분). 시작 직후의 자연스러운 증가와 구분하기 위한 제안값이다.
- **읽기 실패:** 마지막 읽기가 실패한 파드는 값과 판정을 내고 안내만 표시한다. 오래된 값을 현재 값처럼 보이지 않게 하기 위해서다.
- **프로브 스크립트:** `sh` 내장 명령만 쓰므로 `cat`이 없어도 읽는다. 명령줄(`cmdline`)은 nginx의 master·worker 구분에만 파드 안에서 쓰고 앱으로 보내지 않는다.
- **감시 저장:** `dachsterm.kube.workers.<세션>`에 감시 대상, 고정 지표, 프로브 확인 이력을 둔다. 저장된 프로필이 없는 탭은 탭이 열린 동안만 유지한다. 트리 행은 `memo`이므로 값은 컨텍스트로 전달한다.
- **이번 범위가 아닌 것:** vLLM 프리셋은 KV.10, 변화 기록에 올리는 일은 KV.7에서 한다. 대시보드의 판정 행은 해당 파드의 런타임 탭을 열고, 우클릭으로 로그 검색을 연다.

### KV.10 — vLLM·GPU

원본 `V` 화면을 옮긴다. 모델 > 파드 표, 실행·대기 요청, 처리량 추이, KV 캐시, GPU·VRAM. 파서와 탐지 규칙은 `podtree.sh:1946-2914`를 레퍼런스로 Rust에 다시 작성한다.

- 수집 경로는 `get --raw /api/v1/namespaces/<ns>/pods/<파드>:<포트>/proxy/<경로>`이다. 경로는 탐지 대상의 메트릭 경로로만 제한하고 GET만 쓴다. **조건을 만족하면 조회 모드에서 허용**한다.
- 후보 탐지와 수집 동시성은 원본(동시 4개)을 따른다. 대상이 없으면 메뉴를 표시하지 않는다. 처리 정지는 KV.9의 판정과 합친다.

### KV.11 — 로컬 kubeconfig

SSH 없이 내 PC의 kubeconfig로 접속한다. Mac 판매에 필요할 가능성이 크다.

- 연결 목록에 "로컬 클러스터"를 추가하고 `Local` 러너를 구현한다. Windows는 `kubectl.exe`, macOS는 탐지한 절대 경로를 쓴다. Finder 실행 앱은 Homebrew 경로를 모르므로 이름만으로 실행하지 않는다(규칙 §11).
- 인증 플러그인(`exec` credential)이 PATH를 요구할 수 있어 패키지된 앱으로 직접 검증한다.
- 로그 검색의 서버 측 `grep`은 쓸 수 없으므로 앱에서 거른다. 정책이 달라 러너에서 분기한다.

### KV.12 — 터미널 UI 제거와 문서

- **KV.4까지 쓸 수 있어도 기존 터미널 UI 코드는 바로 없애지 않는다.** 도구 메뉴의 **PodTree 열기**는 TW.9에서 이미 숨겼으므로, 그동안 화면에서 여는 경로는 없다.
- 기능 비교표를 만들어 패킷 캡처, 네트워크 2초 화면, 여러 파드 로그, 트리 저장을 옮길지 뺄지 정한다. 사용자가 확인하면 스크립트와 `Script` 경로를 제거한다.
- 사용 안내서, 전체 회귀, Mac 실기기 검증을 진행한다. 화면 문구에는 외부 제품명을 쓰지 않는다(규칙 §3).

### KV.13 — 실시간 로그 보드와 화면 개선

2026-11-09 사용자 요청. KV.4의 "실시간 따라가기는 터미널 탭" 결정은 파드 하나를 볼 때만 유지하고, 여러 파드를 함께 보는 일은 이 화면이 맡는다.

- **채널 하나:** 파드마다 SSH 채널을 열면 `MaxSessions`(기본 10)를 금방 넘는다. `kube_log_stream`은 스크립트 하나에서 `kubectl logs -f`를 소스별로 백그라운드 실행하고, `awk`로 줄 앞에 소스 번호를 붙여 stdout 하나로 합친다. `LC_ALL=C`로 3800바이트에서 잘라 `PIPE_BUF` 안에서 한 번에 쓰므로 줄이 섞이지 않는다. Debian·Ubuntu 기본인 mawk는 파이프 입력을 블록으로 모아 읽어 조용한 파드의 로그가 나오지 않으므로(kind 실측) mawk일 때만 `-W interactive`를 쓴다. 폴링 슬롯은 쓰지 않는다.
- **상한:** 소스 20개(kubectl 프로세스와 API 서버 요청 수), 초당 3000줄(넘으면 버리고 건너뛴 수를 표시), 12시간. 화면 메모리는 소스당 2000줄, 합친 보기 1만 줄이다. 로그는 메모리에만 둔다.
- **종료:** PTY가 없어 채널이 닫혀도 kubectl이 모르므로 KV.5와 같이 stdin을 읽는 감시 프로세스가 끝낸다. 취소는 `kube_log_cancel`을 공용으로 쓴다.
- **대상:** 파드 목록을 저장하지 않고 서비스·워크로드·노드 같은 범위를 저장해 스냅샷으로 다시 계산한다. 파드가 바뀌면 스트림을 교체하고 살아 있는 파드는 `--since-time`으로 마지막 시각부터 이어 중복을 버린다.
- **요청 흐름:** 인그레스 행에서 컨트롤러 로그를 위, 서비스 파드를 아래에 연다. 컨트롤러 로그는 upstream 이름(`[namespace-서비스-포트]`, KV.8)으로 서버에서 좁히고, 형식을 바꾼 환경을 위해 **전체 요청** 버튼을 둔다. upstream이 여럿이면 좁히지 않는다.
- **색:** 칸 배경과 글자, 소스 색은 터미널 토큰을 쓴다. 터미널 색은 그 배경에서 읽히도록 정해져 있기 때문이다.
- **레벨 추정:** 색과 `경고·오류만`에만 쓴다. 구조화 로그의 level 필드를 단어보다 우선하고, 컨트롤러 로그는 HTTP 상태로 판정한다.
- **리사이즈 원인:** `.resize-handle`은 폭 지정이 없고 그리드 칸에서 폭을 받는다. flex인 `.kube-split`에서는 0px이라 잡을 수 없었다.

## 6. 보안 요약

- 클러스터 데이터는 신뢰할 수 없는 입력이다. 길이를 먼저 확인하고, 일반 텍스트로 표시하고, 명령 인자로 쓰기 전에 이름 규칙을 검증한다. 모든 명령은 고정 형식이고 값은 인용 함수를 거친다.
- kubeconfig, 토큰, 인증서 내용을 읽거나 저장하지 않는다. 경로만 저장하며 내보내기에서 뺀다. KV.1의 복사는 서버 안에서 사용자가 버튼으로 실행하며 내용은 앱으로 오지 않는다.
- 쓰기는 `Action` enum뿐이고 Rust가 운영 모드를 재확인한다. 임의 `kubectl` 입력 경로를 만들지 않는다.
- 파드 안 프로브와 메트릭 proxy는 고정 스크립트와 제한된 경로만 쓴다. Secret은 이름 대조만 하고 값은 조회하지 않는다.
- 로그 검색 키워드는 인자로만 전달되고 셸 코드가 되지 않는다.
- 로그, YAML, 런타임 정보는 메모리에만 두고 세션 로그와 진단 내보내기에 넣지 않는다.
- 주기 조회가 많으므로 연결당 동시 실행을 제한해 서버와 API 서버에 부담을 주지 않는다.
