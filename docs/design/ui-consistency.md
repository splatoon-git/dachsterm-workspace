# UI.1 — UI 배치와 타이포그래피 일관성

2026-11-18 사용자 요청. 기능별 스타일을 공통 역할에 맞추고, 제목보다 본문·버튼이 커지는 역전과 작업 탭 안의 불필요한 중앙 폼을 없앤다. [검증 기록](../verification/ui-consistency.md).

## 글자 역할

일반 작업 UI의 기본 역할은 네 가지다. 토큰 이름의 크기를 보고 임의로 고르지 않고 아래 역할로 고른다. 크기뿐 아니라 굵기·행간·간격을 함께 적용한다.

| 역할 | 기존 토큰 | 기본 크기 | 적용 |
|---|---|---|---|
| 화면·대화상자 제목 | `--font-heading` | 16px, semibold | 설정 분류 제목, 도구·쿠버네티스 설정·로그 시작 제목 |
| 내용 소제목 | `--font-body` | 14px, semibold | 설정 그룹, 대시보드 카드·상세 정보 구획 |
| 본문·레이블·버튼·입력 | `--font-small` | 12px | 일반 작업 UI 기본, 폼과 동작 |
| 보조 정보 | `--font-caption` | 11px | 상태·배지·경로 보조·단축키·설명 메타데이터 |

본문 기본 행간은 `--font-leading-normal`, 제목은 `--font-leading-tight`다. 사이드바의 짧은 그룹명처럼 밀도가 높은 영역은 본문과 같은 12px에 semibold로 위계를 줄 수 있다. 설명·버튼이 해당 구획 제목보다 커지게 하지 않는다.

기초 토큰의 10개 크기 자체를 결함으로 보지는 않는다. [Microsoft Fluent](https://fluent2.microsoft.design/typography)도 웹용 10개 크기를 제공하지만 제품 전체의 용도별 선택지다. DachsTerm의 시작 화면 큰 제목, 게임 그림·점수, 테마 축소 미리보기, 파일 형식 아이콘은 일반 폼의 글자 단계와 목적이 다르다. 터미널·코드 편집기의 사용자 지정 글꼴과 채팅의 긴 본문도 별도 읽기 영역으로 유지한다. 이 예외를 일반 설정·버튼에 가져오지 않는다.

## 컨트롤

- 일반 버튼·텍스트 입력·선택창은 32px, 글자 12px, 행 상자 20px를 기본으로 한다. `styles.css`에서 기본값을 한 번 정한다.
- 기본·주요·위험 액션의 역할은 색과 강조로 구분한다. 높이와 글자 크기는 바뀌지 않는다.
- 아이콘 도구, 트리 행, 탭, 인라인 링크는 별도의 작은 조작 영역이다. 고정 높이가 필요한 경우 `min-height: 0`도 함께 정해 일반 컨트롤의 최소 높이와 충돌하지 않게 한다.
- 같은 줄의 입력·선택·실행 버튼은 아래쪽 기준선을 맞추고, 같은 역할의 컨트롤 높이를 다르게 만들지 않는다. 레이블과 설명은 필드의 시작선에 맞춘다.
- 긴 버튼 문구와 좁은 화면에서는 줄바꿈 또는 행 전환을 허용한다. 글자를 줄여 억지로 맞추지 않는다.

## 배치

- 작업 탭 안의 설정·복구·시작 폼은 왼쪽 위에서 시작한다. 쿠버네티스는 탭 글자와 본문이 20px의 같은 시작선을 쓴다.
- 폼은 읽기 좋은 최대 폭을 두되 가운데로 옮기지 않는다. 쿠버네티스 설정 내용은 최대 680px이며 좁으면 부모 너비에 맞춘다.
- 작업 탭의 폼 버튼은 본문 시작선에 놓는다. 모달의 완료·취소 버튼은 기존 하단 오른쪽 정렬을 유지한다. 두 배치는 사용 맥락이 다르다.
- 파일·Git의 비어 있는 상태, 쿠버네티스 빈 상태와 실시간 로그 시작도 해당 작업 영역의 왼쪽 위에서 안내한다.
- 모달은 창 가운데, 팝오버는 호출한 버튼 옆이라는 기존 역할을 유지한다.

## 점검 방법

1. `npm run audit:ui -- <개발 서버 URL> <출력 폴더>`로 설정 9분류와 연결 폼 3상태를 1280/800/560/360px, Classic/GitHub Dark/Terminal Green에서 측정한다. CSS 목록·치수 선언, 글자 크기·행간·컨트롤 위치·크기, 넘침 후보와 화면 144장을 남긴다.
2. 넘침 후보는 사람이 판정한다. 스크린리더 전용 텍스트나 음수 여백으로 확장한 모달 footer는 단순 `scrollWidth`만으로 오류라고 할 수 없다.
3. `tests/ui/ui-consistency.spec.ts`는 제목·본문의 크기 관계, 같은 행 필드·버튼 높이와 기준선, 설정 폼의 시작선과 좁은 창을 검증한다.
4. 전체 Playwright UI 회귀로 파일·Git·채팅·쿠버네티스·도구·터미널·게임의 영향을 확인한다. 통과는 시각 품질에 대한 사람의 승인을 대신하지 않는다.
5. Windows 실제 앱과 macOS WKWebView, OS 배율에서 별도 확인한다. 브라우저 픽스처의 통과를 실제 SSH 접속이나 Mac 실기기 검증으로 기록하지 않는다.
