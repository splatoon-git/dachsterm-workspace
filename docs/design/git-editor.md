## 1. 목표와 사용자 결정

**Git과 파일 편집을 VS Code처럼 앱 안에서 끝낸다.** 저장소 폴더면 탭 종류(SSH, 로컬, WSL)와 상관없이 같은 화면과 동작을 준다.

사용자 결정(2026-11-08):

| 항목 | 결정 |

## 3. 화면 구성

```text
┌ 사이드바 ─────────────┐┌ 가운데 탭 ────────────────────────────────┐
│ 연결 │ 파일 │ Git      ││ [Ubuntu ●] [app.ts ×] [app.ts ↔ HEAD ×]    │
│ ⎇ main ↑1 ↓0      ⋯   ││  터미널 / 파일 탭 / diff 탭                 │
│ 메시지 [Ctrl+Enter]   ││                                            │
│ [✓ 커밋        ▾]     ││  mesim@pc:~/app$          ⎇ main ●3   ←GE.11│
│ ▾ 스테이지됨 1        ││                                            │
│   M src/app.ts        ││                                            │
│ ▾ 변경 2              ││                                            │
│   M README.md         ││                                            │
│   ? notes.txt         ││                                            │
└───────────────────────┘└─ 상태바: ⎇ main ●3 · UTF-8 · LF ──────────┘
```

- Git 보기는 **선택된 탭의 저장소**를 보여준다. 저장소가 아니면 "Git 저장소가 아닙니다"와 Git이 없을 때의 안내만 둔다. 상시 버튼은 커밋 입력과 커밋 버튼, 머리줄의 작은 아이콘(새로 고침, 더보기 `⋯`)뿐이고, 나머지는 행 우클릭과 `⋯` 메뉴에 둔다(roadmap §2, TW §1 원칙).
- 가운데 탭에 **파일 탭**과 **diff 탭** 두 종류를 더한다. DX.6 **변경 검토** 탭(여러 파일 diff와 줄 의견)은 그대로 두고, Git 보기의 `⋯ → 변경 검토`로도 연다.

## 4. 작업별 설계

### GE.1 — 외부 편집 저장 확인 카드

- 서버 파일(SFTP·FTP)을 외부 편집기에서 저장해 `pending`이 되면, 사이드바 보기와 상관없이 **그 연결의 탭 위에 카드**를 띄운다. 승인 카드 대기열(`agentSign.ts`)과 같은 자리·같은 모양을 쓰되, 정책이 다르므로 대기열은 따로 둔다(주석으로 이유를 남긴다).
- 선택: **업로드** / **취소(수정본 보존)** / **이 연결 동안 자동 업로드**. 마지막은 `uploadMode`를 연결 수명 동안만 `auto`로 바꾸고 저장하지 않는다. 재접속하거나 앱을 다시 켜면 `ask`로 돌아간다. 백엔드 `set_mode`에 "연결 한정" 표시를 더해 `persist`가 원래 모드를 쓰게 한다.
- 앱이 포커스를 잃었으면 OS 알림도 보낸다(설정 **OS 알림**을 따름).
- 업로드 직전 서버 파일이 바뀌었으면 지금처럼 `conflict`로 멈추고 카드가 덮어쓰기 / 다시 받기 / 다른 이름을 묻는다.
- 로컬·WSL 파일은 업로드가 없으므로 카드도 없다.

구현에서 정한 것(2026-11-08):

- **FTP는 카드 대상이 아니다.** 외부 편집 자체가 SFTP 전용이다(`editor.rs`가 SFTP만 쓰고 파일 패널이 FTP에서 편집 메뉴를 막는다). FTP 내장 편집은 GE.6 범위다.
- `set_mode`를 늘리지 않고 별도 파일 `editor/connection_auto.rs`에 뒀다. `Edit.mode_after_connection`이 돌아갈 모드를 들고, `persist`는 항상 원래 모드를 쓴다. 감시 루프가 매 회 끊긴 연결의 모드를 되돌리고, 다른 연결로 옮겨 갈 때도 되돌린다.
- `edit_session_auto`는 편집 ID 외에 **연결 ID와 프로필 ID도 받는다.** 재접속한 탭에서 답하면 편집을 그 연결로 옮겨야 해서다(`edit_resolve`와 같은 검사, `Editors::rebind`로 공용화).
- **재접속 뒤 카드가 뜰 탭:** 편집은 끝난 연결의 ID를 들고 있으므로, `edit_list`에 `connectionLive`를 더해 연결이 끝났으면 같은 세션의 연결된 탭이 카드를 띄운다. 같은 세션 탭이 둘이면 둘 다 뜨고 먼저 답한 쪽이 가져간다.
- 수동 업로드(`manual`)로 정한 편집은 카드를 띄우지 않는다. 사용자가 묻지 말라고 고른 것이기 때문이다.
- 충돌 카드에는 **취소 · 수정본 보존**을 더했고, **덮어쓰기**는 한 번 더 묻는다(§6, 기본 선택 취소).

### GE.2 — 로컬 패널 끌어 놓기·WSL 다운로드 (구현 완료)

`src/lib/fileDrop.ts` 공용 드롭 훅(끌고 있을 때 점선 테두리), 로컬·WSL 패널 드롭 → 지금 폴더로 복사, WSL 우클릭 **다운로드…**(폴더 선택 후 복사). 상세와 검증은 progress의 GE 항목.

### GE.3 — 탐색기로 끌어내기, 탐색기에서 보기

- 웹 화면은 OS로 파일 끌기를 시작할 수 없다. Windows·macOS를 지원하는 Tauri 드래그 플러그인으로 네이티브 끌기를 시작한다. 네이티브 의존성이므로 macOS 빌드를 함께 확인한다(규칙 §11).
- 로컬 파일은 그 경로, WSL 파일은 `\\wsl.localhost\<배포판>\...` 경로를 넘긴다.
- 서버 파일은 먼저 임시 폴더로 받아야 넘길 수 있다. **10MiB 이하 파일만** 끌어내기를 시작하고, 그보다 크거나 폴더면 "다운로드를 쓰세요" 안내를 띄운다. 임시 파일은 앱 종료 때 지운다.
- 우클릭 **탐색기에서 보기**(Mac **Finder에서 보기**): Windows `%SystemRoot%\explorer.exe /select,"<경로>"`, Mac `/usr/bin/open -R <경로>`. 이름만으로 실행하지 않는다.
- 구현에서 정한 것:
  - 플러그인(`tauri-plugin-drag`) 대신 그 아래의 `drag` 크레이트를 앱 명령에서 직접 호출한다. 웹 화면이 임의 경로로 끌기를 시작하지 못하게 경로 해석을 백엔드에 두기 위해서다.
  - `files_drag_prepare`(검사와 서버 파일 받기, ID 반환)와 `files_drag_out`(ID로 시작)을 나눴다. 받는 동안 버튼을 놓았는지 화면이 확인해야 한다. 버튼을 놓은 뒤 시작하면 Windows는 바로 드롭하고 Mac 동작은 보장되지 않는다.
  - 10MiB는 한 번의 끌기에 담기는 서버 파일 합계다. 버튼을 누른 채 받기 때문이다. 서버의 링크는 폴더일 수 있어 다운로드로 안내한다.
  - 한 번의 끌기는 같은 폴더 항목만 담는다. 셸이 다른 폴더 항목으로 데이터 객체를 만들지 못하면 `drag` 크레이트가 패닉하기 때문이다.
  - 앱 위에 놓으면 아무 일도 하지 않는다. 앱은 모든 드롭을 받으므로 그대로 두면 같은 폴더에 복사본이 생긴다.

### GE.4 — 편집기 부품 시험

반나절 시험판으로 Monaco를 확정하거나 CodeMirror 6로 바꾼다.

| 기준 | Monaco | CodeMirror 6 |
|---|---|---|
| VS Code와 같은 느낌 | 그대로 같다(단축키, 다중 커서, 찾기·바꾸기, 미니맵, 접기, 명령 팔레트) | 조립해야 비슷해진다 |
| diff 화면 | VS Code diff 편집기 기본 포함 | `@codemirror/merge` |
| 한글 입력 | 숨겨진 입력창 방식이라 조합 버그 보고가 있다. **WKWebView 실측 필수** | 브라우저 기본 입력이라 안정적인 편 |
| 테마 | hex로 테마를 등록하고 테마 바뀔 때 다시 등록 | CSS 변수를 바로 씀 |

합격 기준(둘 다 같은 기준): WebView2와 WKWebView에서 한글 조합(받침, 조합 중 커서 이동, 조합 중 저장 단축키), 일본어·중국어 IME 한 번씩, 10만 줄 파일 스크롤, 앱 테마 전환, diff 좌우·한 줄 보기, 웹 워커 로딩(Vite). Monaco가 Mac 한글 조합에서 글자를 잃거나 중복하면 CodeMirror 6로 간다. 편집기 코드는 게임처럼 lazy 로드한다.

시험 결과(2026-11-08, [기록](../verification/editor-trial.md)): Windows 자동 측정 통과, **잠정 Monaco**. 입력은 `editContext: false`로 두 OS 모두 textarea 경로를 쓴다. 뒤 작업은 `src/features/editor/CodeEditor.tsx`만 쓰고, 부품 import는 `MonacoEditors.tsx` 한 파일로 eslint가 제한한다. 실제 IME 입력과 Mac 한글 조합([M.16](../verification/macos-readiness.md))을 본 뒤 확정한다.

### GE.5 — 파일 탭(보기)

- **연다:** 파일 보기·Git 보기에서 한 번 클릭은 **미리보기 탭**(제목 기울임, 같은 칸에 하나, 다음 클릭이 바꿈), 더블클릭·편집 시작·탭 더블클릭은 **고정 탭**. 같은 파일이 이미 열려 있으면 그 탭으로 간다. 우클릭 메뉴는 지금 항목 그대로에 **열기**, **외부 편집기로 열기**를 둔다.
- 탭 종류 `{ kind: 'file'; id }`를 `workspaceLayout.ts`에 더한다. 파일 탭은 원본 연결(SSH 연결 ID, 로컬 대상 ID, FTP 연결 ID)과 경로를 가진다. 연결이 끊기면 읽기 전용으로 남고 저장은 막는다.
- **형식별 표시:** 확장자·첫 바이트로 고른다. 코드·설정 파일은 구문 강조, Markdown은 원문/미리보기 전환(미리보기는 HTML을 정화하고 원격 이미지는 불러오지 않음), JSON은 원문 그대로 보여주고 **정리해서 보기** 전환, 이미지(PNG·JPEG·GIF·WebP·SVG는 `<img>`로만, 스크립트 실행 없음)는 그림으로.
- **상한:** 2MiB 넘는 텍스트는 "크게 열기"(읽기 전용, 구문 강조 끔)를 물은 뒤 32MiB까지(지금 `editor.rs`의 `LIMIT`와 같음). 바이너리는 열지 않고 크기와 형식만 보여준다.
- **인코딩:** SFTP·로컬은 UTF-8, BOM과 UTF-16을 알아본다. FTP는 세션 인코딩(CP949 등)을 따른다. 깨지는 바이트가 있으면 편집을 막고 알린다(저장 때 원본을 망가뜨리지 않기 위해). 상태바에 인코딩·줄바꿈(LF/CRLF)·들여쓰기를 보이고, 누르면 바꾼다.
- 읽기는 새 명령 `file_read(source, path)` 하나로 SFTP·FTP·로컬·WSL을 나눈다. 응답에 내용, 크기, 수정 시각, 내용 해시(저장 충돌 판단용)를 담는다.

구현에서 정한 것(2026-11-08):

- `file_read`는 세 번째 인자 `options`(`large`, `encoding`)를 받는다. 크게 열기와 인코딩 변경은 같은 명령을 다시 부르는 것이다. 처음 8KiB로 형식을 먼저 판단하고 형식이 허용하는 만큼만 더 읽는다. 바이너리·초과 파일은 끝까지 받지 않는다(FTP는 데이터 연결을 끊는다).
- 미리보기 여부는 탭 참조의 `preview` 표시로 둔다. 칸을 옮겨도 따라가므로 이동 연산을 고치지 않았다. 옮겨서 한 칸에 미리보기가 둘이 되면 다음에 파일을 열 때 하나만 남기고 나머지는 고정한다. 연산은 `app/workspaceTabs.ts`에 있고 GE.8의 diff 탭은 `DocumentRef`에 종류를 더하면 된다.
- 링크는 폴더일 수 있어 한 번 클릭으로 미리보기하지 않고 더블클릭도 패널의 원래 동작을 따른다. **열기** 메뉴로는 열 수 있다.
- Ctrl/Cmd·Shift 클릭은 선택만 한다. 여러 파일을 고르는 중에 탭이 바뀌면 안 되기 때문이다.
- FTP는 탭 자체가 파일 목록이라 같은 칸에 열면 목록이 가려진다. FTP에서 연 파일은 다른 칸에, 칸이 하나뿐이면 오른쪽에 새 칸을 만들어 연다(좁은 화면 제외).
- 파일 탭이 선택돼도 사이드바와 상태바는 그 파일을 연 터미널의 연결을 유지한다. 단축키가 쓰는 `selected`는 그대로 터미널 탭만 뜻한다(`owner`를 따로 뒀다).
- Markdown은 **미리보기가 기본**이다(사용자 결정 "형식에 맞게 표시"). 정화한 결과를 DOM 그대로 붙이고 HTML로 다시 파싱하지 않는다. `class`·`id`·`style`을 지워 문서가 앱의 조작부처럼 보이지 못하게 했다. 원격 이미지와 링크는 CSP로 막혀 앱 안에서 불러올 수 없으므로, 물어본 뒤 기본 브라우저로 연다. 파일 기준 상대 경로 이미지는 표시하지 않는다.
- JSON **정리해서 보기**는 파싱한 값을 다시 출력하지 않고 공백만 옮긴다. `JSON.parse`를 거치면 큰 정수와 중복 키가 바뀐다. 파싱은 유효성 검사에만 쓴다.
- 상태바의 인코딩을 누르면 다른 인코딩으로 다시 읽는다(GE.5). 줄바꿈·들여쓰기를 바꾸는 동작은 저장이 있어야 의미가 있어 GE.6으로 넘겼고 지금은 표시만 한다.
- 파일 탭에는 다시 읽기 버튼을 두지 않았다. 바깥에서 바뀐 파일은 탭을 닫았다 열어야 새로 읽는다. 외부 변경 처리는 충돌 판단과 함께 GE.6에서 정한다.
- `marked` 14.0.0, `dompurify` 3.4.17을 직접 의존성으로 올렸다. 둘 다 Monaco가 이미 쓰는 같은 버전이라 새 패키지는 없다. 미리보기 청크에서만 불러온다.

### GE.6 — 내장 편집과 저장

- 편집하면 탭에 `●`(저장 안 됨). `Ctrl/Cmd+S` 저장, `Ctrl/Cmd+Shift+S` 다른 이름. 탭이나 앱을 닫을 때 저장 안 된 탭이 있으면 저장 / 저장 안 함 / 취소를 묻는다.
- 저장은 새 명령 `file_write(source, path, content, baseHash)`. 서버 파일은 기존 임시 파일 규약(`.dachsterm-*`)과 원자 교체(`editor.rs`의 `atomic_replace`)를 다시 쓴다. 쓰기 직전 서버 내용 해시가 `baseHash`와 다르면 쓰지 않고 충돌 카드(덮어쓰기 / 서버 내용 보기(diff) / 취소)를 띄운다.
- 내장 편집기는 사용자가 직접 저장하는 것이므로 GE.1의 확인 카드는 띄우지 않는다. 확인 카드는 외부 편집기처럼 앱이 저장을 "감지"하는 경우에만 쓴다.
- Notepad++식 기능: 세로 선택, 줄 복제·이동, 정규식 찾기·바꾸기, 공백 문자 보기, 줄바꿈 토글. Monaco면 대부분 기본이다.
- 파일 크기 상한 때문에 `features/editor/`(탭, 편집기 감싸기, 형식 판단, 저장 흐름)로 새 기능 폴더를 만든다. `App.tsx`는 탭 렌더 분기 한 줄만 바꾸고 순증하지 않는다.

구현에서 정한 것(2026-11-08):

- `file_write(source, path, content, encoding, baseHash)`다. `baseHash`는 사용자가 읽은 내용의 해시이고 **없으면(null) 새 파일**이라 이미 있으면 충돌이다. 인코딩은 `file_read`가 돌려준 표시(`utf-8-bom`, `utf-16le` 등)를 그대로 보낸다. `encoding_rs`에 UTF-16 인코더가 없어 UTF-16은 직접 쓴다.
- 응답의 충돌은 **지금 파일의 해시**(없어졌으면 null)를 담는다. 덮어쓰기는 이 해시를 `baseHash`로 다시 저장하는 것이다. 덮어쓰기 전용 인자가 없으니, 카드를 본 뒤 또 바뀌었으면 다시 충돌한다. 다른 이름으로 저장도 같은 경로다(이미 있으면 카드).
- 순서는 인코딩 → 옆에 임시 파일 작성 → **임시 파일을 쓴 뒤** 해시 비교 → 교체다. 업로드 시간만큼 충돌 판단이 늦어지지 않게 비교를 교체 바로 앞에 뒀다.
- 깨지는 바이트는 두 곳에서 막는다. 읽을 때 원래 바이트로 다시 인코딩되지 않으면 `lossy`로 표시해 편집을 막고(Shift_JIS 등은 다른 바이트 열을 같은 글자로 읽어 저장하면 안 고친 줄이 바뀐다), 저장할 때 그 인코딩으로 쓸 수 없는 글자가 있으면 저장하지 않는다.
- 링크는 따라가서 대상 파일을 바꾼다. 교체(rename)는 링크 자체를 일반 파일로 바꾸기 때문이다. FTP는 링크 대상을 알 수 없어 저장을 막는다. 교체는 폴더 권한만 보므로, 먼저 쓰기로 열어 읽기 전용 파일을 거부한다(FTP는 이런 확인 수단이 없다).
- 서버 소유자는 시도만 한다(일반 계정은 실패하고 그대로 저장). SFTP 권한은 그대로 복사한다. FTP는 `SITE CHMOD`를 시도하고, 안 되는 서버는 새 파일 기본 권한이 된다. FTP 교체는 업로드 덮어쓰기와 같은 백업 방식이라(`.dachsterm-*.backup`) 원자적이지 않고, 백업을 못 지우면 저장은 성공으로 두고 안내한다.
- WSL은 네트워크 공유로 권한을 읽고 쓸 수 없어 `wsl.exe`로 실제 경로와 권한을 읽고 `chmod`한다.
- 줄바꿈이 섞인 파일은 Monaco가 불러올 때 한 가지로 통일하므로, 편집 가능하면 안내 띠를 띄운다.
- 상태바: 줄바꿈(LF/CRLF)과 들여쓰기(탭, 공백 2, 공백 4) 변경은 편집 가능하고 편집기가 준비된 탭에서만 누를 수 있다. 공백 문자 보기와 자동 줄바꿈(Alt+Z)은 편집기 우클릭 메뉴에 두고 모든 탭에 공통으로 적용하며 `dachsterm.editor.view`에 기억한다. 세로 선택, 줄 복제·이동, 정규식 찾기·바꾸기는 Monaco 기본 동작이다.
- `Ctrl/Cmd+Shift+S`는 앱의 명령 창 단축키이므로 파일 탭이 포커스일 때만 다른 이름으로 저장이 가져간다. 저장 단축키는 창에서 받아 Markdown 미리보기나 탭 머리에 포커스가 있어도 동작한다.
- Markdown 미리보기·JSON 정리 보기로 바꿔도 편집기는 숨겨 두어 실행 취소와 커서를 유지한다. 파일 다시 읽기는 탭 메뉴의 **파일 다시 읽기**이고, 인코딩 변경을 포함해 편집 내용을 잃을 때는 먼저 묻는다.
- 편집을 시작한 미리보기 탭은 고정한다. 연결이 끊긴 탭은 읽기 전용이 되며 편집 내용은 남고 닫을 때 **저장 안 함**과 **취소**만 고를 수 있다.

### GE.7 — Git 실행 공용화와 Git 보기(읽기)

- **실행 경로 공용화:** DX.15의 `git_status/local.rs` 실행기(로컬 셸 없이, WSL `wsl.exe --exec sh -c`)와 원격 `remote_exec`를 `git_run(source, folder, args, limits)` 하나로 묶는다. `git_diff.rs`(819줄)는 이 위로 옮기며 나눈다(architecture-review 정리 목록과 같이 보고 진행). 모든 읽기는 지금의 안전 설정(`core.fsmonitor=false`, `GIT_OPTIONAL_LOCKS=0`, `LC_ALL=C`, diff에 `--no-ext-diff --no-textconv`)을 유지한다.
- **사이드바 Git 보기:** `features/git/GitView.tsx`. 머리줄: 브랜치, 앞섬·뒤처짐, `⋯`(새로 고침, 변경 검토, fetch/pull/push, 브랜치, stash). 목록: **스테이지됨**, **변경**, **추적 안 함**, **충돌** 묶음. 파일 행은 상태 글자와 폴더 경로를 흐리게. 폴더 단위 트리 보기 / 목록 보기 전환.
- 조회는 지금 `GitScheduler`를 쓰되, 스테이지 구분을 위해 `porcelain=v2`의 `XY` 두 글자를 앞뒤로 나눠 내려준다(지금은 한 글자로 합침). 추적 안 함 파일은 이 보기에서는 파일 단위(`-uall`)로, 단 5,000항목 상한은 그대로.
- Git이 없으면: "이 PC에서 git을 찾지 못했습니다 / 서버에 git이 없습니다"와 **설정 → Git** 링크, 설치 안내.

### GE.8 — diff 탭

- Git 보기에서 파일을 클릭하면 diff 탭(미리보기 규칙 같음): 스테이지됨은 `HEAD ↔ 인덱스`, 변경은 `인덱스 ↔ 작업 트리`, 추적 안 함은 새 파일 내용. 좌우 / 한 줄 보기 전환. 오른쪽(작업 트리)은 GE.6 편집기로 바로 고칠 수 있다.
- 행 우클릭: 파일 열기, diff 열기, 스테이지/스테이지 취소, 변경 버리기, 경로 복사, 외부 편집기로 열기, 탐색기에서 보기.

구현에서 정한 것(2026-11-08):

- 비교 기준은 판별 유니온 `headIndex`, `indexWorktree { deleted }`, `untracked`다. Git이 가진 쪽은 `ls-tree -z`·`ls-files --stage -z`로 객체를 찾아 `cat-file blob`으로 읽는다. 필터와 textconv가 돌지 않고, 파일이 없는 쪽을 stderr 문구가 아니라 빈 목록으로 판단한다(엔지니어링 규칙 §6). 그 때문에 SSH 탭에서는 한 번 여는 데 exec 채널을 차례로 최대 5번 쓴다(동시 사용량은 1개).
- 작업 트리 쪽은 `file_read`를 그대로 쓴다. 파일 탭과 같은 해시가 나와 GE.6의 `file_write` 충돌 판단이 그대로 동작한다. 작업 트리에서 지운 파일은 Git 목록의 표시로 판단해 읽지 않는다.
- 한쪽이라도 2MiB를 넘거나 바이너리면 비교하지 않고 이유만 보인다. 파일 탭의 **크게 열기**는 두지 않았다.
- 파일 탭과 diff 탭은 `useFileTabs`의 같은 목록에 있다(`diff` 필드). 칸마다 미리보기 하나를 두 종류가 함께 쓰고, `●`, 저장, 닫기·창 닫기 확인, 다시 읽기를 그대로 공유한다. 같은 파일의 스테이지됨·변경 행은 별개 탭이다.
- 충돌 행은 단일한 상대가 없어 diff 대신 파일 탭으로 연다(머지 충돌 편집기는 제외 범위).
- 파일 저장과 Git 보기의 동작을 `lib/gitChanges.ts`로 서로 알린다. 탭에서 저장하면 Git 보기를 새로 고치고, Git 보기에서 스테이지 등을 하면 열린 diff를 다시 읽는다. 다시 읽을 때 왼쪽은 항상 따라가고, 오른쪽은 내용이 실제로 바뀌었고 저장 안 한 편집이 없을 때만 바꾼다. 터미널에서 친 `git add`는 알림이 없어 탭 우클릭 **다시 읽기**로 맞춘다.
- `Ctrl/Cmd+Shift+S`는 diff 탭에서 명령 창을 그대로 연다. diff 탭은 저장소의 그 파일에 묶여 있어 다른 이름 저장이 없다.
- 인코딩·줄바꿈 상태바와 인코딩 변경은 diff 탭에 두지 않았다. UTF-8로 깨지는 파일은 편집을 막고, 인코딩을 바꾸려면 파일 탭을 쓴다.
- **외부 편집기로 열기**는 파일 패널에서 마지막으로 고른 편집기로 묻지 않고 연다(기본 `code`). **탐색기에서 보기**는 이 컴퓨터의 파일만 해당하므로 로컬·WSL 탭에만 나온다.
- 알려진 한계: 심볼릭 링크는 Git 쪽이 링크 대상 문자열이고 작업 트리 쪽은 링크가 가리키는 파일 내용이라 전부 달라 보인다. 커밋 그래프의 파일 행은 GE.15에서 커밋과 부모의 diff로 이었다.

### GE.9 — Git 쓰기 동작

실행 위치를 둘로 나눈다.

| 동작 | 실행 | 이유 |
|---|---|---|
| 스테이지·취소(파일, 전체), 커밋(메시지, `--amend`), 브랜치 만들기·전환, stash 넣기·꺼내기, 태그 | 앱이 Git 보기의 실행 경로로 직접 실행 | 인증이 필요 없고 결과를 바로 다시 조회 |
| 변경 버리기 | 앱이 실행, **확인창 필수**(되돌릴 수 없음, 파일 목록 표시). 추적 안 함 파일 삭제는 따로 묻는다 | 데이터 손실 |
| fetch, pull, push, 원격 브랜치 체크아웃 | **그 탭의 터미널에 명령을 입력해 실행**(사용자가 Enter를 누르는 것과 같게 보이게) | 비밀번호·2단계 인증·호스트키 질문이 터미널에 그대로 뜨고, DX.2·DX.11~14의 키·자격 증명 전달이 셸 환경에서 동작한다. 앱이 몰래 실행하면 질문이 나올 곳이 없어 멈춘다 |

- 강제 push(`--force`)는 메뉴에 두지 않는다. 필요하면 `--force-with-lease`만 `⋯ → push → 강제(안전)`로 두고 확인창을 거친다.
- 터미널이 명령 실행 중(DX.9 상태로 판단)이면 네트워크 동작을 막고 "터미널이 사용 중입니다"를 알린다. tmux 탭은 활성 pane에 입력한다.
- 커밋 실패의 흔한 원인(이름·이메일 없음, 훅 실패)은 stderr 첫 줄과 함께 보여주고, 이름·이메일이면 **설정 → Git**으로 안내한다. 사전 커밋 훅은 저장소 설정이므로 그대로 실행된다(`--no-verify` 메뉴는 두지 않는다).
- 실행한 Git 명령은 Git 보기 아래 **출력** 접이식 영역에 최근 50개를 남긴다(VS Code의 Git 출력과 같은 용도). 내용과 의견은 로그·진단 내보내기에 남기지 않는다.

구현에서 정한 것(2026-11-08):

- `GIT_LITERAL_PATHSPECS=1`은 자식 프로세스로 상속된다. `stash --include-untracked`가 내부에서 부르는 `git clean ... :/`와 커밋 훅의 `:(exclude)`가 깨지므로, 경로를 받지 않는 동작(`commit`, 브랜치 만들기·전환, `stash`)에는 `--no-literal-pathspecs`를 붙인다. 경로를 받는 `add`, `reset`, `checkout --`, `clean`은 글자 그대로 둔다.
- 스테이지 취소는 `git reset -q`(첫 커밋 전에도 동작, Git 2.23 미만 서버 포함), 변경 버리기는 `git checkout -q --`(스테이지한 쪽은 남음), 추적 안 함 삭제는 파일 삭제가 아니라 `git clean -f -q --`(그 사이 Git이 추적하게 된 파일은 건드리지 않음)이다.
- 경로 목록은 16KiB마다 나눠 실행한다. Windows 명령줄 32K와, WSL 스크립트가 인자 하나로 들어가는 제약 때문이다. **그룹 전체 동작은 화면에 보이는 파일 목록만** 넘겨, 5,000개 상한 뒤의 보이지 않는 파일을 건드리지 않는다. 경로 없이 전체에 적용되는 것은 위험이 없는 `⋯ → 모두 스테이지`·`모두 스테이지 취소`뿐이다.
- `git_refs`의 입력을 연결 ID에서 **출처**로 넓혔다(브랜치 전환 목록이 로컬·WSL에서도 필요). 새 조회 명령은 만들지 않았다.
- 터미널 입력 판단(`gitTerminal.ts`): 프롬프트 대기 중이면 입력, 명령 실행 중·전체 화면이면 **터미널이 사용 중입니다**, 프롬프트에 글자가 남아 있으면 막음(입력에 덧붙지 않게), 저장소 폴더 밖이거나 폴더를 모르면 막음. **프롬프트를 보고하지 않는 셸(PowerShell, cmd, 훅 없는 셸)과 tmux는 상태를 알 수 없으므로 명령을 보여 주고 확인을 받는다(기본 취소).** tmux는 화면이 항상 보조 화면이라 전체 화면 판단을 쓸 수 없고, 폴더만 `tmux_current_path`로 확인한다.
- 원격 브랜치 체크아웃의 `git checkout --track <이름>`은 셸마다 인용이 달라 인용하지 않는다. 글자·숫자·`_`·`.`·`/`·`-`만으로 된 이름만 입력하고 나머지는 직접 입력하도록 안내한다.
- 명령 실행 시간 상한은 120초(커밋 훅), 출력은 stdout 8MiB, stderr 64KiB만 남기고 끝까지 읽어 버린다. 전에는 상한을 넘은 뒤 파이프를 비우지 않아 훅이 많이 출력하면 커밋이 시간 초과까지 멈췄다(`git_run.rs`의 `read_capped`).
- 이름·이메일이 없는 커밋 실패는 stderr 문구가 아니라 `git var GIT_AUTHOR_IDENT`·`GIT_COMMITTER_IDENT`의 종료 코드로 판단한다(엔지니어링 규칙 §6).
- 첫 푸시용 `git push -u origin <브랜치>` 메뉴는 두지 않았다. 원격 이름을 추측해야 하므로, 업스트림이 없을 때는 `git push`의 안내를 터미널에서 그대로 본다. 커밋 실패 안내의 **설정 → Git**은 GE.10이 만든 `requestSettings`로 연결했다.

### GE.10 — 설정 → Git

새 분류 **Git**(`features/settings/GitSettings.tsx`). Git 자동 조회(지금 터미널 분류)와 HTTPS Git 자격 증명(지금 에이전트 분류)을 여기로 옮기고, 원래 자리에는 링크만 남긴다.

1. **Git 위치(이 PC):** 자동으로 찾은 경로와 버전(`git --version`)을 보여주고, 직접 지정(파일 선택)할 수 있다. 지정 경로가 없거나 실행되지 않으면 오류로 알리고 자동 찾기로 돌아가지 않는다. Mac은 명령줄 도구가 없을 때 `/usr/bin/git`을 실행하지 않고 설치 안내를 보인다(DX.12 규칙 유지). WSL·서버는 각자의 `PATH`의 git을 쓴다.
2. **표시 방식(미리보기와 함께):**
   - 터미널 안 브랜치: 프롬프트 줄 오른쪽 / 끔 (GE.11)
   - 표시 내용: 브랜치만 / 변경 수 / 앞섬·뒤처짐까지
   - 파일 트리: 글자(`M`, `?`) / 파일 이름 색 / 둘 다
   - 상태바 표시: 켬 / 끔
   - 자동 조회: 켬 / 끔(지금 설정), 추적 안 함 파일을 폴더로 / 파일로
3. **Git 설정 편집(`git config`):** 위쪽에서 **대상**을 고른다: 이 PC / WSL 배포판(목록) / 현재 SSH 연결의 서버. 범위는 사용자 전역(`--global`), Git 보기의 `⋯`에서는 저장소(`--local`)도 연다. 값은 그 대상에서 읽어 오고, 사용자가 바꾼 항목만 `git config --global <키> <값>`으로 쓴다.
   - 항목: `user.name`, `user.email`, `init.defaultBranch`, `pull.rebase`(false/true/merges), `pull.ff`, `fetch.prune`, `push.autoSetupRemote`, `push.default`, `core.autocrlf`(true/input/false), `core.eol`, `core.editor`, `merge.conflictStyle`(merge/diff3/zdiff3), `rebase.autoStash`, `rerere.enabled`, `credential.helper`(읽기 표시만, 바꾸려면 직접 입력), `safe.directory`(목록 보기와 추가, 와일드카드 `*`는 경고).
   - 쓰기 전 최종 명령을 보여주고 확인받는다. 설정 파일을 직접 고치지 않고 항상 `git config`를 거친다.

구현에서 정한 것(2026-11-08):

- 설정 창은 다른 대화상자를 열지 않는다는 규칙에 따라 최종 명령 확인은 대화상자가 아니라 분류 안의 카드로 띄운다. 미리보기와 실행은 Rust의 같은 함수에서 명령을 만들어 둘이 달라질 수 없다(`git_config_preview`, `git_config_write`).
- 읽기는 표의 키만 `--get-regexp`로 묻는다. `http.extraHeader` 같은 다른 항목은 대상 밖으로 나오지 않는다. `credential.helper`는 값이 `!`로 시작하거나 `@`, `password`, `token`, `secret`, `key=`를 담으면 내용을 보내지 않고 "숨김"으로만 알린다.
- 값이 여러 개인 키를 바꾸면 그때만 `--replace-all`·`--unset-all`을 붙인다. `safe.directory`는 Git이 저장소 설정에서 읽지 않으므로 저장소 범위에서는 뺐다.
- 사용자 지정 Git은 DB `git-program`에 두고 `git_program()`이 읽는다. `GitHost::local`에 저장소를 넘기지 않으려고(GE.9와 충돌 방지) 값은 프로세스 전역 변수에 두고 시작할 때 읽는다. 손상된 값은 자동 찾기로 넘어가지 않고 Git 없음으로 동작하며 설정 화면에 알린다.
- `features/settings`가 다른 기능을 import하지 않도록 표시 설정(`app/GitDisplaySettings.tsx`)과 자격 증명은 `app/GitSettingsSection.tsx`가 넣는다. 새 표시 설정은 `lib/gitDisplay.ts`(`dachsterm.gitDisplay`)에 두고, `promptBranch`·`gitStatus`는 셸 훅 삽입에 쓰이므로 터미널 설정에 그대로 둔다.
- 표시 내용은 프롬프트 배지와 상태바에 함께 적용한다. 에이전트 보드의 Git 글자는 바꾸지 않는다. 추적 안 함 파일 설정은 상태바·파일 트리 조회(`git_status`, `local_git_status`의 `untrackedFiles`)에만 적용하고, Git 보기는 GE.7대로 항상 파일 단위다.
- 저장소 범위는 Git 보기 `⋯ → 이 저장소의 Git 설정…`으로만 열리며 대상 목록의 첫 항목으로 나타난다. 어디서든 설정을 열 수 있게 `lib/settingsRequest.ts`를 두었다.

### GE.11 — 터미널 안 브랜치

**브랜치 출처:** 셸 훅이 프롬프트마다 `.git/HEAD`를 셸 내장 명령만으로 읽어 `OSC 777;DachsTerm;branch;<이름>`으로 알린다(프로세스 실행 없음). 지금 Git 조회는 프롬프트 기준 5초 간격이라 checkout 직후 예전 브랜치가 보일 수 있어서다.

```sh
# 개념 코드. Bash 3.2·Zsh 공통, 작은따옴표 없음(훅 전체가 한 eval 안에 있음)
__dachsterm_head() {
  local d=$PWD g h
  while :; do
    if [ -f "$d/.git/HEAD" ]; then g=$d/.git; break
    elif [ -f "$d/.git" ]; then read -r h < "$d/.git"; g=${h#gitdir: }
      case $g in /*) ;; *) g=$d/$g;; esac; break; fi
    [ -z "$d" ] && { printf "\033]777;DachsTerm;branch;\007"; return; }
    d=${d%/*}
  done
  read -r h < "$g/HEAD" || return
  case $h in "ref: refs/heads/"*) h=${h#ref: refs/heads/};; *) h=@${h:0:7};; esac
  printf "\033]777;DachsTerm;branch;%s\007" "$h"
}
```

- `__dachsterm_cwd`에서 `CurrentDir` 다음, `133;A` 앞에 부른다. worktree·submodule의 `.git` 파일은 `gitdir:`을 한 번 따라간다. 분리된 HEAD는 `@`+7자, 저장소 밖은 빈 값. 앱은 200자로 자르고 제어 문자를 버린다. 재생 중 받은 값은 무시한다.
- 받은 브랜치가 마지막 Git 조회와 다르면 `GitScheduler`에 새 사건 `branch`(최소 간격 0)를 보내 상태바·파일 트리·Git 보기도 바로 따라오게 한다.

**표시:** `FailedCommandMarks`와 같은 방식의 오버레이 `PromptBranch`.

- 프롬프트에서 입력을 기다리는 동안만(`133;A` 뒤, 명령 시작 전). 실행 중·보조 화면(vim, less)에서는 숨긴다.
- 커서가 있는 줄의 오른쪽 끝. 두 줄 프롬프트, `Ctrl+L`, 창 크기 변경에도 입력 줄을 따라간다. 현재 프롬프트에만 그린다.
- 그 줄의 글자가 배지 2칸 앞까지 오면 숨기고, 입력이 다음 줄로 넘어가면 숨긴다. 프롬프트 줄에 같은 브랜치 이름이 이미 있으면(사용자 프롬프트 테마) 그리지 않는다.
- 내용 `⎇ main ●3`(GE.10 표시 내용 설정을 따름). 변경 수가 그 프롬프트보다 오래된 조회 결과면 흐리게. 최대 24칸, 넘으면 가운데 줄임. 40칸 미만 터미널에는 그리지 않는다.
- `aria-hidden`, 터미널 버퍼에 글자를 쓰지 않는다(복사·검색·세션 기록·화면 읽기 무변경). 누르면 Git 조회 새로 고침, 툴팁은 `gitTooltip`.

**적용 탭:** SSH Bash·Zsh(훅 있음) 표시 / tmux 제외(화면을 tmux가 그림) / 훅 없는 셸 제외 / WSL Bash 표시(`WSL_FOLLOW`에 같은 함수, ConPTY 커서 줄은 GE.0 실측) / Mac 로컬 Bash·Zsh 표시 / PowerShell 후속 / cmd 제외.

구현에서 정한 것(2026-11-08, GE.0 실측은 [검증 기록](../verification/prompt-branch.md)):

- 보고 값에 인쇄할 수 없는 문자가 있으면 셸에서 빈 값으로 보낸다. `.git/HEAD`는 폴더 안의 파일이라, 개념 코드대로면 그 안의 이스케이프 시퀀스가 터미널에 그대로 전달된다. 앱의 제어 문자 제거는 OSC가 끝난 뒤의 일이라 이를 막지 못한다.
- `HEAD`를 읽지 못하면 이전 값을 남기지 않고 빈 값을 보낸다. reftable 저장소의 `ref: refs/heads/.invalid`도 빈 값이다. Git 기본값이 reftable로 바뀔 수 있어 처리했다.
- 빈 값이어도 Git 조회가 저장소를 알면 그 브랜치를 그린다(`LANG=C`의 한글 브랜치, reftable).
- 같은 보고가 Git과 계속 다르면 `branch` 사건은 폴더·값 조합당 한 번만 보낸다. 프롬프트마다 조회가 도는 것을 막는다.
- WSL은 프롬프트 대기를 알아야 하므로 `WSL_FOLLOW`에 `133;A`를 더했다(`C`, `D`는 넣지 않음). 그 결과 WSL 탭에서도 프롬프트 이동과 프롬프트 기준 Git 조회가 동작하고, 실패 표시는 지금처럼 없다.
- 기능 간 직접 import를 늘리지 않기 위해 오버레이는 `src/app/PromptBranch.tsx`에 두고 `TerminalPane`의 `children`으로 넣는다. `GitScheduler`에는 `branch` 사건만 더했고, 조회 시각은 `useGitStatus.ts`의 저장소 객체가 기록한다.
- 프롬프트 테마의 브랜치 판단은 앞 글자가 `/`, `\`, `~`면 폴더 이름으로 본다. 입력 중인 명령에 같은 이름이 있으면 그동안 숨는다.

### GE.12 — 상태바

- Git 항목 앞에 브랜치 아이콘. 바뀐 파일이 없어도 Git 표시인지 알아보게 한다. 누르면 Git 보기를 연다(지금은 새로 고침).
- 파일 탭이 선택되면 상태바 오른쪽에 인코딩·줄바꿈·들여쓰기·언어(GE.5).

구현에서 정한 것(2026-11-08):

- 저장소 항목을 누르면 Git 보기를 열면서 다시 조회도 한다. 자동 조회를 끈 사용자에게는 이 클릭이 상태를 갱신하는 경로였기 때문이다. Git 보기는 상태가 바뀌면 함께 다시 읽는다.
- **Git 조회 멈춤**과 자동 조회를 껐을 때의 **Git**은 지금처럼 조회만 한다. 멈춘 저장소는 Git 보기도 같은 조회로 막히고, **Git**은 아직 저장소인지 모르는 폴더를 묻는 버튼이다. 세 상태 모두 아이콘은 붙는다.
- 독립 창에는 사이드바가 없어 클릭은 새로 고침으로 남는다. `showGit`을 넘기지 않는 것으로 나뉜다.
- 파일 정보는 GE.5의 `FileStatusItems`를 그대로 쓴다. 실제 상태바의 버튼 규칙이 인코딩 태그에만 적용돼 크기·배경이 달랐던 것을 고쳤다.

### GE.14 — 커밋 그래프(읽기 전용)

VS Code 소스 제어의 **그래프**를 기준으로 하며, 쓰기 동작(체크아웃, cherry-pick, revert, 태그·브랜치 만들기)은 메뉴에 두지 않는다.

- **표시 위치:** Git 보기 아래쪽의 접이식 구역 **그래프**. 펼치면 변경 목록과 세로를 반씩 나누고 각자 스크롤한다. 접은 상태는 `dachsterm.gitView.graph`에 기억하고, 접혀 있으면 조회하지 않는다. 저장소가 아니면 구역이 없다.
- **보여 주는 커밋:** `HEAD`와 그 upstream에서 닿는 커밋(업스트림이 없거나 분리된 HEAD면 `HEAD`만). `--topo-order`로 부모가 자식보다 먼저 나오지 않게 한다. 모든 브랜치 보기는 GE.15에서 추가했다.
- **커밋 수 상한:** 처음 100개, 목록 끝의 **더 불러오기**로 100개씩, 최대 1,000개. 상한에 닿으면 "최근 1,000개까지만 표시합니다"를 보인다. 커밋을 하나 더 요청해 다음이 있는지 판단한다. 더 불러올 때는 처음부터 다시 조회한다. 그 사이 새 커밋이 생겨도 `--skip`처럼 어긋나지 않는다.
- **조회 제한:** 15초, 출력 4MiB. 넘으면 이유와 **다시 조회**를 보인다. 큰 저장소에서 `--topo-order`는 전체 이력을 걷을 수 있어 시간 제한이 실제로 쓰인다.
- **다시 조회:** 저장소 객체가 알린 HEAD·upstream·앞섬·뒤처짐이 바뀌거나 머리줄의 새로 고침을 누를 때. 앞선 요청이 끝난 뒤 최신 요청 하나만 보낸다.
- **행:** 그래프, 제목, 참조 배지(현재 브랜치, 브랜치, 원격, 태그, 최대 3개와 `+N`). `refs/remotes/*/HEAD`는 표시하지 않는다. 툴팁은 짧은 해시·작성자·시각·제목.
- **커밋 클릭:** 그 행 아래로 펼쳐 전체 해시, 작성자, 시각, 부모, 전체 메시지, 바뀐 파일 목록을 보인다. VS Code에서 커밋을 펼치는 것과 같고, 한 번에 하나만 펼친다. 다시 누르면 닫는다. 커밋은 바뀌지 않으므로 받은 상세는 그 구역이 살아 있는 동안 다시 조회하지 않는다.
- **파일 목록:** 병합 커밋은 첫 번째 부모와 비교하고, 최초 커밋은 빈 트리와 비교한다. 5,000항목 상한이 지나거나 시간·크기 제한에 걸리면 목록이 잘렸음을 표시한다. 파일 행을 눌러 diff를 여는 것은 GE.8 뒤에 잇는다(지금은 표시만).
- **우클릭:** 전체 해시 복사, 제목 복사. Enter·Space로 펼치고, 위아래 화살표로 행을 옮긴다.
- **배치 계산:** `commitGraphModel.ts`의 순수 함수(이름을 `commitGraph.ts`로 하면 `CommitGraph.tsx`와 대소문자만 달라 충돌). 각 칸은 다음에 나올 커밋(lane)을 기다린다. 커밋이 기다리던 칸이 여럿이면 그 칸들이 커밋으로 모이고, 첫 번째 부모가 커밋의 칸을 잇고, 나머지 부모는 오른쪽에 새 칸을 연다. 칸 색은 칸이 열릴 때 정해 끝까지 유지한다. 칸이 많으면 칸 폭을 줄여 전체 폭 96px 안에 넣는다.
- **안전 설정:** `git_run`의 설정에 더해 `--no-show-signature`(저장소의 `log.showSignature`와 `gpg.program`이 프로그램을 실행하지 못하게), `--no-color`, `--encoding=UTF-8`, diff에 `--no-ext-diff --no-textconv`. 해시는 40·64자 16진수만 받는다. 참조 이름은 Git이 준 `refs/` 이름만 넘긴다.

### GE.15 — Git 보기 마감

2026-11-08 사용자 요청: 그래프와 변경 목록의 상하 크기 조절, 명령 아이콘, 브랜치 전환, 커밋 정보와 파일 미리보기를 VS Code 소스 제어 화면처럼. GE.14의 일부 결정(인라인 상세, 모든 브랜치 없음, 파일 행은 표시만)을 이 절이 대체한다.

- **변경 목록과 그래프 분할:** `useGitPanes`가 위쪽 높이를 `dachsterm.gitView.changesHeight`에 기억한다. 양쪽 최소 72px, 더블클릭하면 반반. 창이 줄면 위쪽이 먼저 줄어든다(`flex: 0 1 <px>`). 접힌 그래프는 손잡이가 없다.
- **그래프 머리줄:** `자동/모두` 토글(`dachsterm.gitView.graphScope`), 현재 커밋으로 이동, fetch, pull, push, 이력 새로 고침. fetch·pull·push는 GE.9와 같이 터미널에 입력한다. 머리줄 **⋯**는 넣지 않았다. 나머지 명령은 Git 보기 위쪽 **⋯**에 있다.
- **`git_graph` 범위:** `scope: auto | all`. `all`은 `--branches --remotes --tags HEAD`다. `--all`은 `refs/stash`까지 걷으므로 쓰지 않는다.
- **커밋 정보:** 트리 안에 펼치던 해시·작성자·메시지는 호버 카드(`CommitHoverCard`)로 옮겼다. 350ms 뒤 열리고 카드로 포인터를 옮길 수 있다. 스크롤·클릭·우클릭·Esc로 닫는다. 키보드는 `:focus-visible` 포커스일 때 연다. 카드를 열 때 상세를 읽고, 펼치기와 같은 캐시를 쓴다. `Co-Authored-By` 줄은 작성자 아래로 옮긴다. `git_commit_detail`에 `--numstat`을 더해 줄 수를 합산한다.
- **참조 배지:** 브랜치와 원격 브랜치는 이름을 쓴다(다른 worktree에 체크아웃된 브랜치도 구별되게). 같은 커밋에 같은 이름의 원격 브랜치가 있으면(`origin` 우선) 로컬 배지 하나에 구름 아이콘으로 합친다. 태그는 아이콘만 쓰고, 이름은 카드와 툴팁에 있다. 좁으면 이름이 말줄임으로 줄고 4번째부터는 `+N`이다.
- **커밋 파일 diff:** `Compare::Commit { hash, parent }`. 양쪽을 `ls-tree`와 blob으로 읽어 작업 트리를 보지 않고, 항상 읽기 전용이다. 병합 커밋은 첫 부모, 최초 커밋은 왼쪽이 없다. 해시는 `check_hash`를 거친다. `sameDiffTarget`은 커밋마다 다른 탭으로 본다.
- **브랜치 전환:** 머리줄의 브랜치 이름을 누르면 빠른 선택(`GitBranchPicker`)이 뜬다. 입력으로 좁히고 화살표·Enter로 고른다. 맨 위는 새 브랜치 만들기이고, 입력과 맞는 브랜치가 있으면 그 첫 항목이 선택된다. 상태바의 Git 항목은 GE.12대로 Git 보기를 연다.
- **설명과 파일 아이콘:** Git 보기의 버튼은 `data-tip`과 `useHoverTips`(`components/HoverTips.tsx`)로 250ms 뒤 설명을 보인다. 브라우저 `title`은 1초 넘게 걸려 쓰지 않는다. 비활성 커밋 버튼은 포인터 이벤트를 받지 못해 바깥 span에 둔다. 파일 앞 아이콘은 `components/fileType.ts`의 확장자표이고, 색은 상태 토큰이다. 글자형 아이콘은 `::before`라 행의 글자에 섞이지 않는다. 파일 트리(`FileTreeRow`)도 같은 아이콘을 쓰고, 폴더 행의 일반 클릭은 꺽쇠와 같이 열고 닫는다. 수정 키를 누른 클릭은 선택만 하고, 더블클릭의 폴더 이동은 그대로다.
- **행 버튼:** 파일 행과 묶음 제목에 마우스를 올리거나 포커스가 있을 때만 파일 열기·되돌리기·스테이지 아이콘을 보인다(상시 버튼 금지 규칙). 동작은 우클릭 메뉴와 같은 `rowItems`·`groupItems`에서 온다. 키보드는 기존 우클릭 메뉴를 쓴다.

## 6. 보안

- 모든 Git 실행은 DX.5의 안전 설정을 유지한다. clean 필터와 커밋 훅은 저장소 설정이라 실행될 수 있음을 안내서에 적는다(DX.5와 같은 남는 위험).
- 파일 탭의 Markdown·SVG는 스크립트를 실행하지 않는다(정화, `<img>`로만). 원격 이미지와 링크는 열기 전에 묻는다.
- 되돌릴 수 없는 동작(변경 버리기, 추적 안 함 삭제, 강제 push, 덮어쓰기 저장)은 확인창. 기본 선택은 취소.
- 연결 한정 자동 업로드는 저장하지 않는다. 재접속 뒤 같은 파일도 다시 묻는다.
- `git config` 쓰기는 사용자가 바꾼 키만, 최종 명령을 보인 뒤에. 비밀(토큰)은 설정 화면에 표시하지 않는다.

3. PowerShell 프롬프트 브랜치: 후속(사용자 의견 "빠져도 됨").
