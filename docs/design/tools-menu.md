- 작업 ID: **TL.0~TL.10**, 설계일: **2026-11-08**.
- 현재 상태: **설계 확정(2026-11-08 사용자 승인). TL.0~TL.7 구현, TL.8~TL.10은 구현 전.** 구현 상태의 정본은 [progress.md](../progress.md)다.

## 1. 목표와 사용자 결정

**도구 메뉴를 세션 없이 바로 쓰는 단독 도구의 입구로 만든다.** 지금 메뉴에는 게임과 터널만 있다. 사용자가 연계 업무에서 자주 하는 "A에서 B까지 통신이 되는가, 어디까지 갔는가" 확인을 앱 안에서 끝내는 것이 가장 큰 목적이다.

사용자 결정(2026-11-08):

| 항목 | 결정 |
|---|---|
| 터널 | 도구 메뉴에 등록하고 제목 줄 아이콘과 단축키도 유지한다 |
| SSH 키 | "키 만드는 거" 하나만 넣는다. 호스트 키 관리, 전송 현황은 이번 범위에서 뺀다 |
| 문서 편집기 | 도구로 넣는다 |
| 네트워크 도구 | **포트 개통, 포트 사용 여부, 서비스 연결** 3개의 독립 도구. 서비스 연결의 상세는 펼쳐서 본다 |
| 출발지 | 도구마다 `로컬(기본) \| 리모트`. 리모트는 **등록된 세션 정보**로 연결한다 |
| 입력 | 출발지 A와 최종 목적지 B만 넣는다. 중간 장비 IP는 사용자가 모르므로 입력받지 않고 경로 추적으로 찾는다 |
| 서버 조건 | 서버에 아무것도 설치하지 않는다 |

제외: 호스트 키 관리, 전송 현황, 사용자가 구간을 하나씩 적는 구간 표, UDP 개통 확인, ping 기반 호스트 탐색, SYN·위장 등 연결 외의 스캔 기법, 결과 장기 보관, WSL을 출발지로 쓰기(§8).

## 3. 화면 구성

메뉴:

```text
도구
  터널
  SSH 키 만들기
  문서 편집기
  네트워크
    포트 개통
    포트 사용 여부
    서비스 연결
  게임
    (7개)
```

- SSH 키 만들기는 짧은 입력이라 대화상자(`Dialog` M)다. 편집기는 기존 파일 탭을 쓴다.
- 네트워크 도구는 결과가 길고 나란히 볼 일이 많아 **가운데 탭**이다. `TabRef`에 `{ kind: 'tool'; id: ToolId }`를 추가한다. 같은 도구는 탭 하나만 연다.
- 도구 목록은 `src/features/tools/catalog.ts`, 탭 열기·닫기는 `app/useToolTabs.tsx`에 둔다. 도구 코드는 게임처럼 lazy 로드한다.

네트워크 도구 공통 머리:

```text
출발지  (•) 로컬  ( ) 리모트 [세션 검색 ▾]
대상    [10.0.0.5            ]  포트 [22,80,8000-8100]     [점검]
```

- 리모트 선택 목록은 등록된 **SSH 세션**이다. FTP 세션은 넣지 않는다. 상태 표시는 `연결됨`(재사용), `미연결`.
- 화면에 상시 버튼을 늘리지 않는다(규칙 §7). 결과 조작(복사, 다시 점검, 서비스 연결로 보기)은 결과 행의 우클릭 메뉴에 둔다.

## 4. 작업별 설계

### TL.0 — 실측

추측으로 정한 값을 코드 전에 확인한다. Docker의 OpenSSH와 iptables로 시험한다.

1. `direct-tcpip` 실패 구분: 포트 닫힘(REJECT), 패킷 버림(DROP), 경로 없음, `AllowTcpForwarding no`, `PermitOpen` 각각의 russh 사유 코드와 응답 시간.
2. 클라이언트가 시간 초과로 포기한 뒤 늦게 열린 채널이 새는지, 닫는 방법.
3. 한 연결에서 동시에 여는 `direct-tcpip` 수의 실제 상한.
4. 서버 이미지별 도구 유무(Alpine, Debian slim, Ubuntu, RHEL 계열): `ss`, `lsof`, `netstat`, `traceroute`, `tracepath`, `bash`, `nc`, 일반 계정에서의 동작.
5. Windows 일반 권한의 `GetExtendedTcpTable`, 프로세스 이름 조회, `IcmpSendEcho` 경로 추적.
6. 인증서 해석 크레이트 선택(`x509-parser` 등)과 `audit-windows`·고지 영향.
7. Mac: `/usr/sbin/lsof`, `/usr/sbin/traceroute -P tcp`의 일반 권한 동작. **실기기 대기**이며 결과가 없어도 다른 작업을 막지 않는다.

결과는 `docs/verification/tools-menu.md`에 적고 §6의 값과 다르면 이 문서를 고친다.

**결과(2026-11-08, Windows·Docker 실측 / Mac 대기):** [검증 기록](../verification/tools-menu.md). 인증서 해석은 `x509-cert =0.3.0`을 쓴다(새 크레이트 3개, 감사 0건, 라이선스 문서 있음). 리모트 판정과 상한은 TL.6과 §6에 반영했다.

### TL.2 — 도구 메뉴와 도구 탭의 틀

§3의 메뉴 구성, `tool` 탭 종류, `catalog.ts`, `useToolTabs.tsx`, 내용이 빈 네트워크 도구 탭까지. `App.tsx`는 순증 없이 고친다. 탭 복원과 칸 이동이 기존 탭과 같게 동작하는지 `workspaceLayout.test.ts`에 추가한다.

구현 결과(2026-11-08, [검증 기록](../verification/tools-menu.md#tl2tl5-도구-탭과-셸-없는-연결)). 설계에서 정한 부분:

- 메뉴는 `catalog.ts`의 `toolActions`(터널, SSH 키 만들기, 문서 편집기)와 `networkTools`로 그린다. 제목 줄 터널 아이콘과 단축키는 그대로다.
- 네트워크 도구 탭은 다른 탭처럼 재시작 후 복원되지 않는다. 저장되는 것은 칸 모양뿐이다.
- `App.tsx`는 마스터 암호 확인을 `useVaultGate.tsx`로 옮겨 817줄에서 811줄로 줄였다. 터미널 접속과 도구 탭이 같은 확인을 쓴다.

### TL.3 — SSH 키 만들기

- 입력: 파일 이름(기본 `id_ed25519`, 영문·숫자·`._-`만), 주석(기본 `사용자@PC`), Passphrase(선택, 두 번 입력), 저장 폴더(기본 `~/.ssh`, OS 폴더 창으로 변경).
- 종류는 **Ed25519만**. RSA는 §8.
- 처리: `spawn_blocking`에서 생성하고 Passphrase가 있으면 암호화해 OpenSSH 형식으로 저장한다. 비밀 인자는 첫 줄에서 `Zeroizing`.
- 파일: 같은 이름이 있으면 **거부**하고 덮어쓰지 않는다(`create_new`). `.pub` 쓰기에 실패하면 만든 개인키를 지운다. 권한은 Mac `0600`, Windows는 현재 사용자만 접근하는 ACL. Windows OpenSSH가 ACL을 검사하므로 실제 `ssh`로 합격을 확인한다.
- 완료 화면: 공개키 전문과 복사(`clipboard_write_text`), 저장 위치, 지문.
- 세션 폼의 키 파일 목록에 만든 키를 넣는 동작까지 포함한다. 서버 `authorized_keys`에 자동 등록은 §8.
- 합격: 생성한 키를 `ssh-keygen -y -f`가 읽고(Passphrase 있음·없음), 앱의 `ssh_keys::info`가 같은 지문을 내고, Docker OpenSSH에 실제 로그인된다.

구현 결과(2026-11-08, [검증 기록](../verification/ssh-key.md)). 위와 달라졌거나 정한 부분:

- 사용자 지시로 TL.2를 기다리지 않고 메뉴 항목을 `HeaderTools.tsx`에 직접 넣었다. TL.2가 `catalog.ts`를 만들 때 이 항목을 옮긴다.
- 대화상자가 `components/SshKeyDialog.tsx`에 있다. 세션 폼과 로컬 에이전트 설정의 키 목록(`components/KeyFileList`)이 함께 열어야 해서 `features` 아래에 둘 수 없다. lazy 로드는 그대로다.
- "키 파일 목록에 넣는 동작"은 키 목록과 로그인 키 경로 옆의 **새 키…**로 구현했다. 만든 키가 그 칸에 바로 들어간다. 메뉴에서 만든 키는 완료 화면의 경로를 쓴다.
- 기본 폴더와 주석을 화면에 미리 보여야 해서 `ssh_key_defaults`를 추가했다(§5).
- 저장 폴더는 OS 폴더 창 외에 직접 입력도 된다. 없는 폴더는 거부하고, 기본 `~/.ssh`만 만든다.
- Windows는 파일을 공유 없이 연 채로 ACL부터 바꾼 뒤 내용을 쓴다. 비밀이 상속 권한 파일에 닿는 순간이 없다.
- 파일 이름은 설계의 문자 제한에 더해 점으로 시작·끝나는 이름, `.pub`로 끝나는 이름, Windows 예약 이름을 거부한다.

### TL.4 — 문서 편집기

편집기는 이미 있으므로 새로 만들지 않는다. 이 작업은 터미널 없이 파일 탭을 여는 입구만 만든다(2026-11-08 사용자 지시로 범위 축소).

- 도구 메뉴의 **문서 편집기**를 누르면 OS 파일 선택 창을 띄우고, 고른 파일을 기존 파일 탭에 고정 탭으로 연다. 창을 닫으면 아무것도 열지 않는다. 항목은 도구 메뉴에 직접 추가하며 TL.2를 기다리지 않는다.
- 만들지 않는 것: 빈 새 문서, 첫 저장 창(`local_file_pick_save`), `Ctrl/Cmd+O`.
- `FileTab`의 소유 정보는 판별 유니온 `owner`다(`terminal`이면 `sessionTabId`·`connectionId`, `none`이면 없음). 소유 터미널이 없는 탭은 `live`가 항상 참이다. 터미널 소유가 있는 탭의 동작은 바꾸지 않는다.
- 출처는 이 PC의 첫 비WSL 로컬 대상(`Source::Local`)을 쓴다. 새 출처 종류를 만들지 않는다. 앱 시작 때의 목록은 실패했거나 오래됐을 수 있어 파일을 고른 뒤 `local_targets`로 다시 읽는다.
- 파일 창은 `rfd`로 새 명령 `local_file_pick` 하나다.
- 닫을 때는 기존 저장 확인을 그대로 쓴다.
- 합격: 세션 없이 파일 열기, 저장, 한글 파일 이름, 저장 안 하고 닫기 확인. 편집기 부품 경계(`CodeEditor.tsx`) 밖의 import를 추가하지 않는다.

### TL.5 — 셸 없는 SSH 연결과 출발지 선택

리모트 도구의 공통 기반이다.

- `ssh.rs`의 경유·인증 부분을 새 파일로 꺼내 공용으로 쓴다(`ssh.rs`는 줄어야 한다). 터미널 연결은 그 뒤에 PTY를 잇고, 새 경로는 여기서 멈춘다.
- 새 경로는 PTY, 셸, 세션 로그, Git 자격 증명, 에이전트 전달, **터널 자동 시작을 하지 않는다.**
- 같은 프로필로 이미 연결된 탭이 있으면 그 연결을 재사용한다.
- 없으면 등록된 세션의 호스트·계정·저장 비밀·경유 설정으로 접속한다. 비밀이 저장돼 있지 않거나 최초 호스트 키면 기존 인증·호스트 키 카드를 도구 탭 안에 띄운다. 카드는 터미널 쪽에서 꺼내 공용으로 쓴다.
- 수명: 소유자는 도구 탭이다. 탭을 닫거나 5분간 쓰지 않으면 끊는다. 재사용한 연결은 끊지 않는다.

구현 결과(2026-11-08, [검증 기록](../verification/tools-menu.md#tl2tl5-도구-탭과-셸-없는-연결)). 위 설계를 구체화한 부분:

- 경유·인증은 `ssh/route.rs`로 옮겼고 슬롯 등록·정리는 `Connections::register`와 `finish`로 나눴다. `ssh.rs`는 649줄에서 445줄이 됐다. 터미널 경로의 동작은 바꾸지 않았다.
- 재사용 대상은 **터미널의 연결뿐**이다. 도구 탭끼리는 공유하지 않는다. 다른 도구 탭의 수명에 묶이지 않게 하기 위해서다. 저장된 세션과 접속 시점의 대상이 달라졌으면(편집 후) 재사용하지 않는다.
- 도구의 출발지 `connectionId`는 **도구 탭의 링크 ID**다. 재사용이면 백엔드가 터미널 연결로 풀어 준다. TL.6 이후 명령은 `Links::handle`로 연결을 얻는다. 이 함수가 미사용 시간도 다시 잰다.
- 같은 세션을 다시 고르면 `net_connect`가 같은 ID로 다시 불리고, 연결을 새로 만들지 않고 미사용 시간만 다시 잰다. 점검 기능이 붙는 TL.6부터는 점검 실행도 사용으로 친다.
- `net_connect`에는 비밀 인자가 없다. 저장 비밀이 없으면 경유지와 같은 `AuthPrompt` 카드로 묻고(**세션 인증**), 저장하지 않는다.
- 터미널이 끝나면 재사용 중인 도구에 종료를 알린다.

### TL.6 — 포트 개통

- 대상: 호스트 이름, IPv4/IPv6 주소, IPv4 대역(`10.0.0.0/24`). 포트: `22,80,8000-8100`.
- TCP 연결만 시도하고 연결되면 바로 닫는다. 로컬은 `TcpStream`, 리모트는 `channel_open_direct_tcpip`.

| 결과 | 의미 | 로컬 판정 | 리모트 판정(TL.0 실측, OpenSSH 9.2p1) |
|---|---|---|---|
| 열림 | 접속 성공 | 연결됨 | 채널 열림. 바로 닫는다 |
| 닫힘 | 대상까지 닿았고 그 포트를 쓰는 프로그램이 없음 | 연결 거부 | `ConnectFailed` + 설명 `Connection refused` |
| 응답 없음 | 방화벽 차단 가능성이 높음(확정 불가) | 시간 초과 | 표시 시간 초과. 서버가 먼저 포기하면 `ConnectFailed` + `Connection timed out`(Linux 기본 약 124초) |
| 도달 불가 | 경로 없음을 장비가 알림 | 호스트·네트워크 도달 불가 | `ConnectFailed` + `No route to host` 또는 `Network is unreachable` |
| 확인 불가 | 점검 자체를 못 함 | 이름 해석 실패 등 | `AdministrativelyProhibited`, `ConnectFailed` + `Name or service not known` 또는 `open failed`, 그 밖의 설명 |

리모트 시도 규칙(TL.0 실측에 따른 변경, 이유는 [검증 기록](../verification/tools-menu.md) 1~3번):

- **판정 근거:** 사유 코드는 닫힘과 경로 없음이 모두 `ConnectFailed`라 구분하지 못한다. 서버 설명은 `Handler::channel_open_failure`로만 오고 어느 시도의 설명인지 호출자가 알 수 없으므로, 동시 실행 결과에는 사용할 수 없다.
- **2단계 판정:** 동시 시도에서는 `ConnectFailed`를 잠정 `닫힘`으로 둔다. 잠정 `닫힘`이 64개 이하이면 동시 시도가 끝난 뒤 그 대상만 한 번에 하나씩 다시 열어 설명으로 확정한다. 64개를 넘으면 `닫힘 또는 도달 불가`로 표시한다. 설명은 서버가 보낸 문자열이므로 Handler에서 한 번만 enum으로 바꾸고, 모르는 설명은 `확인 불가`로 둔다.
- **open 작업을 드롭하지 않는다.** 표시 시간 초과는 결과만 `응답 없음`으로 정하고, `channel_open_direct_tcpip`는 별도 태스크가 서버 응답까지 소유한다. 늦게 열리면 즉시 `close()`한다. 드롭하면 채널이 연결 수명 동안 샌다.
- **서버 미해결 상한:** 서버가 응답하지 않은 시도는 시간 초과 뒤에도 서버의 fd를 쥐고 있다. 연결당 미해결 채널을 §6의 상한으로 제한하고 권한은 서버 응답 때 돌려준다. 상한에 닿으면 새 시도를 기다리게 하고 "서버 응답 대기 중"으로 표시한다.
- **자원 고갈 중단:** 작업 중 Handler가 `ConnectFailed` + `open failed`를 받으면 새 시도를 멈추고 "서버가 연결을 더 시작하지 못함(자원 부족 또는 경로 없음)"으로 알린다. 시작하지 못한 대상은 `확인 불가`로 표시한다. fd가 차면 모든 시도가 즉시 이 응답으로 끝나 전부 `닫힘`이 되기 때문이다.
- **취소:** 서버가 응답하기 전의 채널은 닫을 수 없다. 임시 연결을 다른 도구가 쓰지 않으면 연결을 끊어 정리한다(실측 0.2초). 쓰고 있으면 응답까지 상한에 남는다.
- 리모트에서 포워딩이 막혀 있으면 `remote_exec`로 bash `/dev/tcp`, 없으면 `nc`로 대신 시도한다. 결과에 이 방식임을 표시한다. bash는 거부(종료 코드 1)와 시간 초과(`timeout`의 124 또는 143)가 구분되지만 `nc -z`는 닫힘과 응답 없음이 모두 1이므로 `닫힘 또는 응답 없음`으로 표시한다.
- 대역이나 여러 호스트는 시작 전에 시도 수를 보여 주고 확인을 받는다. "허가된 망에서만 사용"을 같은 확인창에 적는다.
- 결과가 많으면 `256개 중 12개 열림`으로 요약하고 기본은 열림만 표시한다.
- 진행 중 취소할 수 있다. 결과 행 우클릭: 복사(출발지, 목적지, 포트, 결과, 시각), 다시 점검, 서비스 연결로 보기.

구현 결과(2026-11-08, [검증 기록](../verification/tools-menu.md#tl6tl7-포트-개통과-포트-사용-여부)). 구현하며 정하거나 실측으로 바꾼 부분:

- **설명 대기:** russh는 채널 실패를 호출자에게 먼저 알리고(`client/encrypted.rs:578`) 그다음 Handler를 호출한다(`:586`). 2단계 판정은 호출 결과만 보면 설명이 아직 없을 수 있어 `Gate::reason_after`가 실패 건수가 늘 때까지 최대 1초 기다린다. 그 사이 실패가 2건 이상이면(같은 연결을 쓰는 터널 등) 대응시킬 수 없으므로 `닫힘 또는 도달 불가`로 둔다.
- **Windows 로컬 최소 대기:** Windows는 연결 거부를 재시도해 `127.0.0.1`도 약 2초 걸린다(실측 2,056ms). 1초로 두면 닫힌 포트가 `응답 없음`이 되므로 Windows 로컬은 2.5초 미만으로 정해도 2.5초까지 기다린다. 다른 OS와 리모트는 입력값을 그대로 쓴다.
- **시도 수 확인:** 파서는 백엔드 하나다. `net_port_check`의 `confirmed: false` 호출이 호스트가 둘 이상이면 시작하지 않고 시도 수만 돌려준다(`NeedsConfirmation`). 화면에 같은 파서를 두 벌 두지 않기 위해서다. 호스트 하나면 바로 시작한다.
- **취소 시 정리:** 도구 탭의 연결만 끊고 터미널 연결은 끊지 않는다. 끊은 뒤에는 `다시 연결`로 잇는다.
- **`서비스 연결로 보기` 메뉴는 TL.8로 넘겼다.** 지금 열면 내용 없는 탭이 되고, 대상을 넘겨받는 입력도 TL.8에서 생긴다.
- 스트림 구조: `net_tools/dial.rs`의 `Dialer::dial`이 `Connected`(로컬 `TcpStream`, 리모트 `Channel`)를 돌려준다. TL.8은 여기에 `into_stream`을 더해 쓴다. 호출처 없는 함수를 남기지 않으려고 이번에는 넣지 않았다.
- **로컬 판정의 대상:** Docker Desktop의 게시 포트는 듣는 프로그램이 없어도 이 PC 쪽에서 연결이 성공한다(실측 5ms). 컨테이너의 REJECT·DROP은 Windows 출발지에서 보이지 않으므로 로컬 5종은 루프백과 실제 주소로 확인했다(검증 기록).

### TL.7 — 포트 사용 여부

- 입력은 없어도 된다. 없으면 전체 목록, 포트를 넣으면 "사용 중 · 프로세스 · 주소" 또는 "사용 안 함"으로 답한다. 필터는 화면에서 한다.
- TCP 대기와 UDP 바인드를 함께 보여 준다.

| 출발지 | 방법 |
|---|---|
| Windows | `GetExtendedTcpTable`·`GetExtendedUdpTable`와 Toolhelp 스냅숏의 프로세스 이름(TL.0: 일반 권한에서 경로 조회는 14/28뿐이고 이름은 28/28). `netstat` 출력은 언어별로 달라 쓰지 않는다 |
| Mac | `/usr/sbin/lsof -nP -F`를 절대 경로로 실행 |
| 리모트 Linux | `/proc/net/{tcp,tcp6,udp,udp6}`로 목록을 정하고(TL.0: 모든 이미지에서 읽힘), `ss -lntup`, 없으면 `netstat -lntup`로 프로세스 이름을 덧붙인다. 일반 계정은 자기 프로세스 이름만 나오므로 빈 칸을 "권한 없음"으로 표시한다. BusyBox `lsof`는 포트를 내지 않으므로 쓰지 않는다 |
| 리모트 기타 | `lsof`, `netstat -an` 순서. 프로세스 이름은 없을 수 있다 |
| SSH 실패 | 포트를 입력했으면 세션의 호스트로 이 PC에서 포트 개통을 시도하고 **"외부에서 확인한 결과"**로 표시한다. 전체 목록은 낼 수 없다 |

- 명령은 고정 문자열이고 사용자 입력을 넣지 않는다. `sudo`를 쓰지 않는다. 다른 계정의 프로세스 이름은 비어 있을 수 있음을 표시한다.
- `remote_ports`의 응답 형식은 터널 대화상자가 쓰므로 유지하고, 파서만 공용으로 쓴다.

구현 결과(2026-11-08, 같은 검증 기록). 위 표대로 구현했다. 구체화한 부분:

- 리모트 Linux는 고정 스크립트 한 번으로 표와 도구 출력을 함께 받는다. 표가 하나도 없으면 두 번째 고정 스크립트로 `lsof`, `netstat -an`을 시도한다. 도구가 소켓을 한 줄도 내지 않으면 없는 것으로 친다.
- 프로세스는 세 상태다. `Known`(이름), `Denied`(도구는 돌았지만 안 보임, **권한 없음**), `Unavailable`(도구가 없음, **알 수 없음**).
- 외부 확인은 프런트엔드가 `net_port_check`를 출발지 로컬, 세션의 호스트로 호출한다. 전용 명령을 두지 않는다.
- 포트 입력은 화면의 필터이므로 TS의 `parsePortFilter`로 읽는다. 시도를 만드는 입력이 아니어서 백엔드 파서와 규칙을 공유하지 않는다.

### TL.8 — 서비스 연결

- 입력: `host:port` 또는 URL. 형식: 자동, HTTP, HTTPS, TLS, TCP 배너.
- 로컬 `TcpStream`과 리모트 `channel.into_stream()`을 같은 일반 함수로 처리한다. **서버에 `curl`, `openssl`이 없어도 된다.**
- 요약 한 줄에 결과를 보여 주고 펼치면 상세를 보여 준다.

```text
WAS01  →  api.example.com:443    연결됨 · HTTPS 200 · 42ms
▾ 상세
  이름 해석   203.0.113.40             3ms
  TCP 연결    성공                    12ms
  TLS         1.3 · 인증서 2027-01-31 만료 · 신뢰 OK
  응답        HTTP/1.1 200 · Server: nginx
  경로 추적   [실행]
```

- 자동: 2초간 서버가 먼저 보내는 배너를 기다리고, 없으면 TLS, 그다음 HTTP를 시도한다. 시도마다 새로 연결하고 최대 3회다.
- TLS는 **신뢰 여부와 무관하게 인증서를 읽고** 검증 결과를 따로 보고한다. 이 연결로는 어떤 인증정보도 보내지 않는다.
- HTTP는 `HEAD`만 보낸다. 본문을 읽지 않는다. 배너와 응답은 4KiB로 자르고 제어 문자를 지운다.
- `열림`이어도 L4 장비나 프록시가 대신 받은 경우가 있으므로, 응답 내용과 인증서로 실제 서비스인지 판단하게 한다.
- 리모트의 이름 해석은 `direct-tcpip`가 서버에서 하므로 소요 시간을 따로 잴 수 없다. `getent`가 있으면 결과만 표시한다.

구현 결과(2026-11-08, [검증 기록](../verification/tools-menu.md#tl8tl9-서비스-연결과-경로-추적)). 구현하며 정한 부분:

- **스트림:** `Connected::into_stream`이 로컬 `TcpStream`과 russh `ChannelStream`을 같은 `Box<dyn ByteStream>`으로 돌려준다. 채널 자체와 달리 `ChannelStream`은 드롭하면 채널을 닫으므로(`ChannelCloseOnDrop`) 취소 때 따로 닫지 않는다.
- **TLS:** 새 TLS 의존성 없이 FTP가 쓰는 `suppaftp::tokio_rustls`를 그대로 쓴다. 인증서 검증기는 `WebPkiServerVerifier`의 결과만 기록하고 핸드셰이크를 계속시킨다. 서명 검증은 그대로 한다. 이 연결로는 인증정보 없는 `HEAD`만 보내므로 안전하고, 다른 곳에서 재사용하지 않는다. 시스템 인증서 저장소를 읽지 못하면 `판단 불가`로 표시한다.
- **자체 서명 판정:** OpenSSL 기본값으로 만든 인증서는 rustls에서 `UnknownIssuer`가 아니라 분류되지 않은 오류(CA를 서버 인증서로 사용)로 온다. 인증서의 주체와 발급자가 같으면 두 경우 모두 `자체 서명`으로 표시한다.
- **대기 시간:** 연결 5초, TLS 5초, HTTP 응답 5초, 배너 2초. 입력으로 받지 않는다.
- **형식 우선순위:** URL의 스킴은 형식이 자동일 때만 쓴다. 주소에 사용자 이름이나 암호가 있으면 거부한다. 경로는 눈에 보이는 ASCII 외에 모두 퍼센트 인코딩해 헤더를 끼워 넣을 수 없게 한다.
- **포워딩 금지:** 포트 개통과 달리 대체 경로가 없다. 스트림이 필요하기 때문이다. `확인 불가 · 서버가 이 연결을 금지했습니다.`로 끝낸다.
- **자동의 TLS 실패:** 이어진 HTTP가 성공하면 TLS 실패는 상세에 보이지 않는다. 일반 HTTP 포트에서 항상 나는 실패이기 때문이다.
- **`서비스 연결로 보기`(TL.6에서 넘긴 메뉴):** 포트 개통 결과 행에서 같은 출발지(리모트면 같은 세션)로 서비스 탭을 열고 대상을 넣어 바로 점검한다. 출발지 연결이 끝나야 시작한다. 리모트는 탭마다 연결을 따로 가지므로 터미널 재사용이 없으면 인증을 한 번 더 묻는다.

### TL.9 — 경로 추적 (서비스 연결의 펼치기)

펼친 뒤 **경로 추적**을 눌렀을 때만 실행한다. 최대 30홉, 취소할 수 있다.

| 출발지 | 방법 | 표시 |
|---|---|---|
| Windows | `IcmpSendEcho`에 TTL 지정(관리자 불필요, 언어 영향 없음) | 참고용 ICMP |
| Mac | `/usr/sbin/traceroute -n`, TL.0 결과에 따라 `-P tcp -p 포트` | TCP 또는 참고용 |
| 리모트 root | `traceroute -T -n -p 포트`. BusyBox처럼 `-T`가 없으면 아래 줄로 간다(TL.0) | **포트 기준 TCP** |
| 리모트 일반 계정 | `traceroute -n`, `tracepath -n` 순서. BusyBox `traceroute`는 일반 계정에서 권한 오류로 실패하므로 다음 도구로 넘어간다(TL.0) | 참고용 |
| 도구 없음 | 실행하지 않음 | "이 서버에서는 경로 추적을 할 수 없습니다" |

- 결론 문장은 **"마지막 응답 장비는 X, 그 다음 구간에서 끊김"**까지만 쓴다. 방화벽은 대개 응답하지 않으므로 특정 장비가 막았다고 단정하지 않는다.
- 참고용 ICMP는 그 포트의 정책과 무관하다는 안내를 결과 옆에 적는다.
- 대상은 호스트 이름·IP 형식만 받고 `remote_exec::quote`로 인용한다.

구현 결과(2026-11-08, 같은 검증 기록). 구현하며 정한 부분:

- **Windows는 IPv4만:** `IcmpSendEcho`는 IPv4 전용이다. IPv6만 있는 대상은 `이 PC의 경로 추적은 IPv4 대상만 지원합니다.`로 끝낸다. 홉마다 1초씩 2회 시도하므로 최악 약 60초다.
- **리모트 명령:** `traceroute`는 `-n -q 2 -w 1 -m 30`을 쓴다. 도구별 헤더가 stderr로 나오는 경우가 있어 `2>&1`로 합친다. 줄마다 파싱해 받는 대로 이벤트로 보내야 60초 제한에 걸려도 앞 홉이 남으므로 `remote_exec::run_lines`를 추가했다. `tracepath`는 `-n`만 쓴다(기본 30홉).
- **다음 도구로 넘어가는 기준:** 홉을 한 줄도 내지 못하면 다음 도구로 간다. BusyBox의 `-T` 없음과 일반 계정 권한 오류가 모두 여기에 해당한다. 이름 해석 실패는 도구를 바꿔도 같으므로 바로 끝낸다. 도구가 모두 실패하면 `이 서버에서는 경로 추적을 할 수 없습니다`다.
- **Mac:** `-P tcp -p 포트`를 먼저 시도하고 홉이 없으면 UDP로 넘어간다. TL.0의 Mac 결과가 없어 두 경로를 모두 넣었다. 실기기 대기(macos-readiness M.22).
- **도달 판정:** 출력의 헤더에서 얻은 주소(또는 입력한 IP)와 같은 장비가 응답하면 도달이다. `tracepath`는 `reached`도 본다. 도달 불가 표시(`!H` 등)는 그 홉의 비고로만 적고 결론은 바꾸지 않는다.

### TL.10 — 문서·회귀·Mac

사용 안내서, 단축키 목록, 고지 재생성, macos-readiness 항목 등록, 바꾼 범위의 회귀.

결과(2026-11-09): 안내서에 서비스 연결·경로 추적, 앱과 안내서 단축키 목록에 결과 행 메뉴(`Shift+F10`, 메뉴 키)를 넣었다. 새 단축키는 없다. `x509-cert` 감사 0건, 고지 재생성 완료. Mac 항목은 macos-readiness M.22로 등록했고 실기기 결과는 대기다. 회귀는 포트 도구만 돌렸다([검증 기록](../verification/tools-menu.md#tl10-회귀)).

## 6. 상한과 기본값 (TL.0에서 조정)

| 항목 | 값 |
|---|---|
| 호스트 수 | 한 번에 256개(`/24`) |

| 리모트 설명 재확인 | 잠정 `닫힘` 64개까지 하나씩 |

| 경로 추적 | 30홉, 원격 명령 시간 60초, 출력 64KiB |

## 7. 보안

- 비밀(Passphrase, 저장 암호)은 코드·문서·로그에 남기지 않고 `Zeroizing`으로 다룬다.
- 임시 SSH 연결도 호스트 키 검증을 그대로 거친다. 우회 옵션을 만들지 않는다.
- 스캔은 일반 TCP 연결만 쓰고, 탐지 회피 기능(위장 주소, 임의 지연, SYN 등)을 넣지 않는다. 상한을 사용자 설정으로 풀지 않는다.
- 서버에서 온 배너·응답·명령 출력은 신뢰하지 않는다. 제어 문자를 지우고 일반 글자로만 표시한다(`agent_filter::plain` 재사용 검토).
- 원격 명령에 들어가는 사용자 입력은 대상 주소와 포트뿐이다. 형식 검증 뒤 `quote`로 인용한다.
- 개인키 파일은 만든 즉시 소유자 전용 권한이고, 내용을 화면이나 IPC 응답으로 돌려주지 않는다.

**남은 결정** (2026-11-08 사용자 승인: 아래 기본값으로 진행)

1. 게임 7개를 메뉴에서 접을지. 기본은 지금처럼 구분 제목 아래 평면 목록이고, 메뉴가 너무 길면 접는다.
2. RSA 키 생성. 기본은 Ed25519만이다. `vendor/ssh-key`의 RSA 패치 범위를 봐야 하고, 오래된 서버 호환이 필요할 때 추가한다.
3. 공개키를 접속 중인 서버의 `authorized_keys`에 자동 등록. 기본은 후속이다.
4. WSL을 출발지로 쓰기. 기본은 후속이다. WSL2는 네트워크가 분리돼 이 PC와 결과가 다르다.
5. 최근 대상 기억. 기본은 후속이다.
6. 네트워크 도구의 터미널 탭 우클릭 진입점(해당 서버를 출발지로 열기). 기본은 후속이다.
